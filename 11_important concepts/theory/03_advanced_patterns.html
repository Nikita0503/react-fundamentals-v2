Advanced Patterns

React has several patterns for sharing logic between components. Some are modern, some are legacy (but still appear on interviews).

Higher-Order Components (HOC) — legacy pattern

A function that takes a component and returns a new enhanced component. Was the primary way to share logic before hooks (2018).

// A HOC that adds authentication check
const withAuth = (WrappedComponent: () => JSX.Element) => {
  return () => {
    const isAuthenticated = true; // imagine real auth check here

    if (!isAuthenticated) {
      return <p>Access denied. Please log in.</p>;
    }

    return <WrappedComponent />;
  };
};

// Usage:
const Dashboard = () => <h1>Dashboard</h1>;
const ProtectedDashboard = withAuth(Dashboard);
// Now <ProtectedDashboard /> shows Dashboard only if authenticated

Problems with HOCs:

  • "Wrapper hell" — multiple HOCs create deeply nested component trees
  • Props collision — HOCs can overwrite each other's props
  • Hard to type in TypeScript
  • Hard to trace where props come from (debugging)

Modern replacement: custom hooks (useAuth, usePermissions) + conditional rendering:

// Modern approach — same result, simpler:
const Dashboard = () => {
  const { isAuthenticated } = useAuth();
  if (!isAuthenticated) return <p>Access denied.</p>;
  return <h1>Dashboard</h1>;
};

When you'll still see HOCs: older codebases, some libraries (React Redux's connect() — though useSelector replaced it).

Render Props — legacy pattern

A component that takes a function as a prop and calls it to determine what to render. The function receives data, and you decide how to display it:

// The component manages logic, you decide the UI via the "render" prop
const Counter = ({ render }: { render: (count: number) => ReactNode }) => {
  const [count, setCount] = useState(0);
  return (
    <div>
      <button onClick={() => setCount(count + 1)}>Increment</button>
      {render(count)}
    </div>
  );
};

// Usage — you control how count is displayed:
<Counter render={(count) => <h1>Count: {count}</h1>} />
<Counter render={(count) => <span>{count} clicks</span>} />

Modern replacement: custom hook — same logic, simpler code:

const useCounter = () => {
  const [count, setCount] = useState(0);
  const increment = () => setCount(count + 1);
  return { count, increment };
};

// Usage:
const MyComponent = () => {
  const { count, increment } = useCounter();
  return <button onClick={increment}>Count: {count}</button>;
};

Compound Components — modern pattern

A set of components that work together, sharing state internally. The consumer doesn't manage the state — just composes the pieces. Think: <Tabs>, <Accordion>, <Select>.

Here's how it looks from the consumer's perspective (the clean API you get):

// Usage — you just compose the pieces, state is handled internally:
<Tabs defaultTab="profile">
  <TabButton name="profile">Profile</TabButton>
  <TabButton name="settings">Settings</TabButton>
  <TabPanel name="profile">Profile content here</TabPanel>
  <TabPanel name="settings">Settings content here</TabPanel>
</Tabs>

Behind the scenes, Tabs manages which tab is active (via Context), and TabButton/TabPanel read from that context to know what to show. You don't pass state around — it's all internal.

Why it's good: clean API for the consumer, flexible composition, state is hidden inside.

Where you see it: UI libraries (Radix, React Aria, Headless UI). You'll use compound components as a consumer — building them from scratch is an advanced topic.
