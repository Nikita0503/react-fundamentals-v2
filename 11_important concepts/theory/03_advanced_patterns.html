Advanced Patterns

React has several patterns for sharing logic between components. Some are modern, some are legacy (but still appear on interviews).

Higher-Order Components (HOC) — legacy pattern

A function that takes a component and returns a new enhanced component. Was the primary way to share logic before hooks (2018).

import { ComponentType } from "react";

const withAuth = <P extends object>(WrappedComponent: ComponentType<P>) => {
  return (props: P) => {
    const isAuthenticated = true; // check auth logic

    if (!isAuthenticated) {
      return <p>Access denied. Please log in.</p>;
    }

    return <WrappedComponent {...props} />;
  };
};

// Usage:
const Dashboard = () => <h1>Dashboard</h1>;
const ProtectedDashboard = withAuth(Dashboard);

Problems with HOCs:

  • "Wrapper hell" — multiple HOCs create deeply nested component trees
  • Props collision — HOCs can overwrite each other's props
  • Hard to type in TypeScript
  • Hard to trace where props come from (debugging)

Modern replacement: custom hooks (useAuth, usePermissions) + conditional rendering:

// Modern approach — same result, simpler:
const Dashboard = () => {
  const { isAuthenticated } = useAuth();
  if (!isAuthenticated) return <p>Access denied.</p>;
  return <h1>Dashboard</h1>;
};

When you'll still see HOCs: older codebases, some libraries (React Redux's connect() — though useSelector replaced it).

Render Props — legacy pattern

A component that takes a function as a prop (or children) and calls it to determine what to render.

import { useState, ReactNode } from "react";

type MousePosition = { x: number; y: number };

type MouseTrackerProps = {
  render: (position: MousePosition) => ReactNode;
};

const MouseTracker = ({ render }: MouseTrackerProps) => {
  const [position, setPosition] = useState<MousePosition>({ x: 0, y: 0 });

  const handleMouseMove = (e: React.MouseEvent) => {
    setPosition({ x: e.clientX, y: e.clientY });
  };

  return <div onMouseMove={handleMouseMove}>{render(position)}</div>;
};

// Usage:
<MouseTracker render={({ x, y }) => <p>Mouse: {x}, {y}</p>} />

Modern replacement: custom hook:

import { useState, useEffect } from "react";

const useMousePosition = () => {
  const [position, setPosition] = useState({ x: 0, y: 0 });
  useEffect(() => {
    const handler = (e: MouseEvent) => setPosition({ x: e.clientX, y: e.clientY });
    window.addEventListener("mousemove", handler);
    return () => window.removeEventListener("mousemove", handler);
  }, []);
  return position;
};

// Usage — much simpler:
const Component = () => {
  const { x, y } = useMousePosition();
  return <p>Mouse: {x}, {y}</p>;
};

Compound Components — modern pattern

A set of components that work together, sharing implicit state via Context. Think: <Select>, <Tabs>, <Accordion> — parent manages state, children render parts.

import { createContext, useContext, useState, ReactNode } from "react";

// Internal context
type TabsContextValue = { activeTab: string; setActiveTab: (tab: string) => void };
const TabsContext = createContext<TabsContextValue | undefined>(undefined);

const useTabs = () => {
  const ctx = useContext(TabsContext);
  if (!ctx) throw new Error("Tab components must be used within <Tabs>");
  return ctx;
};

// Parent — manages state
const Tabs = ({ defaultTab, children }: { defaultTab: string; children: ReactNode }) => {
  const [activeTab, setActiveTab] = useState(defaultTab);
  return (
    <TabsContext.Provider value={{ activeTab, setActiveTab }}>
      <div className="tabs">{children}</div>
    </TabsContext.Provider>
  );
};

// Child — tab button
const TabButton = ({ name, children }: { name: string; children: ReactNode }) => {
  const { activeTab, setActiveTab } = useTabs();
  return (
    <button className={activeTab === name ? "active" : ""} onClick={() => setActiveTab(name)}>
      {children}
    </button>
  );
};

// Child — tab content
const TabPanel = ({ name, children }: { name: string; children: ReactNode }) => {
  const { activeTab } = useTabs();
  return activeTab === name ? <div>{children}</div> : null;
};

// Usage — clean, declarative API:
<Tabs defaultTab="profile">
  <TabButton name="profile">Profile</TabButton>
  <TabButton name="settings">Settings</TabButton>
  <TabPanel name="profile"><ProfilePage /></TabPanel>
  <TabPanel name="settings"><SettingsPage /></TabPanel>
</Tabs>

Why it's good: clean API, flexible composition, state is hidden from the consumer.

Where you see it: UI libraries (Radix, React Aria, Headless UI).
