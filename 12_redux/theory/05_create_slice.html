createSlice = Actions + Reducer + Initial State in One Place

createSlice is the most important function in Redux Toolkit. It combines everything you need for a feature's state into a single, concise declaration:

  • Initial state
  • Reducer logic (with Immer)
  • Action creators (auto-generated from reducer names)

No more jumping between files for constants, types, action creators, and reducers. One function, one file, one feature.

Syntax

import { createSlice, PayloadAction } from "@reduxjs/toolkit";

const mySlice = createSlice({
  name: "sliceName",       // Used as prefix for action types
  initialState: { ... },   // The initial state value
  reducers: {              // Object of "case reducers"
    actionName(state, action: PayloadAction<PayloadType>) {
      // Mutate state directly (Immer handles immutability)
    },
  },
});
  • name — becomes the prefix for all generated action types (e.g., "user/setName")
  • initialState — the starting state for this slice
  • reducers — an object where each key becomes an action creator and its value is the reducer logic

What createSlice Returns

const mySlice = createSlice({ ... });

// What you get back:
mySlice.name;       // "sliceName" — the name you passed in
mySlice.reducer;    // The combined reducer function (pass to configureStore)
mySlice.actions;    // Object of auto-generated action creators
                    // { actionName: (payload) => ({ type: "sliceName/actionName", payload }) }

Full Example: userSlice

// store/slices/userSlice.ts
import { createSlice, PayloadAction } from "@reduxjs/toolkit";

type UserState = {
  name: string;
  email: string;
};

const initialState: UserState = {
  name: "",
  email: "",
};

const userSlice = createSlice({
  name: "user",
  initialState,
  reducers: {
    setName(state, action: PayloadAction<string>) {
      state.name = action.payload;
    },
    setEmail(state, action: PayloadAction<string>) {
      state.email = action.payload;
    },
    resetUser(state) {
      state.name = initialState.name;
      state.email = initialState.email;
    },
  },
});

// Export actions for use in components
export const { setName, setEmail, resetUser } = userSlice.actions;

// Export reducer for use in configureStore
export default userSlice.reducer;

The generated action types are:

  • setName("Alice") → { type: "user/setName", payload: "Alice" }
  • setEmail("a@b.com") → { type: "user/setEmail", payload: "a@b.com" }
  • resetUser() → { type: "user/resetUser" }

PayloadAction<T> for Typing Payloads

PayloadAction<T> is a generic type from RTK that types the action.payload field:

import { PayloadAction } from "@reduxjs/toolkit";

// PayloadAction<string> means action.payload is string
setName(state, action: PayloadAction<string>) {
  state.name = action.payload; // TypeScript knows this is string
}

// PayloadAction<{ id: number; quantity: number }> for complex payloads
addItem(state, action: PayloadAction<{ id: number; quantity: number }>) {
  state.items.push(action.payload); // TypeScript knows the shape
}

// No PayloadAction = no payload expected
resetUser(state) {
  // action parameter omitted — this action carries no data
}

Before vs After: Side-by-Side Comparison

Before (createAction + createReducer separately — ~40 lines):

import { createAction, createReducer } from "@reduxjs/toolkit";

// Actions (separate)
export const setName = createAction<string>("user/setName");
export const setEmail = createAction<string>("user/setEmail");
export const resetUser = createAction("user/resetUser");

// State type
type UserState = {
  name: string;
  email: string;
};

const initialState: UserState = {
  name: "",
  email: "",
};

// Reducer (separate)
export const userReducer = createReducer(initialState, (builder) => {
  builder
    .addCase(setName, (state, action) => {
      state.name = action.payload;
    })
    .addCase(setEmail, (state, action) => {
      state.email = action.payload;
    })
    .addCase(resetUser, (state) => {
      state.name = initialState.name;
      state.email = initialState.email;
    });
});

After (createSlice — ~20 lines):

import { createSlice, PayloadAction } from "@reduxjs/toolkit";

type UserState = { name: string; email: string };
const initialState: UserState = { name: "", email: "" };

const userSlice = createSlice({
  name: "user",
  initialState,
  reducers: {
    setName(state, action: PayloadAction<string>) {
      state.name = action.payload;
    },
    setEmail(state, action: PayloadAction<string>) {
      state.email = action.payload;
    },
    resetUser(state) {
      state.name = initialState.name;
      state.email = initialState.email;
    },
  },
});

export const { setName, setEmail, resetUser } = userSlice.actions;
export default userSlice.reducer;

Same functionality, half the code, zero boilerplate.

When to Use createSlice vs Separate createAction/createReducer

Use createSlice (90% of cases):

  • Standard CRUD operations (set, update, delete, reset)
  • Feature-scoped state (user, cart, notifications, settings)
  • Actions that belong to a single reducer
  • Any time you're starting a new feature

Use separate createAction/createReducer (10% of cases):

  • Shared actions consumed by multiple reducers (e.g., a logout action that resets user, cart, and notifications)
  • Complex action preparation logic (custom prepare callbacks that need to be reused)
  • Actions that come from external libraries or middleware

Export Pattern

The standard export pattern for a slice file:

// Named exports for actions (used in components)
export const { setName, setEmail, resetUser } = userSlice.actions;

// Default export for the reducer (used in configureStore)
export default userSlice.reducer;

This convention keeps imports clean:

// In store.ts — import the reducer
import userReducer from "./slices/userSlice";

// In components — import specific actions
import { setName, setEmail } from "../store/slices/userSlice";
