What is an Action?

An action is a plain JavaScript object that describes what happened. It has two fields:

  • type — a unique string identifying the event (required)
  • payload — the data associated with the event (optional)
// Example action:
{
  type: "user/setName",
  payload: "Alice"
}

Actions are the only way to trigger state changes in Redux. Think of them as "event messages" that tell the store what happened.

The Classic (Legacy) Approach

Before Redux Toolkit, you had to write everything manually. Let's see how verbose it gets:

Step 1: Define string constants

// constants.ts
export const SET_NAME = "user/setName" as const;
export const SET_EMAIL = "user/setEmail" as const;
export const RESET_USER = "user/reset" as const;

Step 2: Define TypeScript types for each action

// types.ts
type SetNameAction = {
  type: typeof SET_NAME;
  payload: string;
};

type SetEmailAction = {
  type: typeof SET_EMAIL;
  payload: string;
};

type ResetUserAction = {
  type: typeof RESET_USER;
};

// Discriminated union of all actions
export type UserAction = SetNameAction | SetEmailAction | ResetUserAction;

Step 3: Write action creator functions

// actions.ts
import { SET_NAME, SET_EMAIL, RESET_USER } from "./constants";
import type { SetNameAction, SetEmailAction, ResetUserAction } from "./types";

export const setName = (name: string): SetNameAction => ({
  type: SET_NAME,
  payload: name,
});

export const setEmail = (email: string): SetEmailAction => ({
  type: SET_EMAIL,
  payload: email,
});

export const resetUser = (): ResetUserAction => ({
  type: RESET_USER,
});

Problems with this approach:

  • Lots of boilerplate — 3 files just for actions
  • Typos in strings are easy to make and hard to catch
  • No autocomplete for action types
  • Every new action requires changes in 3 places (constant, type, creator)
  • The discriminated union must be maintained manually

The RTK Way: createAction()

Redux Toolkit's createAction does all of the above in one line:

import { createAction } from "@reduxjs/toolkit";

// One line = constant + type + action creator
export const setName = createAction<string>("user/setName");
export const setEmail = createAction<string>("user/setEmail");
export const resetUser = createAction("user/reset");

What you get automatically:

  • The type constant: setName.type === "user/setName"
  • Full TypeScript inference: setName("Alice") returns { type: "user/setName", payload: "Alice" }
  • Type safety: setName(123) would be a TypeScript error (expects string)
  • The .match() method for type narrowing in reducers

Usage:

// Creating actions
const action = setName("Alice");
// Result: { type: "user/setName", payload: "Alice" }

// Checking action type
console.log(setName.type); // "user/setName"

// Type narrowing with .match()
if (setName.match(someAction)) {
  // TypeScript knows someAction.payload is string here
  console.log(someAction.payload.toUpperCase());
}

Naming Convention

Action types follow the pattern "domain/eventName":

// Good — clear domain and intent
"user/setName"
"cart/addItem"
"auth/loginSuccess"
"filters/reset"

// Bad — no domain, unclear
"SET_NAME"
"ADD"
"UPDATE"

In practice, you'll rarely use createAction directly. The createSlice function (covered later) generates actions automatically from your reducer logic. But understanding actions as a concept is essential — they're the foundation of Redux's predictable data flow.
