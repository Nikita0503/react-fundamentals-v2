What is a Reducer?

A reducer is a pure function that takes the current state and an action, and returns a new state:

// The signature:
(state, action) => newState

Rules of reducers:

  • Pure — same inputs always produce the same output
  • No side effects — no API calls, no random values, no Date.now()
  • No mutations — never modify the existing state object, always return a new one
  • Synchronous — no async/await inside reducers

The Classic (Legacy) Approach

Traditionally, reducers used a switch/case statement and manual immutable updates:

// types
type UserState = {
  name: string;
  email: string;
  preferences: {
    theme: "light" | "dark";
    notifications: boolean;
  };
};

const initialState: UserState = {
  name: "",
  email: "",
  preferences: {
    theme: "light",
    notifications: true,
  },
};
// reducer with switch/case
import { SET_NAME, SET_EMAIL, RESET_USER } from "./constants";
import type { UserAction } from "./types";

const userReducer = (state = initialState, action: UserAction): UserState => {
  switch (action.type) {
    case SET_NAME:
      return { ...state, name: action.payload };

    case SET_EMAIL:
      return { ...state, email: action.payload };

    case RESET_USER:
      return initialState;

    default:
      return state;
  }
};

The problem with nested updates:

Immutable updates get ugly fast when state is nested:

// Updating a nested field — spread at every level!
case SET_THEME:
  return {
    ...state,
    preferences: {
      ...state.preferences,
      theme: action.payload,
    },
  };

// Imagine 3-4 levels deep... it becomes unreadable and error-prone

Other issues with the classic approach:

  • Easy to forget the spread operator and accidentally mutate state
  • The default case is easy to forget (must return current state)
  • TypeScript requires a discriminated union for proper type narrowing
  • Large reducers become hard to read

The RTK Way: createReducer()

Redux Toolkit's createReducer uses a builder pattern and Immer under the hood:

import { createReducer } from "@reduxjs/toolkit";
import { setName, setEmail, setTheme, resetUser } from "./actions";

type UserState = {
  name: string;
  email: string;
  preferences: {
    theme: "light" | "dark";
    notifications: boolean;
  };
};

const initialState: UserState = {
  name: "",
  email: "",
  preferences: {
    theme: "light",
    notifications: true,
  },
};

const userReducer = createReducer(initialState, (builder) => {
  builder
    .addCase(setName, (state, action) => {
      state.name = action.payload; // "mutating" is safe here!
    })
    .addCase(setEmail, (state, action) => {
      state.email = action.payload;
    })
    .addCase(setTheme, (state, action) => {
      state.preferences.theme = action.payload; // nested update — just assign!
    })
    .addCase(resetUser, () => {
      return initialState; // return a new value to replace entirely
    });
});

Why "mutating" is safe — Immer explained

When you write state.name = action.payload inside createReducer, you're not actually mutating the real state. Here's what happens:

  1. Immer creates a draft (a proxy copy) of the current state
  2. Your code "mutates" the draft
  3. Immer compares the draft to the original and produces a new immutable object with only the changed parts
// What you write:
state.preferences.theme = "dark";

// What Immer produces (behind the scenes):
{
  ...state,
  preferences: {
    ...state.preferences,
    theme: "dark",
  },
}
// Same result, zero boilerplate!

Two ways to update state in createReducer:

  • Mutate the draft — write assignments directly (Immer handles immutability)
  • Return a new value — useful for resetting state entirely. Do NOT combine both in the same case.

TypeScript benefits

With createReducer + createAction, TypeScript automatically knows:

  • The shape of state (from initialState)
  • The type of action.payload (from the action creator's generic)
  • No manual discriminated unions needed
builder.addCase(setName, (state, action) => {
  // TypeScript knows:
  // - state is UserState
  // - action.payload is string
  state.name = action.payload;
});
