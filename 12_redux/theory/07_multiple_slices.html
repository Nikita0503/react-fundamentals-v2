Real Apps Have Multiple Slices

A real application doesn't have just one piece of state. You'll typically have separate slices for different domains:

  • user — authentication, profile info
  • cart — shopping cart items, totals
  • notifications — alerts, unread count
  • settings — theme, language preferences

Each slice manages its own piece of state independently. They don't know about each other — they just coexist in the same store.

How to Combine: Just Add to configureStore

Combining slices is trivial — just add each slice's reducer to the reducer object in configureStore:

// store/store.ts
import { configureStore } from "@reduxjs/toolkit";
import userReducer from "./slices/userSlice";
import cartReducer from "./slices/cartSlice";
import notificationsReducer from "./slices/notificationsSlice";

export const store = configureStore({
  reducer: {
    user: userReducer,
    cart: cartReducer,
    notifications: notificationsReducer,
  },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

Each key in the reducer object becomes a top-level key in your state tree. The RootState type automatically reflects all slices.

Accessing Different Slices

In components, you access each slice through its key on the state object:

// Access user slice
const name = useAppSelector((state) => state.user.name);

// Access cart slice
const items = useAppSelector((state) => state.cart.items);
const totalItems = useAppSelector((state) => state.cart.items.length);

// Access notifications slice
const unreadCount = useAppSelector((state) => state.notifications.unreadCount);

File Structure for a Real App

store/
  store.ts                  // configureStore + RootState + AppDispatch
  hooks.ts                  // useAppSelector, useAppDispatch
  slices/
    userSlice.ts            // User state: name, email, auth status
    cartSlice.ts            // Cart state: items, quantities
    notificationsSlice.ts   // Notifications: list, unread count

Each slice file is self-contained: state type, initial state, reducers, exported actions, exported reducer. The store file just imports and combines them.

Full Example: Two Slices Working Together

store/slices/userSlice.ts

import { createSlice, PayloadAction } from "@reduxjs/toolkit";

type UserState = {
  name: string;
  email: string;
};

const initialState: UserState = {
  name: "",
  email: "",
};

const userSlice = createSlice({
  name: "user",
  initialState,
  reducers: {
    setName(state, action: PayloadAction<string>) {
      state.name = action.payload;
    },
    setEmail(state, action: PayloadAction<string>) {
      state.email = action.payload;
    },
  },
});

export const { setName, setEmail } = userSlice.actions;
export default userSlice.reducer;

store/slices/cartSlice.ts

import { createSlice, PayloadAction } from "@reduxjs/toolkit";

type CartItem = {
  id: string;
  title: string;
  price: number;
  quantity: number;
};

type CartState = {
  items: CartItem[];
};

const initialState: CartState = {
  items: [],
};

const cartSlice = createSlice({
  name: "cart",
  initialState,
  reducers: {
    addItem(state, action: PayloadAction<Omit<CartItem, "quantity">>) {
      const existing = state.items.find((item) => item.id === action.payload.id);
      if (existing) {
        existing.quantity += 1;
      } else {
        state.items.push({ ...action.payload, quantity: 1 });
      }
    },
    removeItem(state, action: PayloadAction<string>) {
      state.items = state.items.filter((item) => item.id !== action.payload);
    },
    clearCart(state) {
      state.items = [];
    },
  },
});

export const { addItem, removeItem, clearCart } = cartSlice.actions;
export default cartSlice.reducer;

import { configureStore } from "@reduxjs/toolkit";

store/hooks.ts

import { useDispatch, useSelector } from "react-redux";
import type { RootState, AppDispatch } from "./store";

export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();

components/Dashboard.tsx — reading from both slices

import { useAppDispatch, useAppSelector } from "../store/hooks";
import { setName } from "../store/slices/userSlice";
import { addItem, clearCart } from "../store/slices/cartSlice";

const Dashboard = () => {
  const dispatch = useAppDispatch();

  // Reading from user slice
  const userName = useAppSelector((state) => state.user.name);

  // Reading from cart slice
  const cartItems = useAppSelector((state) => state.cart.items);
  const totalPrice = useAppSelector((state) =>
    state.cart.items.reduce((sum, item) => sum + item.price * item.quantity, 0)
  );

  return (
    <div>
      <h1>Welcome, {userName || "Guest"}</h1>

      <button
        onClick={() =>
          dispatch(addItem({ id: "1", title: "TypeScript Book", price: 29.99 }))
        }
      >
        Add Book to Cart
      </button>

      <h2>Cart ({cartItems.length} items)</h2>
      <ul>
        {cartItems.map((item) => (
          <li key={item.id}>
            {item.title} x{item.quantity} — ${item.price * item.quantity}
          </li>
        ))}
      </ul>
      <p>Total: ${totalPrice.toFixed(2)}</p>

      <button onClick={() => dispatch(clearCart())}>Clear Cart</button>
    </div>
  );
};

export { Dashboard };

Each Slice is Independent

Key principle: each slice only manages its own state. Dispatching setName("Alice") only affects the user slice — the cart slice is completely unaffected. This makes state changes predictable and easy to debug.

What If One Slice Needs to React to Another Slice's Action?

Sometimes you need cross-slice communication. For example: when a user logs out, you want to clear the cart too. This is done with extraReducers — a way for a slice to listen to actions it didn't define:

// Teaser — covered in detail in Module 13 (async/thunks)
const cartSlice = createSlice({
  name: "cart",
  initialState,
  reducers: { /* ... */ },
  extraReducers: (builder) => {
    // React to an action from another slice
    builder.addCase(logout, (state) => {
      state.items = [];
    });
  },
});

This keeps slices decoupled — the cart slice doesn't import from the user slice's internals, it just listens for a specific action type.
