Core Concepts Recap

ConceptWhat It IsAnalogy
ActionPlain object describing what happened ({ type, payload })An event message
ReducerPure function: (state, action) → newStateEvent handler
StoreSingle object holding the entire app stateDatabase for the frontend
SliceBundle of reducer + actions + initial state for one featureA feature module
DispatchFunction to send actions to the storeSending a message
SelectorFunction to read specific data from the storeA database query

Decision Guide: useState vs Context vs Redux

ScenarioUseWhy
Form input, toggle, local UI stateuseStateSimple, component-scoped, no sharing needed
Theme, locale, auth status (read-mostly)ContextRarely changes, many components read it
Frequently updated shared state (cart, notifications)ReduxFine-grained subscriptions, DevTools, predictable updates
Complex state logic (many actions, derived data)ReduxReducers organize logic, selectors compute derived state
Server data (API responses, caching)React Query / RTK QueryBuilt-in caching, refetching, loading states

Key TypeScript Types

// Derived from the store — always up to date
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

// For typing action payloads in slice reducers
import { PayloadAction } from "@reduxjs/toolkit";

setName(state, action: PayloadAction<string>) {
  state.name = action.payload; // payload is typed as string
}

// Typed hooks — use these instead of raw useSelector/useDispatch
export const useAppSelector = useSelector.withTypes<RootState>();
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();

Common Mistakes to Avoid

MistakeWhy It's WrongFix
Mutating state outside of a reducerImmer only works inside createSlice/createReducer. Mutating elsewhere breaks Redux.Always dispatch an action to change state
Forgetting <Provider>useSelector/useDispatch throw errors without a store in contextWrap your app root in <Provider store={store}>
Circular imports between slicesSlice A imports from Slice B which imports from Slice A → crashUse extraReducers to listen to other slices' actions instead of importing their internals
Putting non-serializable values in stateFunctions, class instances, Promises break DevTools and time-travelStore only plain data (strings, numbers, arrays, objects)
Creating new references in selectors.filter() or .map() inside useSelector creates a new array every renderUse memoized selectors (createSelector) or select primitives
Using raw useSelector/useDispatch without typingLoses type safety — state becomes unknownUse typed hooks (useAppSelector, useAppDispatch)

The Complete Data Flow

// 1. User clicks a button
<button onClick={() => dispatch(addItem({ id: "1", title: "Book", price: 20 }))}>

// 2. Action is created
{ type: "cart/addItem", payload: { id: "1", title: "Book", price: 20 } }

// 3. Store dispatches action to the reducer
// cartSlice reducer handles "cart/addItem"

// 4. Reducer produces new state (via Immer)
state.items.push({ ...action.payload, quantity: 1 });

// 5. Store notifies subscribers
// useSelector re-runs, component re-renders with new data

This unidirectional flow — UI → Action → Reducer → Store → UI — is what makes Redux predictable and debuggable.
