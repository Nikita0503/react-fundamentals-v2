Summary

In this module, we covered the basic usage of Redux, where there is 1 Reducer and 2 Actions. As the application code grows, the number of Reducers and Actions may increase.

Questions arise:

"How to understand when to create new Reducers?"

Answer - there is no strict rule, but you can use the principle "One page - one Reducer". If we add a page with a task list and a login form to our example, it would be quite appropriate to create tasksReducer and loginReducer, then the RootReducer would look approximately like this:

/** /redux/store */

import { combineReducers, createStore } from 'redux';
import userReducer from './reducers/userReducer';
import userReducer from './reducers/tasksReducer';
import userReducer from './reducers/loginReducer';

const rootReducer = combineReducers({
    user: userReducer,
    tasks: tasksReducer,
    login: loginReducer,
});

export const store = createStore(rootReducer);

"Should all data be moved to the Store?"

Answer - no, it shouldn't. If there are reactive variables that only affect the component in which they are created and used, and they are not needed in other parts of the code, there is no point in moving them to the Store. Data moved to the Store is data that can be used in multiple parts of the code located in different areas of the project.

"Isn't there too much code for working with Redux?"

Answer - indeed, there is a lot of boilerplate code in Redux. And this is its biggest drawback, but there is a solution - Redux Toolkit, which allows writing less code.

"Why don't we immediately look at Redux Toolkit for working with Redux?"

Answer - because for a better understanding of the technology, it is better to look at Redux in its pure form. Redux without Toolkit can be found in projects, and it is better to understand how to work with it first, and then Toolkit can be studied independently. This is much easier to do than the other way around.

"There are much simpler alternatives to Redux, for example MobX, why Redux?"

Answer - because it is easier to scale, it has greater popularity, which indicates greater trust due to its convenience, predictability, and stability. Most projects use Redux.

"Is that all? Is there anything else in Redux?"

Answer - there is much more. For example, redux-persist - can save values in Reducers when the application closes and restore this data automatically after reopening. Redux-thunk / redux-saga - helps move interaction logic, for example with REST API, from the component to other parts of the project to improve architecture and code readability. Reselect - an analog of useMemo from React, but for Redux. This list is very long. Due to its great popularity, there are many helper libraries that cover almost 100% of needs.
