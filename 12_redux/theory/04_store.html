What is the Store?

The store is the single source of truth for your entire application's state. It:

  • Holds the complete state tree
  • Allows access to state via getState()
  • Allows state updates via dispatch(action)
  • Registers listeners via subscribe()

There is only one store per application. Different "areas" of state are managed by different reducers, but they all live in the same store.

The Legacy createStore (deprecated)

The old way used createStore from the redux package. You may see it in older codebases:

// ❌ Deprecated — don't use in new code
import { createStore } from "redux";
const store = createStore(rootReducer);

This still works but provides no middleware, no DevTools, and no development safety checks out of the box.

The RTK Way: configureStore()

Redux Toolkit's configureStore is the modern replacement. It gives you everything you need with sensible defaults:

// store/store.ts
import { configureStore } from "@reduxjs/toolkit";
import { userReducer } from "./userReducer";

export const store = configureStore({
  reducer: {
    user: userReducer,
  },
});

What configureStore does automatically:

  • ✅ Sets up Redux DevTools — inspect state, time-travel debug, see action history
  • ✅ Adds redux-thunk middleware — for async logic (API calls, etc.)
  • ✅ Adds serializable check middleware (dev only) — warns if you put non-serializable values in state (functions, class instances, Promises)
  • ✅ Adds immutability check middleware (dev only) — catches accidental mutations outside of Immer

TypeScript: Deriving Types from the Store

The key TypeScript pattern: derive your types from the store itself, not the other way around:

// store/store.ts
import { configureStore } from "@reduxjs/toolkit";
import { userReducer } from "./userReducer";
import { cartReducer } from "./cartReducer";

export const store = configureStore({
  reducer: {
    user: userReducer,
    cart: cartReducer,
  },
});

// Infer types FROM the store — single source of truth
export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

Now RootState automatically reflects the shape of your entire state tree. Add a new reducer — the type updates automatically. No manual maintenance.

Typed Hooks (recommended)

Create pre-typed hooks so you don't have to annotate types every time you use Redux in a component:

// store/hooks.ts
import { useDispatch, useSelector } from "react-redux";
import type { RootState, AppDispatch } from "./store";

// Use these throughout your app instead of plain useDispatch/useSelector
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();

Connecting to React: Provider

The store needs to be made available to your React component tree via the <Provider> component:

// App.tsx
import { Provider } from "react-redux";
import { store } from "./store/store";

const App = () => (
  <Provider store={store}>
    <YourAppContent />
  </Provider>
);

export default App;

The Provider uses React Context internally to make the store accessible to any nested component via useSelector and useDispatch.

Full Working Example

Let's put it all together — a minimal but complete setup:

store/userReducer.ts

import { createReducer, createAction } from "@reduxjs/toolkit";

// Actions
export const setName = createAction<string>("user/setName");
export const setEmail = createAction<string>("user/setEmail");

// State type
type UserState = {
  name: string;
  email: string;
};

const initialState: UserState = {
  name: "",
  email: "",
};

// Reducer
export const userReducer = createReducer(initialState, (builder) => {
  builder
    .addCase(setName, (state, action) => {
      state.name = action.payload;
    })
    .addCase(setEmail, (state, action) => {
      state.email = action.payload;
    });
});

store/store.ts

import { configureStore } from "@reduxjs/toolkit";
import { userReducer } from "./userReducer";

export const store = configureStore({
  reducer: {
    user: userReducer,
  },
});

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;

store/hooks.ts

import { useDispatch, useSelector } from "react-redux";
import type { RootState, AppDispatch } from "./store";

export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();

App.tsx

import { Provider } from "react-redux";
import { store } from "./store/store";
import { UserForm } from "./components/UserForm";

const App = () => (
  <Provider store={store}>
    <UserForm />
  </Provider>
);

export default App;

components/UserForm.tsx

import { useAppDispatch, useAppSelector } from "../store/hooks";
import { setName, setEmail } from "../store/userReducer";

const UserForm = () => {
  const dispatch = useAppDispatch();
  const name = useAppSelector((state) => state.user.name);
  const email = useAppSelector((state) => state.user.email);

  return (
    <div>
      <input
        value={name}
        onChange={(e) => dispatch(setName(e.target.value))}
        placeholder="Name"
      />
      <input
        value={email}
        onChange={(e) => dispatch(setEmail(e.target.value))}
        placeholder="Email"
      />
      <p>Hello, {name} ({email})</p>
    </div>
  );
};

export { UserForm };

This is a fully functional Redux setup with TypeScript. The component reads from the store and dispatches actions — all type-safe, all predictable.
