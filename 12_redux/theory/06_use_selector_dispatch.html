useSelector — Reading Data from the Store

useSelector is a React-Redux hook that lets you extract data from the Redux store. It takes a selector function that receives the entire state and returns the piece you need:

import { useSelector } from "react-redux";
import type { RootState } from "../store/store";

// Selector function: (state: RootState) => value
const name = useSelector((state: RootState) => state.user.name);

Every time the store updates, useSelector re-runs your selector. If the returned value has changed (by reference), the component re-renders. If it hasn't — no re-render.

useDispatch — Sending Actions to the Store

useDispatch returns the store's dispatch function. You use it to send actions:

import { useDispatch } from "react-redux";
import { setName } from "../store/slices/userSlice";

const dispatch = useDispatch();
dispatch(setName("Alice"));

Two Approaches to Typing

Approach 1: Generic annotations (verbose)

You can type each usage manually with generics:

import { useSelector, useDispatch } from "react-redux";
import type { RootState, AppDispatch } from "../store/store";

// Must annotate every useSelector call
const name = useSelector<RootState, string>((state) => state.user.name);
const email = useSelector<RootState, string>((state) => state.user.email);
const items = useSelector<RootState, CartItem[]>((state) => state.cart.items);

// Must annotate every useDispatch call
const dispatch = useDispatch<AppDispatch>();

Problems:

  • Repetitive — you type RootState and AppDispatch in every component
  • Easy to forget — if you skip the generic, you lose type safety
  • Noisy — clutters the component code

Approach 2: Typed hooks (recommended)

Create pre-typed hooks once, use them everywhere:

// store/hooks.ts
import { useDispatch, useSelector } from "react-redux";
import type { RootState, AppDispatch } from "./store";

export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();

Now in components — no generics needed, full type safety automatically:

import { useAppDispatch, useAppSelector } from "../store/hooks";

// TypeScript knows state.user.name is string — no annotation needed
const name = useAppSelector((state) => state.user.name);
const dispatch = useAppDispatch();

Why this is better:

  • DRY — types defined once, used everywhere
  • Less noise — components stay clean
  • Impossible to forget — the hook is always typed
  • Refactor-friendly — change the store shape, types update everywhere

Full Component Example Using Typed Hooks

// components/UserProfile.tsx
import { useAppDispatch, useAppSelector } from "../store/hooks";
import { setName, setEmail, resetUser } from "../store/slices/userSlice";

const UserProfile = () => {
  const dispatch = useAppDispatch();
  const name = useAppSelector((state) => state.user.name);
  const email = useAppSelector((state) => state.user.email);

  return (
    <div>
      <h2>User Profile</h2>
      <input
        value={name}
        onChange={(e) => dispatch(setName(e.target.value))}
        placeholder="Name"
      />
      <input
        value={email}
        onChange={(e) => dispatch(setEmail(e.target.value))}
        placeholder="Email"
      />
      <p>{name} — {email}</p>
      <button onClick={() => dispatch(resetUser())}>Reset</button>
    </div>
  );
};

export { UserProfile };

Selector Patterns

Inline selectors — quick and simple for one-off usage:

const name = useAppSelector((state) => state.user.name);

Extracted selectors — reusable, testable, and named:

// store/slices/userSlice.ts (at the bottom of the slice file)
export const selectUserName = (state: RootState) => state.user.name;
export const selectUserEmail = (state: RootState) => state.user.email;
export const selectUser = (state: RootState) => state.user;

// In component:
import { selectUserName, selectUserEmail } from "../store/slices/userSlice";

const name = useAppSelector(selectUserName);
const email = useAppSelector(selectUserEmail);

When to extract selectors:

  • The same selector is used in multiple components
  • The selector computes derived data (filtering, sorting, totals)
  • You want to unit-test the selection logic

Performance: When Does useSelector Cause Re-renders?

useSelector uses reference equality (===) to decide if the component should re-render:

  • If the selected value is the same reference → no re-render
  • If the selected value is a new reference → re-render
// ✅ Good — primitive value, cheap comparison
const name = useAppSelector((state) => state.user.name);

// ⚠️ Careful — creates a new array reference every time
const expensiveItems = useAppSelector((state) =>
  state.cart.items.filter((item) => item.price > 100)
);
// This will re-render on EVERY store update, even unrelated ones!

// ✅ Fix — use a memoized selector (e.g., with createSelector from reselect)
// or extract the filtering logic outside the selector

Rule of thumb: Select the smallest piece of state you need. Prefer selecting primitives or stable references over computing new arrays/objects inside the selector.
