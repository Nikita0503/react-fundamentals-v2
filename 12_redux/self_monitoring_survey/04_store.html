Self-Monitoring Survey: Store & configureStore

1. What does configureStore provide by default that the legacy createStore does not?

Automatic state persistence to localStorage
(x) Redux DevTools integration, redux-thunk middleware, and development-only checks for mutations and non-serializable values
Built-in API fetching capabilities
Automatic React component memoization

2. What are RootState and AppDispatch?

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
Manually written interfaces that describe the store shape
(x) Types inferred from the store itself — RootState is the shape of the entire state tree, AppDispatch is the dispatch function type (including thunk support)
React context types for the Provider component
Generic types exported from the @reduxjs/toolkit package

3. What is the role of the <Provider store={store}> component?

It creates the Redux store when the app mounts
It automatically dispatches actions when props change
(x) It makes the store available to all nested components via React Context, enabling useSelector and useDispatch to work
It subscribes all child components to every state change

4. What happens if you use useSelector in a component that is NOT wrapped in a <Provider>?

It returns undefined silently
It uses a default empty store
(x) It throws a runtime error because there is no store in the React context
It works but without type safety
