Self-Monitoring Survey: Why State Management

1. When is Redux the most appropriate choice for state management?

When you need to manage a single form's input values
When you have a theme toggle that rarely changes
(x) When multiple unrelated components need to read and update the same frequently-changing data
When you need to fetch data from an API and cache it

2. What problem does "prop drilling" refer to?

Components re-rendering too often due to state changes
(x) Passing data through many intermediate components that don't use it, just to reach a deeply nested child
Having too many props on a single component
Using props instead of state for dynamic values

3. What is the direction of data flow in Redux?

Bidirectional — components can read and write state directly
Bottom-up — child components push state to parents
(x) Unidirectional — UI dispatches actions → reducer updates state → store notifies UI
Circular — state flows from store to components and back to store simultaneously

4. Which of the following is NOT a valid reason to introduce Redux into a project?

You need time-travel debugging for complex state transitions
Multiple components across different routes need the same data
(x) You have a simple app with 3 components and local form state
You want a predictable, centralized state container with DevTools
