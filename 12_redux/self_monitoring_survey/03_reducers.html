What parameters does a Reducer accept in Redux?


( ) State and Action Type (x) Current Store and Action ( ) Action and Payload

Why should a Reducer not modify the current Store in Redux?


( ) Because modifying the Store can cause an error in React ( ) To simplify the code (x) Because the Store in Redux is immutable ( ) Usually Redux has multiple Store instances

Why is the default case in the Reducer's switch mandatory?


( ) To add additional fields to the Store (x) Because the Reducer must always return a Store instance, otherwise there will be an error ( ) To reduce the chances of collisions with other Reducers

What does a correct Reducer example for updating the Store in Redux look like?


Option 1: 
// userReducer.ts
interface UserState {
  name: string;
  surname: string;
}

type UserAction = {
  type: string;
  payload: string;
};

const userReducer = (state: UserState = initialState, action: UserAction): UserState => {
  switch(action.type){   
    case SET_NAME:
      state.name = action.payload
      break;
    case SET_SURNAME:
      state.surname = action.payload
      break;
  }
}

// userReducer.ts
interface UserState {
  name: string;
  surname: string;
}

type UserAction = {
  type: string;
  payload: string;
};

const userReducer = (state: UserState = initialState, action: UserAction): UserState => {
  switch(action.type){   
    case SET_NAME:
      return {
        ...state,
        name: action.payload
      }
    case SET_SURNAME:
      return {
        ...state,
        surname: action.payload
      }
    default: 
        return state
  }
}

What are the main principles of working with Store and Reducer in Redux?


( ) The Store should be mutable and contain all the business logic of the application. ( ) The Reducer should modify the Store directly, without using Actions. (x) A Reducer is a pure function that accepts the current Store state and an Action, and returns a new state.
