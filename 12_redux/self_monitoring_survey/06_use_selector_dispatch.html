Self-Monitoring Survey: useSelector & useDispatch

1. What does useSelector do?

It dispatches an action to update the store
It subscribes a component to ALL state changes in the store
(x) It takes a selector function, extracts a specific piece of state from the store, and re-renders the component only when that piece changes
It creates a new slice of state for the component

2. What does useDispatch return?

The current state of the store
A selector function
(x) The store's dispatch function, which you call with an action to trigger a state update
A reducer function

3. Why are typed hooks (useAppSelector, useAppDispatch) preferred over using useSelector and useDispatch directly?

// store/hooks.ts
export const useAppDispatch = useDispatch.withTypes<AppDispatch>();
export const useAppSelector = useSelector.withTypes<RootState>();
They make the app run faster by caching state
They are required by Redux Toolkit and won't compile without them
(x) They bake in the correct types (RootState, AppDispatch) once, so every component gets full type safety without repeating generic annotations
They automatically memoize all selectors

4. What will happen with this selector when ANY part of the store updates?

const expensiveItems = useAppSelector((state) =>
  state.cart.items.filter((item) => item.price > 50)
);
Nothing — useSelector is smart enough to detect the filter hasn't changed
(x) The component will re-render on every store update because .filter() creates a new array reference each time, even if the contents are identical
It will throw an error because you can't use .filter() inside a selector
It will only re-render when state.cart.items changes
