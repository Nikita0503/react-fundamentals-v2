Selectors — Why They Matter for Performance

// ❌ Bad — component re-renders on ANY store change
const Component = () => {
  const store = useTodoStore(); // subscribes to entire store
  return <p>{store.todos.length}</p>;
};

// ✅ Good — component only re-renders when todos.length changes
const Component = () => {
  const todoCount = useTodoStore((state) => state.todos.length);
  return <p>{todoCount}</p>;
};
  • The function you pass to the hook IS the selector
  • Zustand uses Object.is to compare previous and next selected value
  • If the selected value didn't change → no re-render
  • Rule: always select the minimum data your component needs

Selecting Multiple Values

// Option 1: multiple selectors (each triggers re-render independently)
const todos = useTodoStore((state) => state.todos);
const isLoading = useTodoStore((state) => state.isLoading);
// Option 2: return an object — BUT there's a problem!
const { todos, isLoading } = useTodoStore((state) => ({
  todos: state.todos,
  isLoading: state.isLoading,
}));
// ❌ This re-renders on EVERY store change!
// Why? The selector returns a new object { ... } every time.
// Zustand compares with Object.is — new object = different reference = re-render.
// Option 3: useShallow — fixes the problem
import { useShallow } from "zustand/react/shallow";

const { todos, isLoading } = useTodoStore(
  useShallow((state) => ({ todos: state.todos, isLoading: state.isLoading }))
);
// ✅ Now Zustand compares each field individually (shallow comparison).
// Re-renders only when todos OR isLoading actually changed — not on every store update.

When to use useShallow: when your selector returns an object or array. Without it, the new object reference triggers a re-render every time, even if the values inside didn't change. useShallow compares each field separately — re-render only happens when at least one field actually changed.

Persist Middleware — Save State to localStorage

import { create } from "zustand";
import { persist } from "zustand/middleware";

type ThemeStore = {
  theme: "light" | "dark";
  toggleTheme: () => void;
};

const useThemeStore = create<ThemeStore>()(
  persist(
    (set) => ({
      theme: "light",
      toggleTheme: () =>
        set((state) => ({ theme: state.theme === "light" ? "dark" : "light" })),
    }),
    { name: "theme-storage" } // key in localStorage
  )
);
  • State automatically saved to localStorage on every change
  • On page reload, state is restored from localStorage
  • name is the localStorage key

Immer Middleware — Simpler Nested Updates

Zustand's set() does shallow merge on the first level only. For nested objects, you still need to spread manually:

// Without immer — nested updates require spread at every level
set((state) => ({
  user: {
    ...state.user,
    address: {
      ...state.user.address,
      city: "LA",  // just changing one field, but so much code!
    },
  },
}));

With the immer middleware, you can write direct assignments — Immer creates the immutable copy for you under the hood:

import { create } from "zustand";
import { immer } from "zustand/middleware/immer";

type UserStore = {
  user: { name: string; address: { city: string; zip: string } };
  setCity: (city: string) => void;
};

const useUserStore = create<UserStore>()(
  immer((set) => ({
    user: { name: "Alice", address: { city: "NYC", zip: "10001" } },
    setCity: (city) =>
      set((state) => {
        state.user.address.city = city; // looks like mutation, but Immer makes it safe
      }),
  }))
);
  • Install: npm install immer
  • Same library used in Redux Toolkit — write mutations, Immer produces immutable updates
  • When to use: when your state has nested objects (2+ levels deep). For flat state like { count: 0 }, immer is unnecessary.

Async Actions — Fetching Data

import { useEffect } from "react";
import { create } from "zustand";
import { useShallow } from "zustand/react/shallow";

type User = { id: string; name: string; email: string };

type UserStore = {
  user: User | null;
  loading: boolean;
  error: string | null;
  fetchUser: (id: string) => Promise<void>;
};

const useUserStore = create<UserStore>((set) => ({
  user: null,
  loading: false,
  error: null,

  fetchUser: async (id) => {
    set({ loading: true, error: null });
    try {
      const res = await fetch(`/api/users/${id}`);
      const user = await res.json();
      set({ user, loading: false });
    } catch (err) {
      set({ error: "Failed to fetch user", loading: false });
    }
  },
}));

// Usage:
const Profile = ({ userId }: { userId: string }) => {
  const { user, loading, fetchUser } = useUserStore(
    useShallow((s) => ({ user: s.user, loading: s.loading, fetchUser: s.fetchUser }))
  );

  useEffect(() => {
    fetchUser(userId);
  }, [userId, fetchUser]);

  if (loading) return <p>Loading...</p>;
  return <p>{user?.name}</p>;
};
  • Actions can be async — just use async/await and call set when ready
  • Note: for server state with caching/refetching, TanStack Query is better. Zustand async is for simple cases or client-side async logic.

DevTools Middleware

import { create } from "zustand";
import { devtools } from "zustand/middleware";

type MyStore = {
  count: number;
  increment: () => void;
};

const useStore = create<MyStore>()(
  devtools(
    (set) => ({
      count: 0,
      increment: () => set((state) => ({ count: state.count + 1 })),
    }),
    { name: "MyStore" }
  )
);
  • Works with Redux DevTools browser extension
  • See state changes, time-travel debug

Combining Middleware

import { create } from "zustand";
import { devtools, persist } from "zustand/middleware";
import { immer } from "zustand/middleware/immer";

type MyStore = {
  count: number;
  increment: () => void;
};

const useStore = create<MyStore>()(
  devtools(
    persist(
      immer((set) => ({
        count: 0,
        increment: () =>
          set((state) => {
            state.count += 1;
          }),
      })),
      { name: "my-storage" }
    ),
    { name: "MyStore" }
  )
);

Middleware composes from inside out: immer → persist → devtools
