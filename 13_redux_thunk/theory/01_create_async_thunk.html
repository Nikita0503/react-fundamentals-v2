Why Async in Redux?

Redux reducers are pure, synchronous functions. They take state + action and return new state — no side effects allowed. But real applications need to make API calls, read from databases, or perform other async operations.

The question is: where does async logic live? The answer in Redux Toolkit is thunks.

What is a Thunk?

A thunk is a function that returns another function — it's a pattern for delaying execution. In Redux, a thunk is a function that:

  • Gets dispatched like a regular action
  • Receives dispatch and getState as arguments
  • Can contain async logic (API calls, timeouts, etc.)
  • Can dispatch other actions based on results

Redux Toolkit includes thunk middleware by default — no extra installation needed. When you use configureStore, thunk support is already there.

Simple Thunk (Manual Approach)

The simplest way to do async in Redux — just write an async function that dispatches actions manually:

// store/slices/usersSlice.ts
import { createSlice, PayloadAction } from "@reduxjs/toolkit";

type User = { id: number; name: string };

type UsersState = {
  items: User[];
  loading: boolean;
  error: string | null;
};

const initialState: UsersState = {
  items: [],
  loading: false,
  error: null,
};

const usersSlice = createSlice({
  name: "users",
  initialState,
  reducers: {
    setLoading(state, action: PayloadAction<boolean>) {
      state.loading = action.payload;
    },
    setUsers(state, action: PayloadAction<User[]>) {
      state.items = action.payload;
    },
    setError(state, action: PayloadAction<string | null>) {
      state.error = action.payload;
    },
  },
});

export const { setLoading, setUsers, setError } = usersSlice.actions;
export default usersSlice.reducer;
// store/thunks/fetchUsers.ts
import { AppDispatch } from "../store";
import { setLoading, setUsers, setError } from "../slices/usersSlice";

// A simple thunk — just a function that returns an async function
export const fetchUsers = () => async (dispatch: AppDispatch) => {
  dispatch(setLoading(true));
  dispatch(setError(null));
  try {
    const response = await fetch("/api/users");
    const users = await response.json();
    dispatch(setUsers(users));       // success — set data
  } catch (error) {
    dispatch(setError("Failed to fetch users")); // error — set message
  } finally {
    dispatch(setLoading(false));      // always — stop loading
  }
};

// Usage in component:
// dispatch(fetchUsers());

With parameters:

// Thunk that accepts a parameter
export const fetchUserById = (id: number) => async (dispatch: AppDispatch) => {
  dispatch(setLoading(true));
  try {
    const response = await fetch(`/api/users/${id}`);
    const user = await response.json();
    dispatch(setUsers([user]));
  } catch (error) {
    dispatch(setError("User not found"));
  } finally {
    dispatch(setLoading(false));
  }
};

// Usage:
// dispatch(fetchUserById(42));

Pros of simple thunks:

  • Easy to understand — it's just an async function that calls dispatch
  • Full control over loading/error states — you decide when to set them
  • Simple TypeScript — no complex generics
  • Easy to debug — you see every dispatch call

Cons:

  • Repetitive — you write setLoading/setError/setData for every async operation
  • No automatic action types for pending/fulfilled/rejected
  • Harder to track in DevTools (you see individual actions, not a grouped async flow)

Which Approach Do Developers Use?

createAsyncThunk automates the simple thunk pattern — it generates pending/fulfilled/rejected actions automatically, so you don't write setLoading/setError manually. But the TypeScript typing is more complex.

In practice, the community is split:

  • Simple thunks — many teams prefer them because they're transparent, easy to type, and give full control. You see exactly what happens step by step.
  • createAsyncThunk — useful when you have many similar async operations and want a consistent pattern (pending/fulfilled/rejected). Reduces boilerplate if you have 20+ API calls.

Our recommendation: start with simple thunks — they're easier to understand and debug. Use createAsyncThunk when you notice repetitive loading/error patterns across many slices.

createAsyncThunk Syntax

createAsyncThunk is RTK's utility for creating thunks that handle async operations. It takes two arguments:

  1. A string action type prefix (e.g., "user/fetchUser")
  2. A payload creator — an async function that returns the data
import { createAsyncThunk } from "@reduxjs/toolkit";

type User = {
  id: string;
  name: string;
  email: string;
};

const fetchUser = createAsyncThunk(
  "user/fetchUser",
  async (userId: string, thunkAPI) => {
    const response = await fetch(`/api/users/${userId}`);
    return response.json() as Promise<User>;
  }
);

What It Generates Automatically

createAsyncThunk automatically generates 3 lifecycle action types based on the string prefix you provide:

  • fetchUser.pending → "user/fetchUser/pending" — dispatched when the async function starts
  • fetchUser.fulfilled → "user/fetchUser/fulfilled" — dispatched when the Promise resolves
  • fetchUser.rejected → "user/fetchUser/rejected" — dispatched when the Promise rejects or you call rejectWithValue

You don't create these actions manually — they're generated for you. You just handle them in your reducer.

TypeScript: Typing createAsyncThunk

You can provide generic type parameters for full type safety:

// createAsyncThunk<ReturnType, ArgType, ThunkApiConfig>

type FetchUserError = {
  message: string;    // human-readable error text (to show in UI)
  statusCode: number; // HTTP status (to decide how to handle: 404 vs 500)
};

const fetchUser = createAsyncThunk<
  User,              // what the thunk returns on success (becomes action.payload in fulfilled)
  string,            // what you pass when dispatching: dispatch(fetchUser("123"))
  { rejectValue: FetchUserError }  // shape of the error object on failure
>(
  "user/fetchUser",
  async (userId, thunkAPI) => {
    const response = await fetch(`/api/users/${userId}`);

    if (!response.ok) {
      // Request failed — return structured error data
      // This object becomes action.payload in the rejected case
      return thunkAPI.rejectWithValue({
        message: "User not found",       // you choose what to put here
        statusCode: response.status,     // e.g., 404
      });
    }

    // Request succeeded — return the data
    // "as Promise<User>" tells TypeScript what type response.json() resolves to
    return response.json() as Promise<User>;
  }
);

Without parameters (void):

// When the thunk doesn't need any argument — use void
const fetchCurrentUser = createAsyncThunk<
  User,              // return type
  void,              // no argument needed
  { rejectValue: string }  // error is just a string
>(
  "user/fetchCurrent",
  async (_, thunkAPI) => {  // _ means "I'm ignoring this parameter"
    const response = await fetch("/api/me");
    if (!response.ok) {
      return thunkAPI.rejectWithValue("Failed to load profile");
    }
    return response.json() as Promise<User>;
  }
);

// Usage — no argument:
// dispatch(fetchCurrentUser());

Error Handling: rejectWithValue

By default, if your async function throws, the rejected action's payload is the error message. But you often want structured error data. Use thunkAPI.rejectWithValue():

const fetchUser = createAsyncThunk<
  User,
  string,
  { rejectValue: FetchUserError }
>(
  "user/fetchUser",
  async (userId, thunkAPI) => {
    try {
      const response = await fetch(`/api/users/${userId}`);
      if (!response.ok) {
        const errorData = await response.json();
        // This becomes action.payload in the rejected case
        return thunkAPI.rejectWithValue({
          message: errorData.message,
          statusCode: response.status,
        });
      }
      return (await response.json()) as User;
    } catch (error) {
      return thunkAPI.rejectWithValue({
        message: "Network error",
        statusCode: 0,
      });
    }
  }
);

Using dispatch and getState Inside a Thunk

The thunkAPI object gives you access to dispatch (to dispatch other actions) and getState (to read current state):

const fetchUserPosts = createAsyncThunk(
  "posts/fetchUserPosts",
  async (_, thunkAPI) => {
    // Read current state to get the logged-in user's ID
    const state = thunkAPI.getState() as RootState;
    const userId = state.auth.user?.id;

    if (!userId) {
      return thunkAPI.rejectWithValue("User not logged in");
    }

    const response = await fetch(`/api/users/${userId}/posts`);
    const posts = await response.json();

    // Dispatch another action from inside the thunk
    thunkAPI.dispatch(setLastFetched(Date.now()));

    return posts as Post[];
  }
);

getState() is useful when the thunk needs data that's already in the store (e.g., auth token, user ID). dispatch() lets you trigger side effects or update other slices from within the thunk.

Dispatching a Thunk

You dispatch a thunk just like any other action. It returns a Promise that you can await:

// In a component or another thunk:
dispatch(fetchUser("123"));

// You can also await the result:
const result = await dispatch(fetchUser("123"));

if (fetchUser.fulfilled.match(result)) {
  console.log("User loaded:", result.payload);
}

if (fetchUser.rejected.match(result)) {
  console.log("Error:", result.payload); // typed as FetchUserError
}

Full Example: Fetching a User

// store/thunks/fetchUser.ts
import { createAsyncThunk } from "@reduxjs/toolkit";

type User = {
  id: string;
  name: string;
  email: string;
  avatar: string;
};

type FetchUserError = {
  message: string;
  statusCode: number;
};

export const fetchUser = createAsyncThunk<
  User,
  string,
  { rejectValue: FetchUserError }
>(
  "user/fetchUser",
  async (userId, thunkAPI) => {
    try {
      const response = await fetch(`/api/users/${userId}`);

      if (!response.ok) {
        const errorData = await response.json();
        return thunkAPI.rejectWithValue({
          message: errorData.message || "Failed to fetch user",
          statusCode: response.status,
        });
      }

      return (await response.json()) as User;
    } catch (error) {
      return thunkAPI.rejectWithValue({
        message: "Network error — please check your connection",
        statusCode: 0,
      });
    }
  }
);
