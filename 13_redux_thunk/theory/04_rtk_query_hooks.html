Auto-Generated Hooks

When you import from "@reduxjs/toolkit/query/react", RTK Query automatically generates React hooks for every endpoint you define. The naming convention is:

  • Queries: use{EndpointName}Query — e.g., useGetPostsQuery
  • Mutations: use{EndpointName}Mutation — e.g., useAddPostMutation

These hooks handle everything: fetching, caching, loading states, error states, and refetching.

useQuery Hook Return Value

The query hook returns an object with all the state you need:

const {
  data,         // The response data (undefined until loaded)
  error,        // Error object if the request failed
  isLoading,    // true on first load (no cached data yet)
  isFetching,   // true whenever a request is in-flight (including refetches)
  isSuccess,    // true if the last request succeeded
  isError,      // true if the last request failed
  refetch,      // Function to manually trigger a refetch
} = useGetPostsQuery();

Key difference: isLoading is only true on the first request (no cached data). isFetching is true on any request, including background refetches.

Full Component Example with useQuery

// components/PostsList.tsx
import { useGetPostsQuery } from "../store/api/postsApi";

const PostsList = () => {
  const { data: posts, isLoading, error } = useGetPostsQuery();

  if (isLoading) {
    return <p>Loading posts...</p>;
  }

  if (error) {
    return <p style={{ color: "red" }}>Error loading posts</p>;
  }

  return (
    <ul>
      {posts?.map((post) => (
        <li key={post.id}>
          <h3>{post.title}</h3>
          <p>{post.body}</p>
        </li>
      ))}
    </ul>
  );
};

export { PostsList };

useMutation Hook

Mutations return a tuple: [triggerFunction, resultObject]:

const [addPost, { isLoading, isSuccess, isError, error }] = useAddPostMutation();

The trigger function is what you call to fire the mutation. The result object gives you the current state of that mutation.

Mutation Example: Form Submission

// components/AddPostForm.tsx
import { useState } from "react";
import { useAddPostMutation } from "../store/api/postsApi";

const AddPostForm = () => {
  const [title, setTitle] = useState("");
  const [body, setBody] = useState("");
  const [addPost, { isLoading }] = useAddPostMutation();

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    if (!title.trim() || !body.trim()) return;

    try {
      await addPost({ title, body, authorId: "user-1" }).unwrap();
      setTitle("");
      setBody("");
    } catch (err) {
      console.error("Failed to add post:", err);
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={title}
        onChange={(e) => setTitle(e.target.value)}
        placeholder="Post title"
      />
      <textarea
        value={body}
        onChange={(e) => setBody(e.target.value)}
        placeholder="Post body"
      />
      <button type="submit" disabled={isLoading}>
        {isLoading ? "Adding..." : "Add Post"}
      </button>
    </form>
  );
};

export { AddPostForm };

Query Parameters

Pass arguments to query hooks — they become the argument to your query function:

// The argument (postId) is passed to the query function
const { data: post, isLoading } = useGetPostByIdQuery(postId);

// In the API definition:
// getPostById: builder.query<Post, string>({
//   query: (postId) => `/posts/${postId}`,
// })

Hook Options

Query hooks accept an options object as the second argument:

const { data } = useGetPostsQuery(undefined, {
  // Skip the query (don't fetch) — useful for conditional fetching
  skip: !isLoggedIn,

  // Poll every 30 seconds
  pollingInterval: 30000,

  // Refetch when the component mounts or the arg changes
  refetchOnMountOrArgChange: true,

  // Refetch when the browser tab regains focus
  refetchOnFocus: true,
});

Cache Invalidation with Tags

Tags are RTK Query's mechanism for knowing when to refetch. The system works with two pieces:

  • providesTags — "this query provides data tagged as X"
  • invalidatesTags — "this mutation invalidates data tagged as X"

When a mutation invalidates a tag, all queries providing that tag automatically refetch.

endpoints: (builder) => ({
  // This query PROVIDES data tagged as "Post"
  getPosts: builder.query<Post[], void>({
    query: () => "/posts",
    providesTags: ["Post"],
  }),

  // This mutation INVALIDATES the "Post" tag
  // → getPosts will automatically refetch after addPost succeeds!
  addPost: builder.mutation<Post, Omit<Post, "id">>({
    query: (newPost) => ({
      url: "/posts",
      method: "POST",
      body: newPost,
    }),
    invalidatesTags: ["Post"],
  }),
})

This means: after you add a post, the posts list automatically refetches — no manual dispatch needed.

Full CRUD Example

// components/PostsManager.tsx
import { useGetPostsQuery, useAddPostMutation, useDeletePostMutation } from "../store/api/postsApi";
import { useState } from "react";

const PostsManager = () => {
  const { data: posts, isLoading } = useGetPostsQuery();
  const [addPost, { isLoading: isAdding }] = useAddPostMutation();
  const [deletePost] = useDeletePostMutation();
  const [newTitle, setNewTitle] = useState("");

  const handleAdd = async () => {
    if (!newTitle.trim()) return;
    await addPost({ title: newTitle, body: "New post body", authorId: "user-1" });
    setNewTitle("");
    // No need to refetch — tags handle it automatically!
  };

  const handleDelete = async (postId: string) => {
    await deletePost(postId);
    // Posts list refetches automatically because deletePost invalidates "Post" tag
  };

  if (isLoading) return <p>Loading...</p>;

  return (
    <div>
      <div>
        <input
          value={newTitle}
          onChange={(e) => setNewTitle(e.target.value)}
          placeholder="New post title"
        />
        <button onClick={handleAdd} disabled={isAdding}>
          {isAdding ? "Adding..." : "Add Post"}
        </button>
      </div>

      <ul>
        {posts?.map((post) => (
          <li key={post.id}>
            <span>{post.title}</span>
            <button onClick={() => handleDelete(post.id)}>Delete</button>
          </li>
        ))}
      </ul>
    </div>
  );
};

export { PostsManager };

Notice how the component never manually refetches the list. The tag system ensures the list stays in sync with mutations automatically.
