Where to Handle Async Actions: extraReducers

When you create a thunk with createAsyncThunk, it generates 3 action types (pending, fulfilled, rejected). But where do you handle them? In the extraReducers field of createSlice.

Why "extra"?

The reducers field in createSlice is for actions that the slice defines itself. The extraReducers field is for actions defined elsewhere — like thunks, or actions from other slices. They're "extra" because they weren't created by this slice's reducers object.

The Builder Pattern

extraReducers uses a builder callback with .addCase() for each action type you want to handle:

import { createSlice } from "@reduxjs/toolkit";
import { fetchUser } from "./thunks/fetchUser";

const userSlice = createSlice({
  name: "user",
  initialState,
  reducers: {
    // regular synchronous actions here
  },
  extraReducers: (builder) => {
    builder
      .addCase(fetchUser.pending, (state) => {
        state.status = "loading";
        state.error = null;
      })
      .addCase(fetchUser.fulfilled, (state, action) => {
        state.status = "succeeded";
        state.data = action.payload;
      })
      .addCase(fetchUser.rejected, (state, action) => {
        state.status = "failed";
        state.error = action.payload?.message ?? "Unknown error";
      });
  },
});

The Standard Loading State Pattern

Almost every async slice follows this pattern for its state shape:

type User = {
  id: string;
  name: string;
  email: string;
};

type UserState = {
  data: User | null;
  status: "idle" | "loading" | "succeeded" | "failed";
  error: string | null;
};

const initialState: UserState = {
  data: null,
  status: "idle",
  error: null,
};

This gives you everything you need to show loading spinners, error messages, and data — all driven by the store.

Full Slice Example

// store/slices/userSlice.ts
import { createSlice } from "@reduxjs/toolkit";
import { fetchUser } from "../thunks/fetchUser";

type User = {
  id: string;
  name: string;
  email: string;
  avatar: string;
};

type UserState = {
  data: User | null;
  status: "idle" | "loading" | "succeeded" | "failed";
  error: string | null;
};

const initialState: UserState = {
  data: null,
  status: "idle",
  error: null,
};

const userSlice = createSlice({
  name: "user",
  initialState,
  reducers: {
    clearUser(state) {
      state.data = null;
      state.status = "idle";
      state.error = null;
    },
  },
  extraReducers: (builder) => {
    builder
      .addCase(fetchUser.pending, (state) => {
        state.status = "loading";
        state.error = null;
      })
      .addCase(fetchUser.fulfilled, (state, action) => {
        state.status = "succeeded";
        state.data = action.payload;
      })
      .addCase(fetchUser.rejected, (state, action) => {
        state.status = "failed";
        state.error = action.payload?.message ?? "Unknown error";
      });
  },
});

export const { clearUser } = userSlice.actions;
export const userReducer = userSlice.reducer;

Component Example: Using the Thunk

Here's how a component dispatches the thunk and reacts to the loading/error/data states:

// components/UserProfile.tsx
import { useEffect } from "react";
import { useAppDispatch, useAppSelector } from "../store/hooks";
import { fetchUser } from "../store/thunks/fetchUser";
import { clearUser } from "../store/slices/userSlice";

type UserProfileProps = {
  userId: string;
};

const UserProfile = ({ userId }: UserProfileProps) => {
  const dispatch = useAppDispatch();
  const { data: user, status, error } = useAppSelector((state) => state.user);

  useEffect(() => {
    dispatch(fetchUser(userId));

    return () => {
      dispatch(clearUser());
    };
  }, [dispatch, userId]);

  if (status === "loading") {
    return <p>Loading user...</p>;
  }

  if (status === "failed") {
    return <p style={{ color: "red" }}>Error: {error}</p>;
  }

  if (!user) {
    return null;
  }

  return (
    <div>
      <img src={user.avatar} alt={user.name} />
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  );
};

export { UserProfile };

When to Use createAsyncThunk

Use it when:

  • You need the fetched data in the Redux store (not just local component state)
  • Multiple components consume the same async data
  • You need to track loading/error state globally
  • Other parts of the app need to react to the fetch lifecycle (e.g., show a global loading bar)

Don't use it when:

  • Data is only used by one component — just use useEffect + useState
  • You don't need caching or global access — consider React Query / TanStack Query
  • You have many endpoints with similar patterns — RTK Query (next section) is better
