What is a Single-Page Application (SPA)?

A Single-Page Application (SPA) is a web application that loads one HTML page and then dynamically updates content using JavaScript — without full page reloads.

In a traditional website, every link click sends a request to the server, which returns a completely new HTML page. In an SPA, the browser loads the application once, and all subsequent "page changes" are handled by JavaScript on the client side.

How it Works

  1. The browser loads the initial HTML page (usually just a <div id="root"> and a JavaScript bundle)
  2. JavaScript takes over and renders the UI
  3. When the user navigates (clicks a link), the URL changes but no new page is requested from the server
  4. A client-side router intercepts the URL change and renders the appropriate component
  5. Only data (JSON) is fetched from the server when needed — not entire pages

SPA Advantages

  • Fast navigation: No page reloads means instant transitions between views
  • Smooth user experience: The app feels native, like a desktop or mobile application
  • Clear separation of frontend and backend: The frontend is a standalone application that communicates with the backend via APIs
  • Rich interactivity: Complex UI interactions (drag-and-drop, real-time updates, animations) are natural to implement

SPA Disadvantages

  • Initial load can be slow: The browser must download the entire JavaScript bundle before the app becomes interactive
  • SEO challenges: Search engines may struggle to index content that is rendered by JavaScript (not present in the initial HTML)
  • Browser history needs special handling: The back/forward buttons don't work automatically — a client-side router must manage navigation state (this is solved by routing libraries)

Modern Solutions to SPA Problems

The React ecosystem has mature solutions for every SPA limitation:

  • Code splitting / lazy loading: Load only the code needed for the current page. The rest is loaded on demand. This dramatically reduces initial bundle size.
  • Server-Side Rendering (SSR): Frameworks like Next.js render the page on the server first, send ready HTML to the browser, then "hydrate" it with JavaScript for interactivity. This solves both SEO and initial load speed.
  • Static Site Generation (SSG): Pre-render pages at build time. The result is plain HTML files that load instantly and are perfectly indexable by search engines.

React Supports All Approaches

  • Pure SPA: Vite + React Router (client-side only)
  • SSR: Next.js (server-rendered with hydration)
  • SSG: Next.js, Astro (pre-rendered at build time)

For this course, we'll build a pure SPA — it's the foundation you need before moving to SSR or SSG. Understanding how a client-side app works makes server-side concepts much easier to grasp later.
