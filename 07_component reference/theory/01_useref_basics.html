What is useRef?

useRef is a React hook that returns a mutable object with a single property: { current: T }. This object persists across renders — React keeps the same reference between re-renders, so you can store values in it without losing them.

Two Main Use Cases

  1. Accessing DOM elements directly — get a reference to an actual DOM node (input, div, etc.) to call imperative methods like .focus(), .scrollIntoView(), or .getBoundingClientRect()
  2. Storing mutable values that don't trigger re-renders — keep track of timer IDs, previous values, render counts, or any data that should persist between renders but doesn't need to update the UI

Quick Example — Focus an Input

import { useRef } from "react";

const SearchBar = () => {
  const inputRef = useRef<HTMLInputElement>(null);

  const handleClick = () => {
    inputRef.current?.focus(); // directly access the DOM element
  };

  return (
    <div>
      <input ref={inputRef} placeholder="Search..." />
      <button onClick={handleClick}>Focus input</button>
    </div>
  );
};

Click the button → the input gets focused. No state needed, no re-render — just direct DOM access via ref.current.

Syntax

const ref = useRef<T>(initialValue);

The generic T defines the type of ref.current. The initialValue is what .current starts as.

The Key Property: .current

The returned object has one property — .current. You can read and write to it freely:

const myRef = useRef<number>(0);

// Read
console.log(myRef.current); // 0

// Write
myRef.current = 42;

Critical Difference from State

  • Changing ref.current does NOT trigger a re-render
  • Changing state (via setState) DOES trigger a re-render

This is the most important thing to understand about refs. If you update ref.current, the component will NOT re-render, and the UI will NOT reflect the new value until something else causes a re-render.

Comparison Table

Feature useState useRef
Triggers re-render on change Yes No
Persists between renders Yes Yes
Can be displayed in JSX Yes No (stale until next render)
Use for UI data DOM access, timers, previous values

When to Use Ref vs State

  • Use state: when the value should be reflected in the UI. If the user needs to see the value change on screen, it must be state.
  • Use ref: when you need to store something between renders but DON'T want to re-render when it changes. Think of it as a "silent" variable that React doesn't watch.

Example: State vs Ref

import { useState, useRef } from "react";

const Counter = () => {
  const [stateCount, setStateCount] = useState(0);
  const refCount = useRef(0);

  const incrementState = () => {
    setStateCount(prev => prev + 1); // triggers re-render → UI updates
  };

  const incrementRef = () => {
    refCount.current += 1; // no re-render → UI does NOT update
    console.log("refCount:", refCount.current); // value changes, but only visible in console
  };

  return (
    <div>
      <p>State: {stateCount}</p>
      <p>Ref: {refCount.current}</p>
      <button onClick={incrementState}>Increment State</button>
      <button onClick={incrementRef}>Increment Ref</button>
    </div>
  );
};

Try clicking "Increment Ref" several times — the number on screen stays at 0. The value IS changing (check the console), but React doesn't know about it because ref changes don't trigger re-renders. Now click "Increment State" — both numbers update, because the state change causes a re-render and React reads the latest refCount.current.
