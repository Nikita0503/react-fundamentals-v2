The Problem: Refs Don't Pass Through Components

When you create a custom component (e.g., <CustomInput />) and want to pass a ref to the underlying DOM element inside it, it won't work by default. The ref prop is special — React handles it differently from regular props and does NOT forward it to child components automatically.

forwardRef — Forwarding Refs to Child Components

forwardRef lets a component receive a ref from its parent and forward it to a DOM element (or another component) inside:

import { forwardRef, useRef } from "react";

type CustomInputProps = {
  label: string;
  placeholder?: string;
};

const CustomInput = forwardRef<HTMLInputElement, CustomInputProps>(
  ({ label, placeholder }, ref) => {
    return (
      <label>
        {label}
        <input ref={ref} placeholder={placeholder} />
      </label>
    );
  }
);

CustomInput.displayName = "CustomInput";

// Usage in parent:
const Form = () => {
  const inputRef = useRef<HTMLInputElement>(null);

  const focusInput = () => {
    inputRef.current?.focus();
  };

  return (
    <div>
      <CustomInput ref={inputRef} label="Email" placeholder="you@example.com" />
      <button onClick={focusInput}>Focus email input</button>
    </div>
  );
};

TypeScript with forwardRef

The generic signature is forwardRef<RefType, PropsType>:

  • First generic — the type of the ref (what .current will be). Usually an HTML element type.
  • Second generic — the props type of the component.

The component function receives (props, ref) — note that ref is the second argument, not part of props.

displayName

Always set displayName on forwarded ref components. Without it, React DevTools will show the component as "ForwardRef" instead of its actual name, making debugging harder.

When to Use forwardRef

  • Building reusable UI components (Input, Button, Modal) that need to expose DOM access to their parent
  • Integrating with libraries that need DOM refs (focus management, animation libraries)
  • Building component libraries — consumers expect to be able to attach refs to your components

useImperativeHandle — Customizing the Exposed Ref

Sometimes you don't want to expose the entire DOM element — just specific methods. useImperativeHandle lets you customize what the ref exposes to the parent:

import { forwardRef, useRef, useImperativeHandle, useState } from "react";

type ModalHandle = {
  open: () => void;
  close: () => void;
};

const Modal = forwardRef<ModalHandle, { title: string }>(({ title }, ref) => {
  const [isOpen, setIsOpen] = useState(false);

  useImperativeHandle(ref, () => ({
    open: () => setIsOpen(true),
    close: () => setIsOpen(false),
  }));

  if (!isOpen) return null;
  return <div className="modal"><h2>{title}</h2></div>;
});

Modal.displayName = "Modal";

// Parent:
const App = () => {
  const modalRef = useRef<ModalHandle>(null);
  return (
    <div>
      <button onClick={() => modalRef.current?.open()}>Open Modal</button>
      <Modal ref={modalRef} title="Hello" />
    </div>
  );
};

When to Use useImperativeHandle

Use sparingly. Prefer props and callbacks for most parent-child communication. Imperative handles are for cases where declarative patterns don't fit well:

  • Focus management (focus a specific input inside a complex form component)
  • Scroll control (scroll to a specific position inside a virtualized list)
  • Open/close modals, drawers, or tooltips from a parent
  • Play/pause media players

If you can solve the problem with props and state, do that instead. Imperative handles make the data flow harder to follow.
