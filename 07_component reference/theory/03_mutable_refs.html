Mutable Refs — Storing Values Between Renders

The second major use case for useRef is storing values between renders without triggering re-renders. Think of it as "instance variables" for functional components — a place to keep data that persists across renders but doesn't affect the UI directly.

Example 1: Storing a Timer ID

This is the most common real-world use case. You need to store the interval/timeout ID so you can clear it later, but changing the ID shouldn't cause a re-render:

import { useRef, useState, useEffect } from "react";

const Stopwatch = () => {
  const [seconds, setSeconds] = useState(0);
  const intervalRef = useRef<ReturnType<typeof setInterval> | null>(null);

  const start = () => {
    if (intervalRef.current) return; // already running
    intervalRef.current = setInterval(() => {
      setSeconds(prev => prev + 1);
    }, 1000);
  };

  const stop = () => {
    if (intervalRef.current) {
      clearInterval(intervalRef.current);
      intervalRef.current = null;
    }
  };

  useEffect(() => {
    return () => stop(); // cleanup on unmount
  }, []);

  return (
    <div>
      <p>{seconds}s</p>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
    </div>
  );
};

Why not use state for the timer ID? Because changing it shouldn't re-render the component — it's not displayed in the UI. Using state would cause unnecessary re-renders every time you start or stop the timer.

Example 2: Tracking Previous Value

A common pattern is to remember the previous value of a state variable. This is useful for comparisons, animations, or showing "changed from X to Y" messages:

import { useRef, useEffect, useState } from "react";

const usePrevious = <T,>(value: T): T | undefined => {
  const ref = useRef<T | undefined>(undefined);
  useEffect(() => {
    ref.current = value;
  });
  return ref.current;
};

// Usage:
const Counter = () => {
  const [count, setCount] = useState(0);
  const prevCount = usePrevious(count);

  return (
    <p>Now: {count}, Before: {prevCount ?? "none"}</p>
  );
};

How it works: useEffect runs after render, so during render ref.current still holds the old value. After render, the effect updates it to the new value — ready for the next render.

Example 3: Render Count (Debugging)

const RenderCounter = () => {
  const renderCount = useRef(0);
  renderCount.current += 1;

  return <p>This component rendered {renderCount.current} times</p>;
};

This works because the ref persists between renders, and incrementing it doesn't cause another render (which would create an infinite loop if you used state).

Example 4: Preventing Stale Closures in Async Code

One of the trickiest bugs in React: closures in setTimeout, event listeners, or async callbacks capture the value of state at the time they were created. If state changes later, the closure still sees the old value. Refs solve this:

import { useState, useRef } from "react";

const LatestValue = () => {
  const [count, setCount] = useState(0);
  const countRef = useRef(count);
  countRef.current = count; // always keep ref in sync

  const handleDelayedLog = () => {
    setTimeout(() => {
      // count would be stale here (closure captures old value)
      // countRef.current is always the latest
      console.log("Latest count:", countRef.current);
    }, 3000);
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(prev => prev + 1)}>Increment</button>
      <button onClick={handleDelayedLog}>Log after 3s</button>
    </div>
  );
};

Click "Increment" a few times, then click "Log after 3s" — the logged value will be the latest count, not the count at the time you clicked the button.

The Rule

If you need the value to show in the UI → use state. If you just need to "remember" something between renders → use ref.
