Mistake 1: Infinite Loop — Object/Array in Dependencies

// ❌ Infinite loop! Object is recreated every render → new reference → effect re-runs → re-render → ...
useEffect(() => {
  fetchData(filters);
}, [{ status: "active", page: 1 }]); // new object every render!

// ✅ Fix: use primitive values or memoize
useEffect(() => {
  fetchData(status, page);
}, [status, page]); // primitives — stable references

Objects and arrays are compared by reference (Object.is). A new object literal {} is always a different reference from the previous render, so the effect re-runs every time, causing an infinite loop.

Mistake 2: Missing Dependencies (Lying About Deps)

// ❌ Bug: effect uses userId but doesn't list it as dependency
useEffect(() => {
  fetch(`/api/users/${userId}`).then(res => res.json()).then(data => setUser(data));
}, []); // userId changes but effect doesn't re-run!

// ✅ Fix: include all values used inside the effect
useEffect(() => {
  fetch(`/api/users/${userId}`).then(res => res.json()).then(data => setUser(data));
}, [userId]);

Rule: never lie about dependencies. If the effect uses a value, include it.

The ESLint plugin react-hooks/exhaustive-deps catches this automatically — always keep it enabled.

Mistake 3: Using useEffect for Things That Don't Need It

"You Might Not Need an Effect" — common cases where useEffect is wrong:

Derived state in useEffect

type Item = { id: string; active: boolean; name: string };

// ❌ Unnecessary effect for derived state
const [items, setItems] = useState<Item[]>([]);
const [filteredItems, setFilteredItems] = useState<Item[]>([]);
useEffect(() => {
  setFilteredItems(items.filter(i => i.active));
}, [items]);

// ✅ Just compute it during render
const [items, setItems] = useState<Item[]>([]);
const filteredItems = items.filter(i => i.active); // no effect needed!

Resetting state on prop change

// ❌ Resetting state on prop change with useEffect
useEffect(() => {
  setInput("");
}, [selectedItem]);

// ✅ Use key prop to reset component entirely
<InputForm key={selectedItem.id} />

Use useEffect for: synchronizing with external systems (APIs, subscriptions, DOM, timers)

Don't use useEffect for: transforming data, handling events, derived state

Mistake 4: Race Conditions in Fetch

// ❌ If userId changes quickly, responses may arrive out of order
useEffect(() => {
  fetch(`/api/users/${userId}`)
    .then(res => res.json())
    .then(data => setUser(data)); // might set stale data!
}, [userId]);

// ✅ Fix with cleanup flag
useEffect(() => {
  let cancelled = false;
  fetch(`/api/users/${userId}`)
    .then(res => res.json())
    .then(data => {
      if (!cancelled) setUser(data);
    });
  return () => { cancelled = true; };
}, [userId]);

If userId changes rapidly (e.g., user types fast), multiple requests fire. The responses can arrive out of order — the last request might resolve before an earlier one, leaving stale data in state. The cleanup flag (or AbortController) prevents this.

Summary of Rules

  1. Include all values used in the effect in the dependency array
  2. If you set something up, clean it up
  3. Don't use effects for derived/computed values — compute during render
  4. Handle race conditions for async effects
  5. Keep effects focused — one effect per concern
