What is a Side Effect?

A side effect is anything that reaches outside the component's rendering logic. When a component function runs, its primary job is to return JSX. Anything else — any interaction with the outside world — is a side effect.

Common examples of side effects:

  • Fetching data from an API — network requests to load or send data
  • Setting up timers — setTimeout, setInterval
  • Subscribing to events — addEventListener on window, document, or other targets
  • Directly manipulating the DOM — reading measurements, focusing inputs, scrolling
  • Writing to localStorage — persisting data in the browser
  • Logging — sending analytics events, console output

Pure Rendering

A component function should be pure during render — given the same props and state, it must return the same JSX. No network calls, no subscriptions, no DOM mutations during the render itself.

Side effects happen AFTER rendering. React provides the useEffect hook specifically for this purpose — it lets you say "run this code after the component has rendered, not during."

Component Lifecycle Phases

Every component goes through three phases during its existence:

  • Mount — the component appears in the DOM for the first time (initial render)
  • Update — the component re-renders due to a state or props change
  • Unmount — the component is removed from the DOM

Interview Note — Class Lifecycle Methods Parallel

In class components, these phases had dedicated methods:

  • componentDidMount() — runs after the first render
  • componentDidUpdate(prevProps, prevState) — runs after every re-render
  • componentWillUnmount() — runs before the component is removed

In functional components, useEffect handles ALL of these. One hook, three phases.

Mapping table:

Class method useEffect equivalent
componentDidMount useEffect(() => { ... }, [])
componentDidUpdate useEffect(() => { ... }, [dep])
componentWillUnmount useEffect(() => { return () => { ... } }, [])

Note: this mapping is simplified. useEffect is actually a different mental model (synchronize with an external system), but the mapping helps for interviews.

Why useEffect Exists

React needs a way to say "run this code AFTER the component renders, not during." Without useEffect, you'd have no safe place to put side effects — they'd run during render, causing bugs, infinite loops, and unpredictable behavior.

useEffect is React's escape hatch from the pure rendering world into the impure world of side effects.
