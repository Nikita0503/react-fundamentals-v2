What Is a Component Test?

A component test renders a React component into a virtual DOM and verifies it produces the correct output. You check what the user would see and interact with — not internal implementation details.

React Testing Library (RTL) Philosophy

React Testing Library is built on one principle: test components the way users interact with them. Users don't know about state variables, class names, or component instances. They see text, buttons, inputs, and links. So your tests should find elements by visible text, roles, and labels — NOT by internal implementation.

render() — Rendering a Component

render() takes a React component and renders it into a virtual DOM that you can query:

// Greeting.tsx — the component we're testing
type GreetingProps = { name: string };

const Greeting = ({ name }: GreetingProps) => {
  return <h1>Hello, {name}!</h1>;
};

export { Greeting };
// Greeting.test.tsx — the test
import { render, screen } from "@testing-library/react";
import { Greeting } from "./Greeting";

it("renders the greeting message", () => {
  render(<Greeting name="Alice" />);
  expect(screen.getByText("Hello, Alice!")).toBeInTheDocument();
});

screen Queries — How to Find Elements

The screen object provides methods to find rendered elements. Prefer queries that reflect how users find things:

QueryUse when
getByRole("button")Element has an ARIA role (button, heading, link, textbox). Preferred!
getByText("Submit")Find by visible text content
getByLabelText("Email")Find input by its associated label (great for accessibility!)
getByPlaceholderText("Search...")Find by placeholder text
getByTestId("custom-id")Last resort — when no semantic query works

Query Variants — getBy, queryBy, findBy

Each query comes in three variants. The difference is what happens when the element is not found:

PrefixIf element NOT foundUse when
getByThrows an error (test fails immediately)Element MUST be there right now
queryByReturns null (no error)You want to check that element does NOT exist
findByWaits and retries until found (async)Element appears later (after API call, timer, etc.)

How to choose:

  • "I expect this button to be on screen" → getByRole("button")
  • "I expect this error message to NOT be on screen" → queryByText("Error") (because getBy would throw before you can assert)
  • "I clicked submit, now I'm waiting for a success message to appear" → findByText("Success")
// getBy — element MUST exist right now. If missing, test fails with a clear error.
const button = screen.getByRole("button");
expect(button).toBeInTheDocument();

// queryBy — returns null if element is not found (instead of crashing the test).
// Perfect for checking that something is NOT on the screen.
// Why not getBy? Because getBy throws an error when element is missing —
// your test would crash before even reaching the .not check.
expect(screen.queryByText("Error message")).not.toBeInTheDocument();

// findBy — waits up to 1 second for element to appear. Returns a Promise.
// Use after async operations (data loading, setTimeout, etc.)
const userName = await screen.findByText("Alice");
expect(userName).toBeInTheDocument();

Common Assertions (from @testing-library/jest-dom)

These matchers are added by the @testing-library/jest-dom package and work on DOM elements:

expect(element).toBeInTheDocument();           // element exists in the DOM
expect(element).toHaveTextContent("Hello");    // element contains this text
expect(element).toBeDisabled();                // button/input is disabled
expect(element).toBeEnabled();                 // button/input is enabled
expect(element).toHaveAttribute("href", "/about"); // has specific attribute value
expect(element).toHaveClass("active");         // has specific CSS class
expect(element).toBeVisible();                 // element is visible to the user

Testing Conditional Rendering

One of the most common things to test — does the component show/hide elements based on props or state?

// Component
const Alert = ({ type, message }: { type: "error" | "success"; message: string }) => (
  <div role="alert" className={type}>
    {type === "error" && <span>⚠️</span>}
    {message}
  </div>
);

// Tests
describe("Alert", () => {
  it("shows error icon for error type", () => {
    render(<Alert type="error" message="Something failed" />);
    expect(screen.getByText("⚠️")).toBeInTheDocument();
  });

  it("does not show error icon for success type", () => {
    render(<Alert type="success" message="Done!" />);
    expect(screen.queryByText("⚠️")).not.toBeInTheDocument();
  });

  it("displays the message", () => {
    render(<Alert type="success" message="All good" />);
    expect(screen.getByRole("alert")).toHaveTextContent("All good");
  });
});
