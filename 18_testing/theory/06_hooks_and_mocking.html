Testing Custom Hooks with renderHook

Custom hooks can't be called outside of a component. renderHook solves this — it renders your hook in a minimal wrapper component so you can test it in isolation:

import { renderHook, act } from "@testing-library/react";
import { useCounter } from "./useCounter";

describe("useCounter", () => {
  it("starts with initial value", () => {
    const { result } = renderHook(() => useCounter(5));
    expect(result.current.count).toBe(5);
  });

  it("increments the count", () => {
    const { result } = renderHook(() => useCounter(0));

    act(() => {
      result.current.increment();
    });

    expect(result.current.count).toBe(1);
  });
});
  • renderHook — renders a hook outside of a real component (for isolated testing)
  • result.current — the current return value of the hook (updates after state changes)
  • act() — wraps code that triggers state updates. It tells React: "process this update completely before I make assertions." Required whenever you call functions that change state.

Mocking Modules with vi.mock

"Mocking" means replacing a real module with a fake version you control. This lets you isolate the code you're testing from its dependencies:

import { vi } from "vitest";

// Replace the entire module with fake implementations
vi.mock("./api/users", () => ({
  fetchUser: vi.fn().mockResolvedValue({ id: 1, name: "Alice" }),
}));
  • The real fetchUser is never called — your fake version runs instead
  • Useful for: API calls, external libraries, modules with side effects (like logging or analytics)
  • The mock is applied to the entire test file

vi.fn() — Creating Mock Functions

A "mock function" (also called a "stub") is a fake function that tracks how it was called and lets you control what it returns:

const mockCallback = vi.fn();

// Call it like a normal function
mockCallback("hello", 42);

// Assert HOW it was called
expect(mockCallback).toHaveBeenCalledTimes(1);
expect(mockCallback).toHaveBeenCalledWith("hello", 42);

// Control what it returns
const mockFetch = vi.fn().mockReturnValue("data");
const mockAsync = vi.fn().mockResolvedValue({ id: 1 }); // for async functions

vi.spyOn — Spy on Existing Methods

Unlike vi.mock (which replaces an entire module), spyOn watches a specific method on an existing object. You can track calls without replacing the whole module:

const spy = vi.spyOn(console, "error").mockImplementation(() => {});

// ... run code that calls console.error ...

expect(spy).toHaveBeenCalledTimes(1);
spy.mockRestore(); // restore the original console.error

Mocking Timers

Some code uses setTimeout or setInterval (like debounce). You don't want tests to actually wait 300ms. Fake timers let you control time manually:

import { vi } from "vitest";
import { renderHook, act } from "@testing-library/react";
import { useDebounce } from "./useDebounce";

describe("useDebounce", () => {
  beforeEach(() => vi.useFakeTimers());  // replace real timers with fakes
  afterEach(() => vi.useRealTimers());   // always restore real timers!

  it("returns debounced value after delay", () => {
    const { result, rerender } = renderHook(
      ({ value }) => useDebounce(value, 300),
      { initialProps: { value: "hello" } }
    );

    // Change the value
    rerender({ value: "world" });
    expect(result.current).toBe("hello"); // not updated yet — timer hasn't fired

    // Fast-forward time by 300ms
    act(() => { vi.advanceTimersByTime(300); });
    expect(result.current).toBe("world"); // now updated!
  });
});
  • vi.useFakeTimers() — replaces setTimeout/setInterval with controllable fakes
  • vi.advanceTimersByTime(ms) — fast-forward time by the specified milliseconds
  • vi.useRealTimers() — restore real timers (always do this in afterEach to avoid affecting other tests!)

Mocking react-router

When your component uses routing hooks, you need to mock them:

vi.mock("react-router-dom", async () => {
  const actual = await vi.importActual("react-router-dom");
  return {
    ...actual,                          // keep all real exports
    useNavigate: () => vi.fn(),         // replace only what you need
    useParams: () => ({ id: "42" }),
  };
});

vi.importActual imports the real module so you can keep most of it intact and only override specific exports.
