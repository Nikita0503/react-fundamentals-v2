Vitest — The Recommended Test Runner

Vitest is the recommended test runner for modern React projects. Here's why:

  • Built on Vite (same config, same speed as your dev server)
  • Native ESM support (no transform issues with modern JavaScript modules)
  • API compatible with Jest (the older standard) — easy migration between them
  • Fast: parallel execution, smart watch mode that only re-runs affected tests

Installation

npm install -D vitest @testing-library/react @testing-library/jest-dom @testing-library/user-event jsdom

What each package does:

  • vitest — the test runner itself (finds and executes test files, reports results)
  • @testing-library/react — utilities to render React components in tests and query the rendered output
  • @testing-library/jest-dom — extra matchers for DOM assertions (like toBeInTheDocument(), toHaveTextContent())
  • @testing-library/user-event — simulates real user interactions (typing, clicking) more realistically than basic events
  • jsdom — a fake browser environment that runs in Node.js. Since tests run in Node (not a real browser), jsdom provides the DOM APIs (document, window, etc.) that your components need

Configuration — vitest.config.ts

import { defineConfig } from "vitest/config";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()],
  test: {
    environment: "jsdom",
    globals: true, // no need to import describe/it/expect in every file
    setupFiles: "./src/test/setup.ts",
  },
});
  • environment: "jsdom" — tells Vitest to use the fake browser environment
  • globals: true — makes describe, it, expect available globally (no imports needed)
  • setupFiles — a file that runs before every test file (for global configuration)

Setup File — src/test/setup.ts

import "@testing-library/jest-dom";

This single import adds custom matchers (toBeInTheDocument, toHaveTextContent, toBeDisabled, etc.) to every test file automatically.

Package.json Scripts

{
  "scripts": {
    "test": "vitest",
    "test:run": "vitest run",
    "test:coverage": "vitest run --coverage"
  }
}
  • npm test — starts watch mode (re-runs tests automatically when you save a file)
  • npm run test:run — single run, then exits (used in CI/CD pipelines)
  • npm run test:coverage — runs tests and shows a coverage report (which lines of code were executed)

Your First Test

Let's write a simple utility and test it:

// src/utils/add.ts
export const add = (a: number, b: number): number => a + b;
// src/utils/add.test.ts
import { describe, it, expect } from "vitest";
import { add } from "./add";

describe("add", () => {           // describe — groups related tests under a name
  it("adds two positive numbers", () => {  // it — one specific test case
    expect(add(2, 3)).toBe(5);    // expect — checks that the result matches what you expect
  });

  it("handles negative numbers", () => {
    expect(add(-1, 1)).toBe(0);
  });
});

What each function does:

  • describe("name", () => { ... }) — creates a group of tests. The name describes what you're testing (e.g., "add"). You can nest describes inside each other.
  • it("description", () => { ... }) — defines a single test. The description says what specific behavior you're checking. Read it as a sentence: "it adds two positive numbers".
  • expect(value) — takes the actual result and lets you compare it with the expected result using a matcher (like .toBe(5)). If they don't match — the test fails.
  • File naming: *.test.ts or *.test.tsx — placed right next to the source file (co-located)
  • Run: npm test → see results in terminal

Vitest vs Jest — Almost Identical API

If you learn one, you know the other. The only differences are the import source and config format:

VitestJestNotes
vi.mock()jest.mock()Same syntax
vi.fn()jest.fn()Same syntax
vi.spyOn()jest.spyOn()Same syntax
vi.useFakeTimers()jest.useFakeTimers()Same syntax
describe/it/expectdescribe/it/expectIdentical

If you know Vitest, you know Jest (and vice versa). The only difference is the import (from "vitest" vs global in Jest) and the config file format.
