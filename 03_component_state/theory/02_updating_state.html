State is Read-Only

You should never mutate state directly. The setter function (setState) tells React "here's the new value, please re-render." Without calling the setter, React doesn't know anything changed.

Direct Value Update

The simplest way to update state — replace it with a specific value:

setCount(5);          // set count to exactly 5
setName("Alice");     // set name to "Alice"
setIsOpen(false);     // set isOpen to false

Functional Updater

Update based on the previous value by passing a function:

setCount(prev => prev + 1);  // increment based on previous value

The function receives the most recent state value as its argument and returns the new value.

Why Functional Updater is Important — The Stale Closure Problem

When you reference state directly inside an event handler, you capture the value from that render. If you call the setter multiple times, they all use the same stale value:

// ❌ Bug: if called multiple times in one event, uses stale value
const handleTripleIncrement = () => {
  setCount(count + 1); // all three use the same "count" value
  setCount(count + 1); // from the closure
  setCount(count + 1); // result: only +1, not +3
};

// ✅ Correct: each update sees the latest value
const handleTripleIncrement = () => {
  setCount(prev => prev + 1); // prev = 0 → 1
  setCount(prev => prev + 1); // prev = 1 → 2
  setCount(prev => prev + 1); // prev = 2 → 3
};

Rule of thumb: use the functional updater when the new value depends on the previous value.

Batching

React groups multiple setState calls in the same event handler into one re-render (not three separate re-renders). This is automatic since React 18.

const handleClick = () => {
  setName("Alice");       // queued
  setAge(25);             // queued
  setIsLoggedIn(true);    // queued
  // React re-renders ONCE with all three updates applied
};

This means React is smart about performance — it doesn't wastefully re-render after every single setter call.

State Updates are Asynchronous

You can't read the new value immediately after calling setState. The state variable still holds the old value until the next render:

const handleClick = () => {
  setCount(prev => prev + 1);
  console.log(count); // still the OLD value! React hasn't re-rendered yet.
};

The component will re-render with the new value — that's when you "see" it. If you need to use the new value in the same handler, calculate it in a variable first:

const handleClick = () => {
  const newCount = count + 1;
  setCount(newCount);
  console.log(newCount); // ✅ use the calculated value directly
};
