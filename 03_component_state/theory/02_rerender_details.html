Important Re-render Details

React is a fairly smart library and it has its own algorithms for deciding whether a component needs to be re-rendered.

import React, { useState } from 'react';

const Counter = () => {
  // Using the useState hook to create state with a default value of 0
  const [count, setCount] = useState(0);

  // Function to increment the counter value
  const increment = () => {
    setCount(count + 1);
  };

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;

Let's examine this logic using the useState example above.

Every time the user clicks the Increment button, the count value incremented by 1 is passed to the setCount function. Therefore, React allows the component to re-render. But if we call setCount and pass the same count value (setCount(count)), then React will compare the current and supposedly updated value and see that they are equal. In this case, React will not re-render the component to prevent unnecessary renders (re-draws) to preserve performance of the application.

However, this logic works with

primitive data

types. With objects, it works somewhat differently.

The basic rule of component re-rendering in React is based on comparing references to the old and new state of the component. That is, if instead of a simple number "0", the count variable contains an object "{value: 0}".

If the reference to the object in the component's state does not change, then React does not detect a difference in state and does not perform a re-render. However, if the reference to the object changes, React considers that the component's state has changed and performs a re-render of the component, even if the values inside the object remain unchanged.

That is, if you pass the same "{value: 0}" to setCount, React will see that this is a new object (a new reference to an object in memory), and will re-render the component, despite the fact that the values inside the object have not changed.

Here is an example of a functional Counter component using an object in state with an explanation of how the re-render rule works:

import React, { useState } from 'react';

const Counter = () => {
  // Using the useState hook to create state with an object {value: 0}
  const [count, setCount] = useState({ value: 0 });

  // Function to increment the counter value
  const increment = () => {
    // Using the setCount function passing a new state object with an incremented value
    setCount({ value: count.value + 1 });
  };

  return (
    <div>
      <p>Count: {count.value}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;

In this example, we use an object { value: 0 } as the initial state value. On each button click, we use the setCount function to update the component's state, passing a new state object with an incremented value. This will cause a re-render of the component, even if the value itself in the object remains unchanged, because the reference to the object has changed, and React considers that the component's state has changed.

However, if you change the data inside the count object and pass it to setCount, React will not understand that a re-render is needed. Because the reference to the object in memory has not changed:

import React, { useState } from 'react';

const Counter = () => {
  // Using the useState hook to create state with an object {value: 0}
  const [count, setCount] = useState({ value: 0 });

  // Function to increment the counter value
  const increment = () => {
    count.value = count.value + 1;
    setCount(count); // does not trigger a re-render
  };

  return (
    <div>
      <p>Count: {count.value}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;

In general, this is the logic of object comparison in JavaScript itself. Therefore, when you compare entire objects with each other in code, JS simply compares their references.
