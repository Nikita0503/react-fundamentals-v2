Важливі деталі перерендеру

React доволі розумна бібліотека і він має свої алгоритми вирішення, чи потрібно перемальовувати компонент.

import React, { useState } from 'react';

const Counter = () => {
  // Використання хука useState для створення стану зі значенням по замовчуванню 0
  const [count, setCount] = useState(0);

  // Функція для збільшення значення лічильника
  const increment = () => {
    setCount(count + 1);
  };

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;

Розглянемо цю логіку на зазначеному вище прикладі використання useState.

Кожного разу коли користувач натискає на кнопку Increment, до функції setCount передається значення count збільшене на 1. Тому React дозволяє перемалювати компонент. Але якщо ми будемо викликати setCount і передавати туди теж саме значення count (setCount(count)), то Raect порівняє поточне та ніби оновлене значення і побачить що вони є рівними. В такому разі React не буде перемальовувати компонент для запобігання зайвої кількості рендерів (перемальовок) для збереження продуктивності додатку.

Але така логіка працює з

елементарними типами

даних. З об`єктами це працює дещо інакше.

Звичайне правило перерендеру (перемальовки) компоненту в React базується на порівнянні посилань (references) на старий та новий стан компоненту. Тобто якщо замість звичайного числа «0» змінна count буде містити об’єкт «{value: 0}».

Якщо посилання на об'єкт в стані компоненту не змінюється, то React не виявляє різниці в стані та не виконує перерендер. Однак, якщо посилання на об'єкт змінюється, React вважає, що стан компоненту змінився і виконує перерендер компоненту, навіть якщо значення в самому об'єкті залишилося незмінним.

Тобто, якщо передати в setCount такий же «{value: 0}», React побачить що це новий об’єкт (нове посилання на об`єкт у пам`яті), та перемалює компонент, незважаючи на те що в середині об’єкту значення не змінилися.

Ось приклад функціонального компонента Counter з використанням об'єкта в стані та поясненням, як працює правило перерендеру:

import React, { useState } from 'react';

const Counter = () => {
  // Використання хука useState для створення стану з об'єктом {value: 0}
  const [count, setCount] = useState({ value: 0 });

  // Функція для збільшення значення лічильника
  const increment = () => {
    // Використання функції setCount з передачею нового об'єкта стану зі збільшеним значенням value
    setCount({ value: count.value + 1 });
  };

  return (
    <div>
      <p>Count: {count.value}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;

У цьому прикладі ми використовуємо об'єкт { value: 0 } як початкове значення стану. При кожному кліку на кнопку, ми використовуємо функцію setCount для оновлення стану компоненту, передаючи новий об'єкт стану зі збільшеним значенням value. Це призведе до перерендеру компоненту, навіть якщо саме значення value в об'єкті залишиться незмінним, оскільки посилання на об'єкт змінилося, і React вважає, що стан компоненту змінився.

Однак, якщо змінити дані в середині об’єкту count та передати його ж в setCount, Raect не зрозуміє, що потрібно зробити перерендер. Так як посилання на об’єкт в пам’яті не змінилося:

import React, { useState } from 'react';

const Counter = () => {
  // Використання хука useState для створення стану з об'єктом {value: 0}
  const [count, setCount] = useState({ value: 0 });

  // Функція для збільшення значення лічильника
  const increment = () => {
    count.value = count.value + 1;
    setCount(count); //  не викликає перерендер
  };

  return (
    <div>
      <p>Count: {count.value}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;

Взагалі, це є логіка порівняння об’єктів у самому javascript. Тому, коли ви порівнюєте цілі об’єкти між собою у коді, в js просто порівнюються їх посилання.
