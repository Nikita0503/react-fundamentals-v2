Lazy Initialization

If the initial state requires an expensive computation, pass a function to useState instead of calling it directly:

// ❌ Runs on EVERY render (expensive)
const [data, setData] = useState(parseLocalStorage());

// ✅ Runs only on FIRST render (lazy)
const [data, setData] = useState(() => parseLocalStorage());

The function form is only called once — on the initial render. On subsequent renders, React ignores it and uses the stored state value.

Use when: reading from localStorage, parsing large data, complex calculations for initial value.

Keep State Minimal

Don't store what you can derive from existing state:

// ❌ Redundant state
const [items, setItems] = useState<Item[]>([]);
const [itemCount, setItemCount] = useState(0); // derived from items!

// ✅ Derive it
const [items, setItems] = useState<Item[]>([]);
const itemCount = items.length; // no state needed

Derived values are recalculated on every render automatically. Storing them in state creates a synchronization problem — you have to remember to update both values together.

Lift State Up

If two sibling components need the same state, move it to their common parent. The parent owns the state and passes it down via props:

// Parent owns the shared state
const Parent = () => {
  const [filter, setFilter] = useState("");

  return (
    <div>
      <SearchInput value={filter} onChange={setFilter} />
      <ResultsList filter={filter} />
    </div>
  );
};

Common Mistakes

  1. Mutating state directly — use spread/map/filter to create new references.
  2. Reading state immediately after setting it — state updates are asynchronous; the new value appears on the next render.
  3. Using state for values that don't affect UI — use useRef instead to avoid unnecessary re-renders (covered in a later module).
  4. Storing derived data in state — compute it from existing state instead.
  5. Not using functional updater when depending on previous value — leads to stale closure bugs.
// Example of mistake #3: using state for non-UI value
// ❌ Causes re-render every time intervalId changes
const [intervalId, setIntervalId] = useState<number | null>(null);

// ✅ useRef — no re-render, value persists between renders
const intervalRef = useRef<number | null>(null);
