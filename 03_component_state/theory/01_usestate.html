What is State?

State is data that can change over time and triggers a re-render when it does. When state changes, React re-executes the component function and updates the UI to reflect the new data.

Why Not Regular Variables?

A regular let variable doesn't work for UI state because:

  • It resets on every render — the component function runs again, and the variable is re-initialized.
  • Changing it doesn't trigger a re-render — React has no way to know the value changed.
// ❌ This doesn't work — variable resets on every render
const Counter = () => {
  let count = 0;
  const increment = () => { count += 1; }; // UI won't update
  return <p>Count: {count}</p>;
};

No matter how many times you click, the UI will always show Count: 0.

useState Syntax

React provides the useState hook to solve this problem:

const [value, setValue] = useState(initialValue);

What's happening here:

  • useState(initialValue) — returns an array with two elements.
  • [value, setValue] — array destructuring to name them. value is the current state, setValue is the function to update it.
  • Naming convention: value / setValue — e.g., count / setCount, name / setName.

Working Counter Example

import { useState } from "react";

const Counter = () => {
  const [count, setCount] = useState(0);

  const increment = () => {
    setCount(count + 1); // tells React: "new value is count + 1, please re-render"
  };

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

Now clicking the button updates the UI because setCount tells React to re-render with the new value.

TypeScript: When to Use the Generic useState<T>()

NOT needed when TypeScript can infer the type from the initial value:

const [count, setCount] = useState(0);        // infers number
const [name, setName] = useState("");          // infers string
const [isOpen, setIsOpen] = useState(true);    // infers boolean

NEEDED when the initial value doesn't reveal the full type:

// Will be User later, but starts as null
const [user, setUser] = useState<User | null>(null);

// Empty array — TS can't infer element type
const [items, setItems] = useState<string[]>([]);

// Union type — initial value is just one variant
const [status, setStatus] = useState<"idle" | "loading" | "error">("idle");

Multiple useState in One Component

Each piece of state is independent. You can have as many useState calls as you need:

const SignupForm = () => {
  const [name, setName] = useState("");
  const [email, setEmail] = useState("");
  const [age, setAge] = useState<number | null>(null);
  // Each piece of state is independent
};

When to Use State vs a Regular Variable

  • Use state: when the value should be displayed in UI and can change over time.
  • Use a regular variable/const: for derived values, calculations, event handler logic that doesn't need to persist between renders.
const ProductList = () => {
  const [products, setProducts] = useState<Product[]>([]);
  const [searchTerm, setSearchTerm] = useState("");

  // ✅ Derived value — no state needed
  const filteredProducts = products.filter(p =>
    p.name.toLowerCase().includes(searchTerm.toLowerCase())
  );

  // ✅ Regular const — doesn't need to persist between renders
  const hasResults = filteredProducts.length > 0;

  return (/* ... */);
};
