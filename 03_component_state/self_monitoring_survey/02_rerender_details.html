Що буде, якщо викликати setCount із тим самим значенням count (setCount(count)) у функціональному компоненті React, що використовує хук useState?


( ) Запуститься перерендер компонента, але із затримкою. (x) Не відбудеться перерендер компонента, React оптимізує ігнорування подібних оновлень. ( ) З'явиться помилка виконання (runtime error) через неявну рекурсію.

Які основні принципи визначення необхідності перерендеру компонента в React?


( ) Перерендер відбувається завжди при виклику setCount незалежно від значення count. (x) Перерендер відбувається тільки при зміні значення в стані компонента. ( ) Перерендер відбудеться, якщо setCount викликається з тим самим значенням, що і поточний стан.

Основні принципи перерендеру компонента React при використанні хука useState та об'єктів у стані компонента


( ) Перерендер завжди відбудеться при кожному виклику setCount, незалежно від змін у стані об'єкта. ( ) Перерендер завжди відбудеться, якщо будь-який ключ у об'єкті стану змінюється, навіть якщо посилання залишається незмінним. (x) Перерендер відбудеться тільки у випадку, якщо setCount викликається з новим об'єктом, а не тим самим посиланням на об'єкт.

У компоненті Counter стан є об'єктом, в якому варіанті коду відбудеться перерендер?


Варіант 1:
import React, { useState } from 'react';

const Counter = () => {
  const [count, setCount] = useState({ value: 0 });

  const increment = () => {
    count.value = count.value + 1;
    setCount(count);
  };

  return (
    <div>
      <p>Count: {count.value}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;

Варіант 2: 
import React, { useState } from 'react';

const Counter = () => {
  const [count, setCount] = useState({ value: 0 });

  const increment = () => {
    setCount({ value: count.value + 1 });
  };

  return (
    <div>
      <p>Count: {count.value}</p>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;
