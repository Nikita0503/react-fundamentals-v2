Why Named Types?

When objects get complex, inline type annotations become unreadable. Imagine typing { id: number; name: string; email: string; isActive: boolean } every time you use a user object. The solution: named types — you define the shape once and reuse it by name.

TypeScript gives you two ways to create named types: type and interface.

type — A Type Alias

A type alias gives a name to any type. You define it once, then use the name everywhere:

type User = {
  id: number;
  name: string;
  email: string;
  isActive: boolean;
};

const user: User = { id: 1, name: "Alice", email: "alice@test.com", isActive: true };

type can describe ANY type — not just objects:

type Status = "idle" | "loading" | "success" | "error";  // union of literal values
type Point = [number, number];                             // tuple (fixed-length array)
type Callback = (value: string) => void;                   // function signature

interface — Describes the Shape of an Object

An interface is another way to describe object shapes. The syntax is slightly different (no = sign):

interface User {
  id: number;
  name: string;
  email: string;
  isActive: boolean;
}

const user: User = { id: 1, name: "Alice", email: "alice@test.com", isActive: true };

Extending / Combining Types

Both type and interface let you build new types from existing ones:

// interface extends interface
interface Animal { name: string; }
interface Dog extends Animal { breed: string; }

// type intersection (combining with &)
type Animal = { name: string };
type Dog = Animal & { breed: string };

// Both result in: { name: string; breed: string }

Optional Properties

Add ? after a property name to make it optional — it may or may not be present:

type User = {
  id: number;
  name: string;
  email?: string;  // optional — type is string | undefined
};

const user: User = { id: 1, name: "Alice" }; // ✅ valid — email is optional

Readonly Properties

Mark properties as readonly to prevent reassignment after creation:

type Config = {
  readonly apiUrl: string;
  readonly timeout: number;
};

const config: Config = { apiUrl: "https://api.example.com", timeout: 5000 };
config.apiUrl = "other"; // ❌ Error: Cannot assign to 'apiUrl' because it is a read-only property

type vs interface — When to Use Which

Featuretypeinterface
Objects✅✅
Unions (A | B)✅❌
Tuples✅❌
Extending& intersectionextends keyword
Declaration merging❌✅ (same name = merged)
Function types✅✅ (but type is cleaner)

Practical advice: pick one style for your project and be consistent. Both work. Many teams use type for everything (simpler, more flexible). Some prefer interface for object shapes. Either is fine — consistency matters more than the choice itself.
