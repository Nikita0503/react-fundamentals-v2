Primitive Types

Primitives are the most basic building blocks of data. TypeScript has three main primitive types that you'll use constantly:

const name: string = "Alice";
const age: number = 25;
const isActive: boolean = true;

The syntax is: variableName: type = value. The part after the colon (: string) is the type annotation — it tells TypeScript what kind of value this variable holds.

Type Inference

Type inference means TypeScript is smart enough to figure out types automatically based on the value you assign:

const name = "Alice";     // TS infers: string
const age = 25;           // TS infers: number
const isActive = true;    // TS infers: boolean

// You DON'T need to write types when TS can infer them!
// Only add explicit types when inference isn't enough.

This is important — you don't need to annotate everything. Let TypeScript do the work when it can. Your code stays cleaner and less verbose.

Arrays

An array type is written as the element type followed by []:

const names: string[] = ["Alice", "Bob", "Charlie"];
const scores: number[] = [95, 87, 92];
const flags: boolean[] = [true, false, true];

Objects

You can describe the shape of an object inline — listing each property and its type:

const user: { name: string; age: number; email: string } = {
  name: "Alice",
  age: 25,
  email: "alice@example.com",
};

Function Types

Functions need types for their parameters (inputs) and optionally their return value (output):

// Parameters must be typed. Return type is usually inferred.
function add(a: number, b: number): number {
  return a + b;
}

// Arrow function
const multiply = (a: number, b: number): number => a * b;

// Function that returns nothing (void = "no return value")
const logMessage = (message: string): void => {
  console.log(message);
};

Special Types

TypeScript has several special types for specific situations:

TypeMeaningUse when
anyDisables type checking entirelyAVOID — defeats the purpose of TS

nullIntentionally emptyValue explicitly set to "nothing"
undefinedNot yet assignedVariable declared but not initialized
neverFunction never returns (throws or infinite loop)Rare — error functions

any vs unknown

Both represent "could be anything" — but they behave very differently:

// any — no checking (dangerous!)
const data: any = fetchSomething();
data.whatever(); // TS doesn't complain, but might crash at runtime

// unknown — must check before using (safe)
const data: unknown = fetchSomething();
data.whatever(); // ❌ Error: Object is of type 'unknown'

if (typeof data === "string") {
  data.toUpperCase(); // ✅ Now TS knows it's a string
}

Rule of thumb: if you're tempted to use any, use unknown instead and add a type check.

When to Add Explicit Types vs Rely on Inference

  • Let TS infer: variable assignments, return types of simple functions
  • Add explicitly: function parameters (always!), complex objects, when inference gives the wrong type
