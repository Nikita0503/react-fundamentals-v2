TypeScript + React Overview

This file connects everything you've learned to React. These patterns appear throughout the rest of the course. The goal here is to recognize the syntax so nothing looks unfamiliar when you encounter it later.

Typing Component Props

Every React component receives data through props. You define a type for those props and use it in the function parameter:

type ButtonProps = {
  label: string;
  onClick: () => void;
  variant?: "primary" | "secondary";
  disabled?: boolean;
};

const Button = ({ label, onClick, variant = "primary", disabled = false }: ButtonProps) => (
  <button className={`btn-${variant}`} onClick={onClick} disabled={disabled}>
    {label}
  </button>
);

The props type acts as a contract: anyone using <Button /> knows exactly what it accepts. TypeScript will error if required props are missing or wrong types are passed.

Typing useState

useState is a React hook that holds a value that can change over time. TypeScript usually infers the type from the initial value:

// Inferred — no generic needed
const [count, setCount] = useState(0);           // number
const [name, setName] = useState("");            // string

// Explicit generic — when initial value doesn't reveal full type
const [user, setUser] = useState<User | null>(null);
const [items, setItems] = useState<string[]>([]);
const [status, setStatus] = useState<"idle" | "loading" | "error">("idle");

You need the generic (<User | null>) when the initial value is null or an empty array — because TypeScript can't infer the full type from those alone.

Typing Events

React provides typed event objects. The pattern is React.{EventType}Event<HTMLElementType>:

const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  console.log(e.target.value);
};

const handleClick = (e: React.MouseEvent<HTMLButtonElement>) => {
  e.preventDefault();
};

const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
  e.preventDefault();
};

The first part is the event type (Change, Mouse, Form, Keyboard, etc.) and the generic is the HTML element it's attached to.

Typing Children

When a component wraps other content (like a layout), use ReactNode for the children prop — it accepts any renderable content (strings, numbers, elements, arrays, fragments):

import { ReactNode } from "react";

type LayoutProps = {
  children: ReactNode;  // accepts any renderable content
};

const Layout = ({ children }: LayoutProps) => (
  <div className="layout">{children}</div>
);

Typing Refs

Refs give you direct access to DOM elements. The generic tells TypeScript what kind of element the ref points to:

import { useRef } from "react";

const inputRef = useRef<HTMLInputElement>(null);
const divRef = useRef<HTMLDivElement>(null);
const timerRef = useRef<ReturnType<typeof setInterval> | null>(null);

Typing Context

React Context lets you share data across components without passing props manually. You type the context value:

import { createContext, useContext } from "react";

type ThemeContextValue = {
  theme: "light" | "dark";
  toggleTheme: () => void;
};

const ThemeContext = createContext<ThemeContextValue | undefined>(undefined);

Typing Callback Props

Components often receive functions as props (callbacks). Type them with arrow function syntax:

type TodoItemProps = {
  id: number;
  text: string;
  onDelete: (id: number) => void;        // function with argument
  onToggle: () => void;                   // function without arguments
  onChange: (value: string) => void;      // function with string argument
};

The pattern is: (parameterName: parameterType) => returnType. Most callbacks return void (they do something but don't return a value).
