The Problem

Imagine you want to write a function that returns the first element of an array. Without generics, you'd need a separate function for each type:

// Without generics — you'd need a separate function for each type:
function firstString(arr: string[]): string | undefined { return arr[0]; }
function firstNumber(arr: number[]): number | undefined { return arr[0]; }
// ... this doesn't scale

The logic is identical — only the types differ. Generics solve this problem.

Generics — Type Parameters

A generic is a type parameter — a placeholder for a type that gets filled in when you use the function or type. Think of it like a function parameter, but for types:

// One function that works with ANY type
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

first<string>(["a", "b", "c"]); // returns string
first<number>([1, 2, 3]);       // returns number
first([true, false]);            // TS infers T = boolean automatically

<T> is the type parameter — a placeholder that gets filled in when you call the function. By convention, single uppercase letters are used: T (Type), K (Key), V (Value), E (Element) — but any name works.

Generic Types

You can also make types generic — creating reusable type templates:

// A reusable API response wrapper
type ApiResponse<T> = {
  data: T;
  error: string | null;
  loading: boolean;
};

// Use with different data types:
type UserResponse = ApiResponse<User>;       // { data: User; error: ...; loading: ... }
type PostsResponse = ApiResponse<Post[]>;    // { data: Post[]; error: ...; loading: ... }

You define the shape once, and the T placeholder gets replaced with whatever type you pass in.

Constraints — Limiting What T Can Be

Sometimes you need T to have certain properties. Use extends to add a constraint:

// T must have an 'id' property
function findById<T extends { id: number }>(items: T[], id: number): T | undefined {
  return items.find(item => item.id === id);
}

findById([{ id: 1, name: "Alice" }], 1); // ✅ has 'id' property
findById([{ title: "Post" }], 1);         // ❌ Error: missing 'id' property

T extends { id: number } means "T can be any type, as long as it has at least an id property of type number."

Multiple Type Parameters

You can have more than one type parameter:

function merge<A, B>(obj1: A, obj2: B): A & B {
  return { ...obj1, ...obj2 };
}

const result = merge({ name: "Alice" }, { age: 25 });
// result type: { name: string } & { age: number }

Default Type Parameters

You can provide a default type that's used when no type argument is specified:

type Container<T = string> = {
  value: T;
};

const strContainer: Container = { value: "hello" };       // T defaults to string
const numContainer: Container<number> = { value: 42 };    // T is number

Where You'll See Generics in React

You don't need to master generics to use React — but you'll encounter the <T> syntax constantly:

useState<User | null>(null);           // generic hook — T is the state type
useRef<HTMLInputElement>(null);         // generic hook — T is the element type
createContext<ThemeContextValue>();     // generic function
Array<Todo>                            // generic type (same as Todo[])
Promise<User>                          // generic type — resolves to User

Understanding the <T> syntax lets you read library types and write typed hooks. You'll get comfortable with it naturally as you use React with TypeScript.
