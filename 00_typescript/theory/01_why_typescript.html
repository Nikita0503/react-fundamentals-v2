What is TypeScript?

TypeScript is a programming language built on top of JavaScript. It's called a "superset" — which means all valid JavaScript code is also valid TypeScript code. TypeScript adds one major feature on top: a type system.

A type system lets you describe what shape your data has (is this a number? a string? an object with specific fields?) — and the TypeScript compiler checks that you're using data correctly before your code ever runs.

TypeScript code lives in .ts and .tsx files. It gets compiled (translated) into regular JavaScript (.js) — because browsers and Node.js don't understand TypeScript directly. They only run JavaScript.

In React projects using Vite or Webpack, this compilation happens automatically — you just write .tsx files and the build tool handles the rest.

Why TypeScript?

1. Catches bugs before you run the code:

// JavaScript — this crashes at RUNTIME (in the browser)
function greet(user) {
  return "Hello, " + user.name.toUpperCase();
}
greet(null); // 💥 TypeError: Cannot read properties of null

// TypeScript — this is caught at COMPILE TIME (in your editor, before you even save)
function greet(user: { name: string }) {
  return "Hello, " + user.name.toUpperCase();
}
greet(null); // ❌ Error: Argument of type 'null' is not assignable

2. Autocomplete and IntelliSense — your editor knows what properties and methods are available on every variable. No more guessing or checking documentation.

3. Self-documenting code — types describe what a function expects and returns. You can understand a function's contract without reading its implementation.

4. Safe refactoring — rename a property and TypeScript shows every place in your codebase that needs updating. No more "find and replace" and hoping you didn't miss one.

5. Team collaboration — types act as a contract between developers. "This function expects X and returns Y" — no ambiguity, no surprises.

How It Works (Simplified)

  1. You write TypeScript code (.ts / .tsx)
  2. The TypeScript compiler checks for type errors
  3. If no errors → compiles to JavaScript
  4. JavaScript runs in the browser

In React projects with Vite: this all happens automatically when you run npm run dev. You write TypeScript, Vite compiles it, and the browser gets JavaScript.

TypeScript is NOT

  • A different language from JavaScript — it's JavaScript WITH types added on top
  • Required at runtime — types are completely erased during compilation. The JavaScript that runs in the browser has zero TypeScript in it. This means zero runtime performance cost.
  • All-or-nothing — you can gradually add types to an existing JavaScript project. You don't have to convert everything at once.
