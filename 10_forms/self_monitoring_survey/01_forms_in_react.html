What drives the value of a controlled input in React?


( ) The DOM manages the value internally, and React reads it via a ref. (x) React state drives the value, and an onChange handler updates the state on every change. ( ) The browser's default form behavior manages the value automatically. ( ) A third-party library always manages the value in controlled components.

How does an uncontrolled component store its input value?


( ) In a useState hook that re-renders the component on every keystroke. ( ) In a global state management library like Redux. (x) In the DOM itself, accessed via a ref when needed (e.g., on form submission). ( ) In the component's props passed from the parent.

What are the main problems with manual form handling using useState at scale?


( ) useState cannot store string values, only numbers and booleans. (x) You need separate state for each field (or a large object), manual validation, manual error tracking, manual touched/dirty tracking, and every keystroke causes a re-render. ( ) useState only works with uncontrolled components and cannot drive input values. ( ) The only problem is that useState is deprecated in modern React.
