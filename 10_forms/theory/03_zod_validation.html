Zod Validation

Schema-based validation means defining your validation rules as a standalone schema object, separate from your UI components. This approach gives you:

  • Separation of concerns — validation logic is not mixed with rendering logic.
  • Reusability — the same schema can validate forms, API responses, environment variables, etc.
  • Composability — schemas can be extended, merged, picked, and omitted.
  • Type safety — TypeScript types are derived directly from the schema (single source of truth).
  • Testability — schemas can be unit-tested independently of any component.

What is Zod?

Zod is a TypeScript-first schema validation library. It lets you define a schema that describes the shape and constraints of your data, then validate any value against that schema at runtime. If validation fails, Zod provides detailed, structured error messages.

Installation

npm install zod @hookform/resolvers

Basic Zod Schema

import { z } from "zod";

const contactSchema = z.object({
  name: z.string().min(1, "Name is required"),
  email: z.string().email("Invalid email address"),
  message: z.string().min(10, "Message must be at least 10 characters"),
});

// Derive the TypeScript type FROM the schema
type ContactForm = z.infer<typeof contactSchema>;

The key point here is z.infer<typeof schema> — it derives the TypeScript type directly from the schema. This means you define your data shape once (in the schema) and get both runtime validation and compile-time type checking from the same source. No duplication, no drift.

Connecting Zod to React Hook Form

The @hookform/resolvers package provides adapters that connect schema libraries (Zod, Yup, Joi, etc.) to React Hook Form. For Zod, you use zodResolver:

import { useForm } from "react-hook-form";
import { zodResolver } from "@hookform/resolvers/zod";
import { z } from "zod";

const contactSchema = z.object({
  name: z.string().min(1, "Name is required"),
  email: z.string().email("Invalid email address"),
  message: z.string().min(10, "Message must be at least 10 characters"),
});

type ContactForm = z.infer<typeof contactSchema>;

const ContactPage = () => {
  const {
    register,
    handleSubmit,
    formState: { errors },
  } = useForm<ContactForm>({
    resolver: zodResolver(contactSchema),
  });

  const onSubmit = (data: ContactForm) => {
    console.log(data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register("name")} placeholder="Name" />
      {errors.name && <span>{errors.name.message}</span>}

      <input {...register("email")} placeholder="Email" />
      {errors.email && <span>{errors.email.message}</span>}

      <textarea {...register("message")} placeholder="Message" />
      {errors.message && <span>{errors.message.message}</span>}

      <button type="submit">Submit</button>
    </form>
  );
};

Notice that with Zod, you no longer pass validation rules to register(). All validation is defined in the schema and applied automatically through the resolver.

Benefits of Schema-Based Validation

  • Validation logic is testable independently — you can write unit tests for your schema without rendering any component.
  • Types are auto-derived — z.infer eliminates the need to manually define and maintain a separate TypeScript type.
  • Schemas are composable — use .extend(), .merge(), .pick(), and .omit() to build new schemas from existing ones.
// Composing schemas
const baseUserSchema = z.object({
  name: z.string().min(1),
  email: z.string().email(),
});

// Extend with additional fields
const registrationSchema = baseUserSchema.extend({
  password: z.string().min(8, "Password must be at least 8 characters"),
  confirmPassword: z.string(),
}).refine((data) => data.password === data.confirmPassword, {
  message: "Passwords don't match",
  path: ["confirmPassword"],
});

// Pick only certain fields
const loginSchema = baseUserSchema.pick({ email: true }).extend({
  password: z.string().min(1, "Password is required"),
});

Common Zod Methods

Here are the most commonly used Zod methods for form validation:

  • z.string() — validates that the value is a string
  • z.number() — validates that the value is a number
  • z.boolean() — validates that the value is a boolean
  • z.enum(["a", "b", "c"]) — validates that the value is one of the specified options
  • z.array(z.string()) — validates an array of a given type
  • z.optional() — makes a field optional (value can be undefined)
  • z.nullable() — allows null as a value
  • .min(n) / .max(n) — minimum/maximum length (strings) or value (numbers)
  • .email() — validates email format
  • .url() — validates URL format
  • .regex(pattern) — validates against a regular expression
const profileSchema = z.object({
  username: z.string().min(3).max(20),
  age: z.number().min(18).max(120),
  website: z.string().url().optional(),
  role: z.enum(["admin", "user", "moderator"]),
  tags: z.array(z.string()).min(1, "At least one tag required"),
  bio: z.string().nullable(),
});
