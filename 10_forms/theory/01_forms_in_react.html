Forms in React

Forms are a fundamental part of any web application. They allow users to input data, validate it, and submit it for processing. In React, handling forms requires a deliberate approach because React manages the UI through state and rendering cycles.

There are two main approaches to handling form inputs in React:

Controlled Components

In a controlled component, the input's value is driven by React state. Every change to the input triggers a state update via an onChange handler, and React re-renders the component with the new value. The React state is the "single source of truth" for the input.

import { useState } from "react";

const ControlledInput = () => {
  const [name, setName] = useState("");

  return (
    <input
      value={name}
      onChange={(e) => setName(e.target.value)}
      placeholder="Enter name"
    />
  );
};

Uncontrolled Components

In an uncontrolled component, the input's value lives in the DOM itself. You access the current value via a ref when you need it (e.g., on form submission). React does not track every keystroke.

import { useRef } from "react";

const UncontrolledInput = () => {
  const inputRef = useRef<HTMLInputElement>(null);

  const handleSubmit = () => {
    console.log(inputRef.current?.value);
  };

  return (
    <>
      <input ref={inputRef} placeholder="Enter name" />
      <button onClick={handleSubmit}>Submit</button>
    </>
  );
};

Controlled Form Example

Here is a simple controlled form with two fields — name and email — using useState and manual onChange handlers:

import { useState, FormEvent } from "react";

type FormData = {
  name: string;
  email: string;
};

const SimpleForm = () => {
  const [formData, setFormData] = useState<FormData>({ name: "", email: "" });
  const [errors, setErrors] = useState<Partial<FormData>>({});

  const validate = (): boolean => {
    const newErrors: Partial<FormData> = {};
    if (!formData.name) newErrors.name = "Name is required";
    if (!formData.email) newErrors.email = "Email is required";
    else if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(formData.email)) {
      newErrors.email = "Invalid email";
    }
    setErrors(newErrors);
    return Object.keys(newErrors).length === 0;
  };

  const handleSubmit = (e: FormEvent) => {
    e.preventDefault();
    if (validate()) {
      console.log("Submitted:", formData);
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={formData.name}
        onChange={(e) => setFormData({ ...formData, name: e.target.value })}
        placeholder="Name"
      />
      {errors.name && <span>{errors.name}</span>}

      <input
        value={formData.email}
        onChange={(e) => setFormData({ ...formData, email: e.target.value })}
        placeholder="Email"
      />
      {errors.email && <span>{errors.email}</span>}

      <button type="submit">Submit</button>
    </form>
  );
};

Problems with Manual Form Handling at Scale

The approach above works fine for simple forms with 1–2 fields. However, as forms grow in complexity, you quickly run into problems:

  • One useState per field (or one large state object) — managing many fields becomes tedious and error-prone.
  • Manual validation logic — writing validation rules inline clutters the component and is hard to reuse.
  • Manual error state tracking — you need a separate state object for errors and logic to clear them at the right time.
  • Manual touched/dirty tracking — knowing which fields the user has interacted with requires even more state.
  • Re-renders on every keystroke — controlled components trigger a re-render for every character typed, which can cause performance issues in large forms.

Conclusion

For simple forms with 1–2 fields, manual state management with useState is perfectly fine. But for complex forms with many fields, nested data, dynamic lists, and advanced validation — use a form library. It will handle state, validation, error tracking, and performance for you.
