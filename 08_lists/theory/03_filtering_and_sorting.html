Filtering and Sorting

In real applications, lists are almost always filtered and/or sorted before rendering. The key principle: derive the displayed list from the source data — don't store filtered results in separate state.

Filtering

Use useMemo to compute filtered results only when the source data or filter criteria change:

import { useState, useMemo } from "react";

type Product = { id: number; name: string; category: string; price: number };

const ProductList = ({ products }: { products: Product[] }) => {
  const [search, setSearch] = useState("");
  const [category, setCategory] = useState<string>("all");

  const filteredProducts = useMemo(() => {
    return products
      .filter(p => category === "all" || p.category === category)
      .filter(p => p.name.toLowerCase().includes(search.toLowerCase()));
  }, [products, category, search]);

  return (
    <div>
      <input
        value={search}
        onChange={e => setSearch(e.target.value)}
        placeholder="Search products..."
      />
      <select value={category} onChange={e => setCategory(e.target.value)}>
        <option value="all">All categories</option>
        <option value="electronics">Electronics</option>
        <option value="clothing">Clothing</option>
      </select>

      {filteredProducts.length === 0 ? (
        <p>No products match your filters.</p>
      ) : (
        <ul>
          {filteredProducts.map(p => (
            <li key={p.id}>{p.name} — ${p.price}</li>
          ))}
        </ul>
      )}

      <p>{filteredProducts.length} of {products.length} products shown</p>
    </div>
  );
};

Sorting

Sorting follows the same derived-data pattern. Important: always spread before sorting ([...arr].sort(...)) because .sort() mutates the original array!

type SortField = "name" | "price";
type SortDirection = "asc" | "desc";

const [sortBy, setSortBy] = useState<SortField>("name");
const [sortDir, setSortDir] = useState<SortDirection>("asc");

const sortedProducts = useMemo(() => {
  return [...filteredProducts].sort((a, b) => {
    const modifier = sortDir === "asc" ? 1 : -1;
    if (sortBy === "price") return (a.price - b.price) * modifier;
    return a.name.localeCompare(b.name) * modifier;
  });
}, [filteredProducts, sortBy, sortDir]);

Why useMemo Here

  • Filtering/sorting can be expensive for large lists (1000+ items)
  • Without useMemo: recalculates on every render (even unrelated state changes)
  • With useMemo: only recalculates when source data or filter/sort criteria change
  • For small lists (<100 items): useMemo is optional — computation is fast enough

Common Pattern: filter → sort → map

type Item = { id: number; name: string; price: number; active: boolean };

const ItemList = ({ items }: { items: Item[] }) => {
  const [filterCriteria, setFilterCriteria] = useState("");
  const [sortCriteria, setSortCriteria] = useState<"name" | "price">("name");

  const displayedItems = useMemo(() => {
    return items
      .filter(item => item.name.toLowerCase().includes(filterCriteria.toLowerCase()))
      .sort((a, b) => a[sortCriteria] > b[sortCriteria] ? 1 : -1);
  }, [items, filterCriteria, sortCriteria]);

  return (
    <ul>
      {displayedItems.map(item => (
        <li key={item.id}>{item.name} — ${item.price}</li>
      ))}
    </ul>
  );
};

Don't Store Derived Data in State

A common mistake is storing filtered results in a separate useState and syncing them with useEffect. This creates unnecessary complexity and potential bugs:

// ❌ Wrong — storing filtered results in separate state
const [products, setProducts] = useState<Product[]>([]);
const [filteredProducts, setFilteredProducts] = useState<Product[]>([]);
useEffect(() => {
  setFilteredProducts(products.filter(p => p.name.includes(search)));
}, [products, search]);

// ✅ Right — derive during render (or with useMemo)
const [products, setProducts] = useState<Product[]>([]);
const filteredProducts = useMemo(
  () => products.filter(p => p.name.includes(search)),
  [products, search]
);

The correct approach computes the filtered list directly from the source data. This eliminates the possibility of the filtered list getting out of sync with the source data.
