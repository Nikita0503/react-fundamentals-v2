Rendering Lists

React provides the ability to work with lists using internal optimized mechanisms.

Here is an example of using a functional component ListComponent with useState to store an initial data list:

import React, { useState } from 'react';

type Item = {
  id: number;
  text: string;
};

const ListComponent = () => {
  const [items, setItems] = useState<Item[]>([
    { id: 1, text: 'Item 1' },
    { id: 2, text: 'Item 2' },
    { id: 3, text: 'Item 3' }
  ]);

  return (
    <ul>
      {items.map(item => (
        <li key={item.id}>{item.text}</li>
      ))}
    </ul>
  );
};

export default ListComponent;

In this example, we use the useState hook to create the items state, which contains an initial data list of three elements. We use the array method map() to iterate over the items list and create <li> elements for each list item, and we also use the key attribute for unique identification of each element.

Essentially, in JSX (in the markup) we use a JavaScript expression where the data array items is transformed into an array of <li> list elements using the .map array method.

It is important to note that we also use the key attribute in the <li> element. The key attribute is needed by React for unique identification of each list element. This helps React optimize the re-rendering process of list elements and ensures correct behavior of React components that have internal state or use certain performance optimizations.

A very popular exercise is creating a task list (todo list), where each task has fields: id, title (task name), completed (task status, done / not done). Additionally — providing the ability to change the task status, i.e., the completed field to true or false. This exercise teaches working with lists where data changes when interacting with the same list.

Here is an example of a simple todo list using functional components, useState hooks, and map for rendering the list and changing the completed state:

import React, { useState } from 'react';

type Todo = {
  id: number;
  title: string;
  completed: boolean;
};

const TodoList = () => {
  const [todos, setTodos] = useState<Todo[]>([
    { id: 1, title: 'Task 1', completed: false },
    { id: 2, title: 'Task 2', completed: true },
    { id: 3, title: 'Task 3', completed: false }
  ]);

  const handleToggle = (id: number) => {
    setTodos(todos.map(todo => {
      if (todo.id === id) {
        return { ...todo, completed: !todo.completed };
      }
      return todo;
    }));
  };

  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          <input
            type="checkbox"
            checked={todo.completed}
            onChange={() => handleToggle(todo.id)}
          />
          <span style={{ textDecoration: todo.completed ? 'line-through' : 'none' }}>
            {todo.title}
          </span>
        </li>
      ))}
    </ul>
  );
};

export default TodoList;

In this example, we use the useState hook to store the list of todo items in the todos state.

Each todo item has properties id, title, and completed, which are used for display on the page and for changing the completed state during user interaction.

We also use the array method map() to create list elements and handle the onChange event to track changes in the completed state using the handleToggle function, which updates the todos state using the setTodos function and uses the spread operator (...) to create a new todo object with the updated completed property.

The map array method provides the index of the current array element as the second parameter in the callback, but we still use the id field of each task. Here are several reasons why you should avoid using the index as a key:

  • Potential loss of efficiency: Using the index as a key can lead to unplanned re-renders and loss of efficiency. When new elements are added, removed, or changed in the list, React may re-render all list elements, even if changes occur in only one element. This can lead to unnecessary component updates, increased load on the web page, and degraded performance.
  • Possibility of errors: Array indices can be unstable, especially when list elements are added, removed, or changed. This can lead to errors in displaying components, interacting with them, or storing state.
  • Lack of uniqueness: Array indices do not guarantee uniqueness for each list element. This can cause problems when interacting with a list that contains multiple elements with the same indices. Instead of using the index as a key, it is recommended to use unique identifiers (for example, id) for each list element as the key attribute. This allows React to efficiently track changes in the list and ensures rendering stability.
