Відображення списків

React дає можливість працювати зі списками, використовуючи внутрішні оптимізовані механізми.

Ось приклад використання функціонального компонента ListComponent з використанням useState для зберігання початкового списку даних:

import React, { useState } from 'react';

const ListComponent = () => {
  const [items, setItems] = useState([
    { id: 1, text: 'Елемент 1' },
    { id: 2, text: 'Елемент 2' },
    { id: 3, text: 'Елемент 3' }
  ]);

  return (
    <ul>
      {items.map(item => (
        <li key={item.id}>{item.text}</li>
      ))}
    </ul>
  );
};

export default ListComponent;

У цьому прикладі ми використовуємо хук useState для створення стану items, який містить початковий список даних з трьох елементів. Ми використовуємо метод масиву map() для ітерації по списку items і створення елементів <li> для кожного елементу списку, а також використовуємо атрибут key для унікальної ідентифікації кожного елементу.

По-суті, в JSX (в розмітці) ми використовуємо вираз javascript, де масив даних items, перетворємо на масив елементів списку <li> за домогою .map методу списку.

Важливо зауважити, що ми також використовуємо атрибут key в елементі <li>. Атрибут key потрібен React для унікальної ідентифікації кожного елементу списку. Це допомагає React оптимізувати процес перерендерування елементів списку та забезпечує правильну роботу React-компонентів, які мають внутрішній стан або використовують певні оптимізації продуктивності.

Дуже популярною вправа - створення списку задач (todo list), де кожна задача має поля: id, title (ім`я задачі), completed (статус задачі, винонано / не виконано). Та додатково - дати можливість змінювати стасус задачі, тобто поле completed на true або false. Ця вправа вчить працювати зі списками, в яких данні змінюються при взаємодії з цим же списком.

Ось приклад простого todo-списку з використанням функціональних компонентів, хуків useState та map для рендерингу списку та зміни стану completed:

import React, { useState } from 'react';

const TodoList = () => {
  const [todos, setTodos] = useState([
    { id: 1, title: 'Завдання 1', completed: false },
    { id: 2, title: 'Завдання 2', completed: true },
    { id: 3, title: 'Завдання 3', completed: false }
  ]);

  const handleToggle = (id) => {
    setTodos(todos.map(todo => {
      if (todo.id === id) {
        return { ...todo, completed: !todo.completed };
      }
      return todo;
    }));
  };

  return (
    <ul>
      {todos.map((todo, index) => (
        <li key={todo.id}>
          <input
            type="checkbox"
            checked={todo.completed}
            onChange={() => handleToggle(todo.id)}
          />
          <span style={{ textDecoration: todo.completed ? 'line-through' : 'none' }}>
            {todo.title}
          </span>
        </li>
      ))}
    </ul>
  );
};

export default TodoList;

У цьому прикладі ми використовуємо хук useState для зберігання списку todo-елементів у стані todos.

Кожен todo-елемент має властивості id, title та completed, які використовуються для відображення на сторінці та для зміни стану completed під час взаємодії користувача.

Ми також використовуємо метод масиву map() для створення елементів списку та обробки події onChange для відстеження змін у стані completed за допомогою функції handleToggle, яка оновлює стан todos за допомогою функції setTodos та використовує оператор розширення (...) для створення нового об'єкта todo з оновленою властивістю completed.

Метод списку map, другим параметром у колбеку надає індекс поточного елементу масиву, але ми всеодно використовуємо поле id кожної задачі. Ось декілька причин, чому варто уникати використання індексу як ключа:

  • Потенційна втрата ефективності: Використання індексу як ключа може призвести до незапланованих перерендерів та втрати ефективності. Коли нові елементи додаються, видаляються або змінюються в списку, React може перерендерювати всі елементи списку, навіть якщо зміни відбуваються тільки в одному елементі. Це може призвести до непотрібного оновлення компонентів, збільшення навантаження на веб-сторінку та погіршення продуктивності.
  • Можливість виникнення помилок: Індекси масиву можуть бути нестабільними, особливо коли елементи списку додаються, видаляються або змінюються. Це може призвести до помилок у відображенні компонентів, взаємодії з ними або зберіганні стану.
  • Відсутність унікальності: Індекси масиву не гарантують унікальності в кожному елементі списку. Це може викликати проблеми при взаємодії зі списком, який містить декілька елементів з однаковими індексами. Замість використання індексу як ключа рекомендується використовувати унікальні ідентифікатори (наприклад, id) для кожного елемента списку як атрибут key. Це дозволяє React ефективно відслідковувати зміни в списку, забезпечує стабільність рендерингу.
