Як правильно використовувати атрибут key при рендерингу списку в React?


( ) Використання індексу масиву як атрибут key є обов`язковим. (x) Атрибут key потрібно використовувати для унікальної ідентифікації кожного елементу списку, щоб допомогти React оптимізувати перерендер компонентів та забезпечити стабільність рендерингу. ( ) React автоматично вирішує проблеми з рендерингом списків, і використання атрибута key не є обов'язковим.

Які проблеми можуть виникнути при використанні індексу масиву як ключа в React?


( ) Використання індексу масиву надає додаткові переваги та полегшує роботу з React-компонентами. ( ) React автоматично вирішує всі проблеми, пов'язані з використанням індексу як ключа, тому його використання є безпечним. (x) Індекси масиву можуть бути нестабільними, особливо при додаванні або видаленні елементів, що може викликати помилки та неправильне відображення компонентів.

Який метод масиву рекомендується використовувати для відображення списків в React?


( ) Метод forEach, оскільки він дозволяє ітерувати по елементах масиву і легко взаємодіяти з React-компонентами. ( ) Метод filter, оскільки він дозволяє відфільтрувати елементи масиву за певною умовою перед їх відображенням в компоненті. (x) Метод map, оскільки він дозволяє трансформувати кожен елемент масиву в React-елемент і створює новий масив React-елементів для відображення.

Чому в атрибуті key для React-елементів важливо мати унікальні значення?


( ) Унікальність атрибуту key впливає лише на зовнішній вигляд React-компонентів, тому можна використовувати неуникальні значення key, якщо це не важливо для відображення.
(x) Унікальні значення key допомагають React ідентифікувати кожен елемент масиву, забезпечуючи ефективний процес оновлення і відображення.
( ) Унікальність атрибуту key важлива лише для естетичного вигляду коду і не впливає на функціональність React-компонентів.
