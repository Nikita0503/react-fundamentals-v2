The Problem

If a component throws an error during rendering, the entire React app crashes — you get a white screen. There's no graceful degradation. One broken component takes down everything.

What is an Error Boundary?

An Error Boundary is a component that catches JavaScript errors anywhere in its child component tree and displays a fallback UI instead of crashing the whole app. Think of it as a try/catch, but for React rendering.

Why It Requires a Class Component

Error Boundaries use two lifecycle methods that don't have hook equivalents (as of React 19):

  • static getDerivedStateFromError(error) — called when a child throws during render. Used to update state so the next render shows a fallback UI.
  • componentDidCatch(error, errorInfo) — called after an error is caught. Used to log the error to an external service (Sentry, Datadog, etc.).

This is the only remaining use case for class components in modern React. Everything else can (and should) be done with function components and hooks.

Implementation

import { Component, ReactNode } from "react";

type Props = {
  children: ReactNode;
  fallback?: ReactNode;
};

type State = {
  hasError: boolean;
};

class ErrorBoundary extends Component<Props, State> {
  state: State = { hasError: false };

  static getDerivedStateFromError(): State {
    return { hasError: true };
  }

  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    console.error("Error caught by boundary:", error, errorInfo);
    // In production: send to error tracking service (Sentry, Datadog)
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback ?? <h2>Something went wrong.</h2>;
    }
    return this.props.children;
  }
}

export { ErrorBoundary };

Usage

<ErrorBoundary fallback={<p>This section failed to load.</p>}>
  <UserProfile />
</ErrorBoundary>

If UserProfile throws during render → the fallback shows. The rest of the app keeps working normally.

The react-error-boundary Library — What Real Projects Use

In practice, you don't write the class yourself. The react-error-boundary library provides a battle-tested implementation with extra features:

npm install react-error-boundary
import { ErrorBoundary } from "react-error-boundary";

const ErrorFallback = ({ error, resetErrorBoundary }: { error: Error; resetErrorBoundary: () => void }) => (
  <div>
    <p>Something went wrong: {error.message}</p>
    <button onClick={resetErrorBoundary}>Try again</button>
  </div>
);

const App = () => (
  <ErrorBoundary FallbackComponent={ErrorFallback}>
    <Dashboard />
  </ErrorBoundary>
);

What it provides over a manual implementation:

  • Reset functionality — user can retry without refreshing the page
  • onError callback — for logging without writing componentDidCatch
  • Functional API — no class component in your code

Where to Place Error Boundaries

  • Around route-level components — each page gets its own boundary, so one page crashing doesn't kill the whole app
  • Around risky/third-party components — libraries you don't control might throw
  • Around independent sections (sidebar, widget) — so one crash doesn't kill the whole page
  • NOT around every single component — too granular, adds complexity without benefit

What Error Boundaries DON'T Catch

  • Event handlers — use regular try/catch inside the handler
  • Async code — promises, setTimeout callbacks
  • Errors in the boundary itself — if the boundary throws, it can't catch its own error
