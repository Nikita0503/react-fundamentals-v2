The Problem — Large Bundles

By default, your entire React app is bundled into one (or a few) JavaScript files. This means users download ALL code upfront — even pages they may never visit. A large bundle means a slow initial load, especially on mobile networks.

Code Splitting — The Solution

"Code splitting" means breaking your app into smaller chunks (separate JS files) that load on demand. When a user visits /dashboard, only the dashboard code loads. If they never visit /settings, that code never downloads. The bundler (Webpack, Vite) handles creating these chunks automatically.

React.lazy() — Dynamically Import a Component

lazy() lets you define a component that loads its code only when it's first rendered. Until then, the code is not downloaded to the user's browser (it stays in the bundled files on the hosting server, waiting to be requested).

import { lazy } from "react";

// Instead of: import { Dashboard } from "./pages/Dashboard";
// Lazy: loads only when the component is first rendered
const Dashboard = lazy(() => import("./pages/Dashboard"));
const Settings = lazy(() => import("./pages/Settings"));
const Analytics = lazy(() => import("./pages/Analytics"));
  • lazy() takes a function that returns a dynamic import() — this is a JavaScript feature that loads a module asynchronously
  • The component is loaded from the server only when it's first rendered in the UI
  • The file must have a default export — lazy() expects it

Suspense — Show a Loading State While Lazy Component Loads

Since lazy components load asynchronously, React needs to show something while the code downloads. That's what <Suspense> does — it wraps lazy components and displays a fallback UI during loading.

import { Suspense, lazy } from "react";
import { BrowserRouter, Routes, Route } from "react-router-dom";

const Dashboard = lazy(() => import("./pages/Dashboard"));
const Settings = lazy(() => import("./pages/Settings"));

const App = () => (
  <BrowserRouter>
    <Suspense fallback={<p>Loading page...</p>}>
      <Routes>
        <Route path="/dashboard" element={<Dashboard />} />
        <Route path="/settings" element={<Settings />} />
      </Routes>
    </Suspense>
  </BrowserRouter>
);
  • <Suspense fallback={...}> wraps lazy components
  • While the chunk is downloading, the fallback renders (spinner, skeleton, loading text, etc.)
  • Once loaded, the actual component renders and the fallback disappears

When to Use Lazy Loading

  • Route-level pages — most common use case. Each page becomes a separate chunk.
  • Heavy components rarely used — rich text editor, chart library, PDF viewer
  • Modals/dialogs — load only when opened
  • Admin panels — most users never see them, no reason to load that code for everyone

When NOT to Use Lazy Loading

  • Small components — the overhead of a separate network request outweighs the benefit
  • Components visible on initial load — user sees a loading flash before content appears (bad UX)
  • Components used on every page (Header, Footer, Layout) — they're always needed, so bundle them normally

Named Exports with lazy (Workaround)

Since lazy() requires a default export, here's how to handle files that use named exports:

// If the component uses a named export:
const Settings = lazy(() =>
  import("./pages/Settings").then(module => ({ default: module.Settings }))
);

This re-maps the named export to a default property so lazy() can consume it.
