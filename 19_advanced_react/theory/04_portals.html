The Problem

Sometimes you need to render a component outside its parent's DOM hierarchy. Common situations:

  • A modal inside a deeply nested component gets clipped by overflow: hidden on a parent element
  • A tooltip needs to appear above everything but is rendered inside a card with a low z-index
  • A dropdown menu gets cut off by a scrollable container

The root cause: CSS properties like overflow, z-index, and transform create "stacking contexts" that trap child elements visually. Even if you set z-index: 9999, the element can't escape its parent's stacking context.

Portals — Render Children Into a Different DOM Node

A portal lets you render a React component's output into a DOM node that exists outside the parent component's DOM tree. The component stays in the React tree (for state, context, events) but its HTML output appears elsewhere in the actual DOM.

import { createPortal } from "react-dom";

const Modal = ({ isOpen, onClose, children }: {
  isOpen: boolean;
  onClose: () => void;
  children: React.ReactNode;
}) => {
  if (!isOpen) return null;

  return createPortal(
    <div className="modal-overlay" onClick={onClose}>
      <div className="modal-content" onClick={(e) => e.stopPropagation()}>
        {children}
        <button onClick={onClose}>Close</button>
      </div>
    </div>,
    document.getElementById("modal-root")! // renders HERE in the DOM
  );
};

createPortal(children, domNode) takes two arguments: the JSX to render, and the DOM element where it should appear.

Setup — Add a Portal Target in Your HTML

You need a separate DOM element for the portal to render into. Add it to your index.html:

<!-- index.html -->
<body>
  <div id="root"></div>          <!-- your React app -->
  <div id="modal-root"></div>    <!-- portal target for modals -->
</body>

Usage Example

import { useState } from "react";

const ProductPage = () => {
  const [showModal, setShowModal] = useState(false);

  return (
    <div>
      <h1>Product Details</h1>
      <button onClick={() => setShowModal(true)}>Delete Product</button>

      <Modal isOpen={showModal} onClose={() => setShowModal(false)}>
        <h2>Are you sure?</h2>
        <p>This action cannot be undone.</p>
      </Modal>
    </div>
  );
};

Key Behavior — Events Still Bubble Through React Tree

This is important to understand: even though the modal renders in #modal-root in the actual DOM, React events (onClick, etc.) still bubble through the React component tree, not the DOM tree.

Good to know: even though the portal renders in a different place in the DOM, React events (like onClick) still work normally — as if the portal was inside its parent component. You don't need to do anything special for event handling.

Common Portal Use Cases

  • Modals / dialogs
  • Tooltips
  • Dropdown menus
  • Toast notifications
  • Full-screen overlays

When NOT to Use Portals

  • If the component renders fine without clipping issues — just use normal rendering
  • Don't use portals just because something is "on top" — z-index often suffices when there's no stacking context trap
