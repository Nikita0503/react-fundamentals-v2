What is useReducer?

useReducer is a React hook — an alternative to useState for managing complex state logic. Instead of calling setState directly, you "dispatch" an action (a plain object that describes what happened), and a "reducer" function decides how the state should change based on that action.

Think of it like a command pattern: your component says "this happened" (dispatches an action), and the reducer decides "here's the new state."

The Pattern

The useReducer pattern has four parts:

const [state, dispatch] = useReducer(reducer, initialState);
  • state — the current state value (like what useState returns)
  • dispatch — a function to send actions to the reducer (instead of calling setState directly)
  • reducer — a pure function with signature (state, action) => newState. It takes the current state and an action, and returns the new state. "Pure" means it has no side effects — given the same inputs, it always returns the same output.
  • initialState — the starting value for your state

Full Example — Multi-Step Form

Here's a practical example: a signup form with multiple steps, where several state fields are related and update together.

import { useReducer } from "react";

type FormState = {
  step: number;
  name: string;
  email: string;
  plan: "free" | "pro" | "";
  isSubmitting: boolean;
};

type FormAction =
  | { type: "NEXT_STEP" }
  | { type: "PREV_STEP" }
  | { type: "SET_FIELD"; field: keyof FormState; value: string }
  | { type: "SUBMIT" }
  | { type: "SUBMIT_SUCCESS" };

const initialState: FormState = {
  step: 1,
  name: "",
  email: "",
  plan: "",
  isSubmitting: false,
};

const formReducer = (state: FormState, action: FormAction): FormState => {
  switch (action.type) {
    case "NEXT_STEP":
      return { ...state, step: state.step + 1 };
    case "PREV_STEP":
      return { ...state, step: state.step - 1 };
    case "SET_FIELD":
      return { ...state, [action.field]: action.value };
    case "SUBMIT":
      return { ...state, isSubmitting: true };
    case "SUBMIT_SUCCESS":
      return { ...state, isSubmitting: false };
    default:
      return state;
  }
};

const SignupForm = () => {
  const [state, dispatch] = useReducer(formReducer, initialState);

  return (
    <div>
      <p>Step {state.step} of 3</p>
      {state.step === 1 && (
        <input
          value={state.name}
          onChange={(e) => dispatch({ type: "SET_FIELD", field: "name", value: e.target.value })}
          placeholder="Name"
        />
      )}
      <button onClick={() => dispatch({ type: "NEXT_STEP" })}>Next</button>
      <button onClick={() => dispatch({ type: "PREV_STEP" })} disabled={state.step === 1}>Back</button>
    </div>
  );
};

Simple value (counter, toggle, input)✅Overkill

Many related state variables that update togetherMessy✅
Complex update logic (state machine, multi-step)Hard to read✅
Need to pass dispatch to deep children—✅ (stable reference)

Practical Advice

  • For most React components, useState is enough — don't reach for useReducer by default
  • For complex shared state across many components, state management libraries like Zustand or Redux Toolkit are better than useReducer
  • useReducer is useful for: local complex state (forms, wizards), and understanding Redux (same pattern — actions, reducers, dispatch)
  • Interview question: "When would you use useReducer?" — answer: when state updates are complex and interdependent, e.g., a multi-step form where going to the next step also resets validation errors
