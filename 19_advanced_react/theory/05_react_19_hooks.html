New Hooks in React 18 & 19

React 18 and 19 introduced new hooks for performance and accessibility. These are specialized — you won't use them in every component, but they solve specific problems elegantly.

useTransition — Mark a State Update as "Not Urgent"

useTransition tells React: "this state update can wait — keep the UI responsive for the user." It splits updates into urgent (user sees immediately) and non-urgent (can be interrupted and processed in the background).

import { useState, useTransition } from "react";

const SearchPage = () => {
  const [query, setQuery] = useState("");
  const [results, setResults] = useState<string[]>([]);
  const [isPending, startTransition] = useTransition();

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value;
    setQuery(value); // urgent — update input immediately

    startTransition(() => {
      // non-urgent — can be interrupted if user keeps typing
      const filtered = hugeList.filter(item => item.includes(value));
      setResults(filtered);
    });
  };

  return (
    <div>
      <input value={query} onChange={handleChange} />
      {isPending && <p>Updating results...</p>}
      <ul>
        {results.map(r => <li key={r}>{r}</li>)}
      </ul>
    </div>
  );
};
  • What it does: tells React "this update can wait — keep the UI responsive"
  • When to use: filtering/sorting large lists, search-as-you-type, tab switching with heavy content
  • isPending: a boolean that's true while the transition is processing — use it to show loading indicators
  • Without useTransition: typing in the input would feel laggy because React tries to re-render the huge list synchronously with every keystroke

useDeferredValue — Defer a Value Update

useDeferredValue returns a "lagging" version of a value. React updates it only when it has idle time, keeping urgent updates (like typing) smooth.

import { useState, useDeferredValue, useMemo } from "react";

const SearchResults = ({ query }: { query: string }) => {
  const deferredQuery = useDeferredValue(query);

  // Only recomputes when deferredQuery changes (not on every keystroke)
  const results = useMemo(() => {
    return hugeList.filter(item => item.includes(deferredQuery));
  }, [deferredQuery]);

  return (
    <ul style={{ opacity: query !== deferredQuery ? 0.5 : 1 }}>
      {results.map(r => <li key={r}>{r}</li>)}
    </ul>
  );
};
  • What it does: returns a "lagging" version of a value — updates are deferred until React has time
  • When to use: same scenarios as useTransition, but when you don't control the state update (e.g., the value comes from props)

useTransition vs useDeferredValue

HookUse whenHow it works
useTransitionYou control the setState callWrap the setState in startTransition()
useDeferredValueYou receive a value (from props)Pass the value to useDeferredValue() — React defers its effect

useId — Generate Unique IDs for Accessibility

useId generates a unique, stable ID that's consistent between server and client rendering. It's designed for connecting accessibility attributes like htmlFor/id and aria-describedby.

import { useId } from "react";

const FormField = ({ label }: { label: string }) => {
  const id = useId();

  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input id={id} type="text" />
    </div>
  );
};

// Each instance gets a unique ID:
// <FormField label="Name" />   → id=":r1:"
// <FormField label="Email" />  → id=":r2:"
  • What it does: generates a unique, stable ID that's consistent between server and client (SSR-safe)
  • When to use: connecting <label> to <input> (htmlFor/id), ARIA attributes (aria-describedby, aria-labelledby)
  • Why not Math.random()?: random IDs differ between server render and client hydration — React throws warnings because the HTML doesn't match. useId is deterministic and produces the same ID on both server and client.

What About useOptimistic, useFormStatus, use()?

React 19 also adds hooks for server-side patterns (useOptimistic, useFormStatus, use). You'll encounter these when working with frameworks like Next.js. They're designed for Server Components and Server Actions, which are beyond the scope of this SPA-focused course.
