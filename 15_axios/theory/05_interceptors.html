Interceptors

Interceptors are middleware functions that run before every request or after every response. They let you centralize cross-cutting concerns like authentication and error handling.

Request Interceptor — Inject Auth Token

Instead of manually adding the Authorization header to every request, a request interceptor does it automatically:

httpClient.interceptors.request.use((config) => {
  const token = localStorage.getItem("accessToken");

  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }

  return config;
});

Now every request made through httpClient automatically carries the token — no manual header setting needed.

Response Interceptor — Token Refresh

When an access token expires, the server returns 401. A response interceptor can catch this, refresh the token, and retry the original request — all transparently:

httpClient.interceptors.response.use(
  (response) => response, // success — pass through

  async (error) => {
    const originalRequest = error.config;

    if (error.response?.status === 401 && !originalRequest._retry) {
      originalRequest._retry = true;

      try {
        const { data } = await axios.post<{ accessToken: string }>(
          "https://api.example.com/auth/refresh",
          { refreshToken: localStorage.getItem("refreshToken") }
        );

        localStorage.setItem("accessToken", data.accessToken);
        originalRequest.headers.Authorization = `Bearer ${data.accessToken}`;

        return httpClient(originalRequest);
      } catch {
        // Refresh failed — logout user
        localStorage.removeItem("accessToken");
        localStorage.removeItem("refreshToken");
        window.location.href = "/login";
        return Promise.reject(error);
      }
    }

    return Promise.reject(error);
  }
);

How the Refresh Flow Works

  1. A request fails with 401 Unauthorized
  2. The response interceptor catches the error
  3. It sends a refresh token to get a new access token
  4. If refresh succeeds → retries the original request with the new token
  5. If refresh fails → logs the user out and redirects to login
  6. The _retry flag prevents an infinite loop (only one retry attempt per request)

Queue Pattern (Advanced)

When multiple requests fail with 401 simultaneously, you don't want to refresh the token multiple times. An advanced pattern uses a promise queue — all failed requests wait for a single refresh call, then retry together. This is a production optimization worth knowing exists, but the basic pattern above covers most cases.

Other Use Cases for Interceptors

  • Logging — log request/response details in development
  • Correlation IDs — add a unique ID to every request for tracing
  • Data transformation — transform response data globally (e.g., convert dates)
  • Global loading indicator — show/hide a spinner on every request
// Example: logging interceptor (development only)
httpClient.interceptors.request.use((config) => {
  console.log(`[API] ${config.method?.toUpperCase()} ${config.url}`);
  return config;
});

httpClient.interceptors.response.use(
  (response) => {
    console.log(`[API] ${response.status} ${response.config.url}`);
    return response;
  },
  (error) => {
    console.error(`[API] Error: ${error.response?.status} ${error.config?.url}`);
    return Promise.reject(error);
  }
);
