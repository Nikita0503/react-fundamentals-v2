Безпека при роботі з REST API

Існує поняття - захищений ендпоінт. Для доступу до якогось ресурсу на сервері, клієнт мусить надати додаткові дані, які будуть свідчити серверу про те що цей клієнт є авторизованим. В більшості випадках це header Authorization, який виглядає приблизно так:

headers: {
    'Authorization': 'Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c'
   },

Величезна стрічка з символів - це access token. Він містить у собі дані про клієнта, котрий звертається до ендпоінту. Сервер розшифровує токен і вирішує чи є доступ у цього клієнта до ресурсу.

Існує схожий токен - resfresh token. У access token є термін придатності, після закінчення якого він вважається невалідним і сервер не буде допускати клієнта до ресурсу з ним. Тому існують додаткові ендпоінти на сервері, котрі допомогають створити новий access token, надаючи йому refresh token.

Приблизно виглядає так:

axios.post('https://myserver.com/generate_access_token', {
    'access_token': '…',
    'refresh_token': '…',
}).
then((reponse) => {
    //response: {new_access_token: ‘….’}
})
.catch((e) => {console.log("error: ", e)})

Пілся отримання нового access_token клієнт знову має доступ до захищених ендпоінтів. Якщо не вдаватися до деталей - пара токенів потрібна для підвищення безпеки.

Зазвичай оновлення токена відбувається тоді, коли один з захищених ендпоінтів повертає помилку, де вказано що access token вже невалідний (застарів). На клієнті у catch ми перехоплюємо цю помилку та робимо запит на оновлення access token. Пілся отримання нового токену повторно робимо невдалий запит, вже з новим access token.

Це відбувається таким чином, що користувач не помічає цього процесу. Але це добре бачить розробник проекту, тому що при великій кількості звертань до різних ендпоінтів він мусить застосувати цей механізм до кожного захищеного ендпоінту і це породжує велику кількіть boilerplate коду.

Звісно, можна самостійно розробити клас, який вміє це робити і використовувати його при звертанні до серверу. Але в Axios реалізувати цей процес набато легже та швидше.
