Error Handling

Proper error handling is essential — users need feedback when something goes wrong, and developers need debugging information. Axios provides structured error objects that make this straightforward.

AxiosError Structure

import axios, { AxiosError } from "axios";

interface ApiErrorResponse {
  message: string;
  errors?: Record<string, string[]>;
}

try {
  const { data } = await httpClient.get<User>("/users/123");
} catch (error) {
  if (axios.isAxiosError<ApiErrorResponse>(error)) {
    // Typed error response
    console.log(error.response?.status);       // 404
    console.log(error.response?.data.message); // "User not found"
    console.log(error.code);                   // "ERR_BAD_REQUEST"
  }
}

axios.isAxiosError() — Type Guard

axios.isAxiosError(error) is a type guard that narrows the unknown error to AxiosError. Always use it in catch blocks to safely access Axios-specific properties.

Centralized Error Handling in Interceptor

import { AxiosError } from "axios";

interface ApiErrorResponse {
  message: string;
}

httpClient.interceptors.response.use(
  (response) => response,
  (error: AxiosError<ApiErrorResponse>) => {
    if (!error.response) {
      // Network error — no response from server
      console.error("Network error — check your connection");
    } else if (error.response.status >= 500) {
      // Server error
      console.error("Server error — try again later");
    }

    return Promise.reject(error);
  }
);

Per-Request Error Handling in Components

import { useState } from "react";
import axios from "axios";
import { usersApi } from "./api/users";

const UserProfile = () => {
  const [user, setUser] = useState<User | null>(null);
  const [error, setError] = useState<string | null>(null);

  const loadUser = async () => {
    try {
      const { data } = await usersApi.getById("123");
      setUser(data);
    } catch (err) {
      if (axios.isAxiosError(err)) {
        setError(err.response?.data?.message ?? "Something went wrong");
      }
    }
  };

  return (
    <div>
      {error && <p style={{ color: "red" }}>{error}</p>}
      {user && <p>{user.name}</p>}
    </div>
  );
};

Request Cancellation with AbortController

When a component unmounts before a request completes, you should cancel the request to avoid setting state on an unmounted component:

import { useState, useEffect } from "react";
import axios from "axios";
import { httpClient } from "./api/httpClient";

const UserList = () => {
  const [users, setUsers] = useState<User[]>([]);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const controller = new AbortController();

    httpClient
      .get<User[]>("/users", { signal: controller.signal })
      .then(({ data }) => setUsers(data))
      .catch((err) => {
        if (!axios.isCancel(err)) {
          setError("Failed to load users");
        }
      });

    return () => controller.abort(); // cleanup on unmount
  }, []);

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
};

Two Levels of Error Handling

In production apps, errors are handled at two levels:

  • Global (interceptor) — handles network errors, 500s, token refresh, logging
  • Local (component) — handles specific errors relevant to the UI (show validation messages, "not found" states)

Note: In production, error handling is often combined with React Query (TanStack Query), which manages loading/error states automatically. But understanding the raw patterns is essential before using abstractions.
