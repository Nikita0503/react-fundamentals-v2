Fetch API

fetch is the native browser API for making HTTP requests. It requires no installation — it's built into every modern browser.

Basic Syntax

fetch(url, options) returns a Promise<Response>. The Response object provides:

  • response.ok — true if status is 200-299
  • response.status — the HTTP status code (200, 404, etc.)
  • response.json() — parses the body as JSON (returns a Promise)
  • response.text() — returns the body as plain text

Important: fetch does NOT reject on HTTP errors (4xx, 5xx). It only rejects on network failures (no internet, DNS error). You must check response.ok manually.

GET Request

interface User {
  id: number;
  name: string;
  email: string;
}

const fetchUsers = async (): Promise<User[]> => {
  const response = await fetch("https://api.example.com/users");

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  return response.json();
};

POST Request

interface CreateUserDto {
  name: string;
  email: string;
}

const createUser = async (user: CreateUserDto): Promise<User> => {
  const response = await fetch("https://api.example.com/users", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(user),
  });

  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`);
  }

  return response.json();
};

Using fetch in a React Component

import { useState, useEffect } from "react";

const UserList = () => {
  const [users, setUsers] = useState<User[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const loadUsers = async () => {
      try {
        const response = await fetch("https://api.example.com/users");
        if (!response.ok) throw new Error(`HTTP error: ${response.status}`);
        const data: User[] = await response.json();
        setUsers(data);
      } catch (err) {
        setError(err instanceof Error ? err.message : "Unknown error");
      } finally {
        setLoading(false);
      }
    };

    loadUsers();
  }, []);

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
};

Limitations of fetch

  • No automatic JSON parsing — you must call .json() manually
  • No request/response interceptors
  • No built-in timeout
  • No automatic error throwing on 4xx/5xx — you must check response.ok
  • Verbose for repeated patterns — you repeat headers, base URL, and auth logic on every request

Conclusion: fetch is fine for simple cases, but for production apps with authentication, centralized error handling, and many endpoints — a dedicated HTTP library helps reduce boilerplate and prevent bugs.
