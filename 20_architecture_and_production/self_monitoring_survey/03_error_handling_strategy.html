What are the levels of error handling in a React app (from broadest to most specific)?


( ) try/catch everywhere → Error Boundary as backup ( ) Only Error Boundaries — they catch all errors (x) Global Error Boundary → route-level boundaries → API error handling → component-level try/catch ( ) Axios interceptors → Error Boundary → console.error

Why is console.log in production an antipattern?


( ) It slows down the application significantly ( ) It's removed by the bundler anyway (x) Not structured, can expose sensitive info, can't search/filter/alert on it ( ) It only works in development mode

What should you NEVER log?


( ) API error status codes ( ) Component names that crashed (x) Personal data, authentication tokens, passwords, sensitive request/response bodies ( ) Timestamps and request URLs

What is graceful degradation?


( ) Slowly reducing app features as the user's session expires ( ) Showing a loading spinner instead of content (x) When part of the app fails, the rest keeps working — a broken sidebar doesn't kill the entire page ( ) Redirecting to a static HTML page when JavaScript fails
