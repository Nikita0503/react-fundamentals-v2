Code Splitting (Recap)

Use React.lazy + Suspense to split your app into chunks that load on demand. Instead of shipping one massive JavaScript file, the browser downloads only what's needed for the current page. Covered in detail in the Advanced React module.

Bundle Analysis — What's Making Your App Heavy?

A "bundle" is the final JavaScript file(s) that the browser downloads. Bundle analysis tools show you exactly which packages contribute to the file size:

# Vite
npx vite-bundle-visualizer

# Or install rollup-plugin-visualizer
npm install -D rollup-plugin-visualizer
  • Generates a visual treemap showing which packages take the most space
  • Common culprits: moment.js (use date-fns instead), lodash (import specific functions), large icon libraries (import only used icons)
  • Rule: if a dependency adds >50KB and you only use one function from it — find a lighter alternative or import selectively

Tree Shaking

"Tree shaking" is a bundler optimization that removes unused code from your final bundle — like shaking a tree and letting dead leaves fall off. Only the code you actually import ends up in the output.

  • Only works with ES modules (import/export, not require)
  • Named imports enable tree shaking:
// ✅ Only debounce is included in the bundle, not all of lodash
import { debounce } from "lodash-es";

// ✅ Named imports — bundler can remove unused exports
import { Button } from "./components";

// ❌ Default import of large object — bundler can't determine what's unused
import components from "./components";

Image Optimization

Images are often the heaviest assets on a page. Optimize them to reduce load time:

Lazy load images below the fold (content not visible without scrolling):

<img src="photo.jpg" loading="lazy" alt="Product photo" />

Use modern formats: WebP (30% smaller than JPEG), AVIF (50% smaller)

Responsive images with srcset — serve different sizes based on screen width:

<img
  src="photo-800.jpg"
  srcSet="photo-400.jpg 400w, photo-800.jpg 800w, photo-1200.jpg 1200w"
  sizes="(max-width: 600px) 400px, 800px"
  alt="Product"
/>

For React: use <img loading="lazy"> or a library like react-lazy-load-image-component

Web Vitals — What Google Measures

Web Vitals are metrics that Google uses to measure real-world user experience. They affect search ranking and correlate with user satisfaction:

MetricWhat it measuresGood threshold
LCP (Largest Contentful Paint)How fast the main content appears< 2.5s
INP (Interaction to Next Paint)How fast the app responds to user input< 200ms
CLS (Cumulative Layout Shift)How much the page layout jumps around< 0.1
  • Why it matters: Google uses these for search ranking. Users leave slow/janky sites.
  • How to measure: Chrome DevTools → Lighthouse tab, or web.dev/measure

React DevTools Profiler (Recap)

  • Shows which components re-render and how long they take
  • Identify: components rendering >16ms (blocking a frame), components rendering unnecessarily
  • Fix with: React.memo, useMemo, useCallback, moving state down
  • Covered in detail in the Performance module

Lighthouse

  • Built into Chrome DevTools (Lighthouse tab)
  • Audits: Performance, Accessibility, Best Practices, SEO
  • Gives actionable recommendations with priority
  • Run on production build (npm run build, not dev server) — dev mode is slower and gives misleading scores

Quick Wins Checklist

  1. Lazy load routes (React.lazy)
  2. Lazy load images (loading="lazy")
  3. Analyze bundle (find heavy dependencies)
  4. Use production build for deployment (npm run build, not dev server)
  5. Enable gzip/brotli compression on server
  6. Cache static assets (long cache headers for JS/CSS/images)
