The Problem

Two sibling components need to share the same data, but they can't pass props to each other — props only flow from parent to child. So how do siblings communicate?

The Solution: Lift State Up

Lifting state up means moving the shared state to the nearest common parent of the components that need it. The parent owns the state and passes it down to both children — one reads it, one writes it, or both do both.

Full Example — Shared Name

An input where you type your name, and a greeting that displays it. Both components need the same value — so the parent owns it:

import { useState } from "react";

const App = () => {
  const [name, setName] = useState("");

  return (
    <div>
      <NameInput value={name} onChange={setName} />
      <Greeting name={name} />
    </div>
  );
};

type NameInputProps = {
  value: string;
  onChange: (value: string) => void;
};

const NameInput = ({ value, onChange }: NameInputProps) => (
  <input
    value={value}
    onChange={(e) => onChange(e.target.value)}
    placeholder="Enter your name"
  />
);

type GreetingProps = {
  name: string;
};

const Greeting = ({ name }: GreetingProps) => (
  <p>{name ? `Hello, ${name}!` : "Enter your name above"}</p>
);

Key Insight: Single Source of Truth

NameInput and Greeting are siblings — they can't talk to each other directly. But they both need the same name value. The parent (App) owns the state and passes it down to both. When the input changes, the parent updates, and both children get fresh data.

The NameInput is "controlled" — it doesn't own its value, the parent does. The parent passes the value down and receives changes back via the callback.

When to Lift State Up

  • Two or more components need the same data
  • A child needs to update something that affects a sibling
  • You want a "single source of truth" for a piece of data

When NOT to Lift (Keep State Local)

  • Only one component uses the data
  • The state is purely UI-related (dropdown open/closed, input focus, hover state)
  • Lifting would add complexity without benefit

Not every piece of state needs to be lifted. Keep state as close to where it's used as possible — only lift when sharing is genuinely needed.
