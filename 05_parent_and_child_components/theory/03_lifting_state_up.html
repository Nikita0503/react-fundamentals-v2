The Problem

Two sibling components need to share the same data, but they can't pass props to each other — props only flow from parent to child. So how do siblings communicate?

The Solution: Lift State Up

Lifting state up means moving the shared state to the nearest common parent of the components that need it. The parent owns the state and passes it down to both children — one reads it, one writes it, or both do both.

Full Example — Temperature Converter

Two input fields (Celsius and Fahrenheit) that stay in sync. When you type in one, the other updates automatically:

const TemperatureConverter = () => {
  const [celsius, setCelsius] = useState("");

  const fahrenheit = celsius ? String((Number(celsius) * 9) / 5 + 32) : "";

  return (
    <div>
      <TemperatureInput
        label="Celsius"
        value={celsius}
        onChange={setCelsius}
      />
      <TemperatureInput
        label="Fahrenheit"
        value={fahrenheit}
        onChange={(f) => setCelsius(String(((Number(f) - 32) * 5) / 9))}
      />
    </div>
  );
};

type TemperatureInputProps = {
  label: string;
  value: string;
  onChange: (value: string) => void;
};

const TemperatureInput = ({ label, value, onChange }: TemperatureInputProps) => (
  <label>
    {label}:
    <input value={value} onChange={(e) => onChange(e.target.value)} />
  </label>
);

Key Insight: Controlled Components

The TemperatureInput component is "controlled" — it doesn't own its value, the parent does. The parent passes the value down and receives changes back via the callback. This makes both inputs stay in sync because they both derive from the same source of truth (celsius state in the parent).

When to Lift State Up

  • Two or more components need the same data
  • A child needs to update something that affects a sibling
  • You want a "single source of truth" for a piece of data

When NOT to Lift (Keep State Local)

  • Only one component uses the data
  • The state is purely UI-related (dropdown open/closed, input focus, hover state)
  • Lifting would add complexity without benefit

Not every piece of state needs to be lifted. Keep state as close to where it's used as possible — only lift when sharing is genuinely needed.
