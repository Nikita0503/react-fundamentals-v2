Data Down, Events Up

In React, communication between components follows a clear pattern:

  • Data flows DOWN — parent → child via props
  • Events flow UP — child → parent via callback functions

A child component cannot directly modify the parent's state. Instead, the parent passes a function (callback) as a prop, and the child calls that function when something happens.

Passing Functions as Props

The parent owns the state and the handler. The child receives the handler via props and calls it to communicate back:

// Parent owns the state and the handler
const TodoList = () => {
  const [todos, setTodos] = useState<string[]>([]);

  const handleAddTodo = (text: string) => {
    setTodos(prev => [...prev, text]);
  };

  return (
    <div>
      <h1>Todos ({todos.length})</h1>
      <AddTodoForm onAdd={handleAddTodo} />
      <ul>
        {todos.map((todo, i) => <li key={i}>{todo}</li>)}
      </ul>
    </div>
  );
};

// Child calls the callback to notify parent
type AddTodoFormProps = {
  onAdd: (text: string) => void;
};

const AddTodoForm = ({ onAdd }: AddTodoFormProps) => {
  const [input, setInput] = useState("");

  const handleSubmit = () => {
    if (input.trim()) {
      onAdd(input);    // notify parent
      setInput("");    // reset local state
    }
  };

  return (
    <div>
      <input value={input} onChange={(e) => setInput(e.target.value)} />
      <button onClick={handleSubmit}>Add</button>
    </div>
  );
};

Naming Convention for Callback Props

Callback props should be prefixed with on to indicate they are event handlers:

  • onClick — when something is clicked
  • onChange — when a value changes
  • onSubmit — when a form is submitted
  • onDelete — when an item should be deleted
  • onAdd — when an item should be added

This convention makes it immediately clear that the prop expects a function and that it will be called in response to some event.

Separation of Concerns

The child doesn't know or care what the parent does with the data — it just calls the function. The parent decides how to handle the event. This is separation of concerns — each component has a single responsibility.

Passing Data WITH the Callback

Often the child needs to tell the parent which item triggered the event. Pass identifying data along with the callback call:

type TodoItemProps = {
  id: number;
  text: string;
  onDelete: (id: number) => void;
};

const TodoItem = ({ id, text, onDelete }: TodoItemProps) => (
  <li>
    {text}
    <button onClick={() => onDelete(id)}>Delete</button>
  </li>
);

Notice the arrow function in onClick — it creates a closure that captures the id and passes it to onDelete when the button is clicked. Without the arrow function, onDelete(id) would be called immediately during render.
