Spreading Props

Sometimes you want to create a wrapper component that adds some behavior but forwards all native attributes to the underlying element. The spread operator makes this easy:

type InputProps = {
  label: string;
} & React.InputHTMLAttributes<HTMLInputElement>;

const Input = ({ label, ...rest }: InputProps) => (
  <label>
    {label}
    <input {...rest} />
  </label>
);

// Usage — all standard input attributes are forwarded:
<Input label="Email" type="email" placeholder="you@example.com" required />
  • ...rest collects all remaining props (everything except label)
  • {...rest} spreads them onto the <input> element
  • This is useful for wrapper components that add behavior but forward native attributes

Props Drilling — The Problem

Props drilling happens when you pass props through many intermediate components that don't use them — they just pass them along to reach a deeply nested child:

// The "theme" prop must travel through components that don't use it:
// App → Layout → Sidebar → UserMenu → Avatar
// Layout, Sidebar, and UserMenu don't use "theme" but must pass it through

Problems with props drilling:

  • Cluttered component APIs — intermediate components have props they don't care about
  • Hard to refactor — changing the prop name or type requires updating every component in the chain
  • Unnecessary coupling — intermediate components are coupled to data they don't use

Props Drilling — Code Example

Here's a 3-level example where Layout doesn't use theme but must pass it through:

// App passes "theme" through Layout to Header — Layout doesn't use it
const App = () => {
  const [theme, setTheme] = useState<"light" | "dark">("light");
  return <Layout theme={theme} />;
};

const Layout = ({ theme }: { theme: "light" | "dark" }) => (
  <div>
    <Header theme={theme} />  {/* just passing through */}
  </div>
);

const Header = ({ theme }: { theme: "light" | "dark" }) => (
  <nav className={`nav-${theme}`}>Navigation</nav>
);

Solutions to Props Drilling

1. Composition — restructure so the parent renders the deep child directly:

const App = () => {
  const [theme, setTheme] = useState<"light" | "dark">("light");
  return (
    <Layout>
      <Header theme={theme} />  {/* App passes directly, no drilling */}
    </Layout>
  );
};

By using children, the Layout component no longer needs to know about theme at all.

2. Context — share data without passing through every level

React Context lets you "broadcast" data to any component in the tree without explicitly passing it through each level. Covered in detail in Module 09.

3. State management libraries — Redux/Zustand for complex shared state

For large applications with many pieces of shared state, dedicated state management libraries provide a global store accessible from any component. Covered in Module 12.

When Props Drilling Is Fine

Don't over-engineer. Props drilling through 2-3 levels is completely normal and often the simplest solution. Only reach for Context or state management when drilling becomes painful:

  • 5+ levels deep
  • Many props being drilled
  • Multiple unrelated components need the same data
  • Refactoring becomes difficult due to the prop chain
