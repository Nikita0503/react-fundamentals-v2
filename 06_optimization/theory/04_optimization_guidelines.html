Rule #1: Don't Optimize Prematurely

React is fast by default. Most apps don't need manual optimization.

  • Wrong approach: wrap everything in memo/useMemo/useCallback "just in case"
  • Right approach: build first, measure, optimize bottlenecks

Rule #2: Measure Before Optimizing

Use the React DevTools Profiler — it shows which components re-render and how long they take.

  • If a component renders in <1ms, memoizing it saves nothing
  • Look for: components that render >16ms (causes frame drops), or render hundreds of times per second

Rule #3: Structural Optimization First

Before reaching for memo, try restructuring your components:

// ❌ Entire page re-renders when input changes
const Page = () => {
  const [search, setSearch] = useState("");
  return (
    <div>
      <input value={search} onChange={e => setSearch(e.target.value)} />
      <ExpensiveChart />  {/* re-renders on every keystroke! */}
    </div>
  );
};

// ✅ Move state down — only SearchInput re-renders
const Page = () => (
  <div>
    <SearchInput />       {/* owns its own state */}
    <ExpensiveChart />    {/* doesn't re-render */}
  </div>
);

const SearchInput = () => {
  const [search, setSearch] = useState("");
  return <input value={search} onChange={e => setSearch(e.target.value)} />;
};

"Move state down" and "lift content up" are free optimizations — no memo needed.

Rule #4: The Optimization Toolkit (in order of preference)

  1. Move state down / restructure components (free)
  2. React.memo for expensive children that re-render unnecessarily
  3. useMemo for expensive computations
  4. useCallback for stabilizing function references (paired with memo)

React Compiler (Future)

React 19 introduces the React Compiler (formerly "React Forget"):

  • It automatically memoizes components, values, and callbacks at build time
  • In the future, manual memo/useMemo/useCallback will become less necessary
  • But understanding WHY they exist is still important for interviews and working with current codebases

Summary — When to Optimize

Symptom Solution
Expensive child re-renders when parent state changes React.memo on child
Expensive computation runs on every render useMemo
Memoized child re-renders because function prop changes useCallback + React.memo
Input causes entire page to re-render Move state down
Many context consumers re-render Split context or use selectors
