React.memo

Given the rules of component re-rendering in React, a perfectly natural question arises — "is it possible to prevent unnecessary re-renders somehow?" The answer is yes, it is possible. For this purpose, React.memo is used.

React.memo is a built-in function in the React library that provides the ability to optimize the re-rendering process of components. It allows caching the rendering results of components and re-rendering them only when the input properties (props) change.

When you use React.memo to wrap a functional component, React automatically checks the component's input props during rendering. If the input props values have not changed, React reuses the cached rendering result of the component instead of performing a re-render. This can help avoid unnecessary renders and improve the application's performance.

The basic syntax for using React.memo is as follows:

import React from 'react';

const MyComponent = (props) => {
  // Component code
};

export default React.memo(MyComponent);

Using React.memo can be useful when you have a component that needs to re-render only when certain input props change, while other component properties remain unchanged. This can be useful, for example, when you have large lists of components or nested components, and you want to avoid unnecessary renders that may affect the application's performance.

Example of using React.memo with two input props, but the component will re-render only when one of these props changes:

import React from 'react';

const MyComponent = ({ prop1, prop2 }) => {
  // Component code

  return (
    <div>
      {/* Using the value of prop1 */}
      <p>Prop1: {prop1}</p>
      {/* Using the value of prop2 */}
      <p>Prop2: {prop2}</p>
    </div>
  );
};

// Using React.memo to optimize rendering
export default React.memo(MyComponent, (prevProps, nextProps) => {
  // Check if only prop1 has changed, while prop2 remains unchanged
  return prevProps.prop1 === nextProps.prop1;
});

In this example, React.memo is used to optimize the rendering of the MyComponent component. It accepts two arguments: the first is the component itself, and the second is a comparison function (compare function). The comparison function takes two arguments — prevProps and nextProps, which represent the previous and next prop values respectively.

In the example, the comparison function checks whether only prop1 has changed, while prop2 is left unchecked. If so, React.memo reuses the cached rendering result of the component and does not perform a re-render, which helps avoid unnecessary rendering operations.

That is, if prop2 is changed, it will not affect the component's render. The MyComponent component will re-render only when prop1 changes, since the comparison function in React.memo only compares the value of prop1 between the previous and next input props. In this case, prop2 does not affect the result.

This can be a useful optimization in some cases when you want to avoid unnecessary re-rendering of a component if changes in some props do not affect the visual appearance or behavior of the component.

However, you should be careful when using React.memo, as incorrect usage can lead to incorrect behavior of components, especially when they interact with state or modify it.
