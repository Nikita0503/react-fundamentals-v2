React.memo

React.memo wraps a component to skip re-renders when props haven't changed.

  • Without memo: component re-renders every time parent re-renders (regardless of props)
  • With memo: component only re-renders when its props actually change (shallow comparison)

Syntax

import { memo } from "react";

type ExpensiveListProps = {
  items: string[];
  onItemClick: (item: string) => void;
};

const ExpensiveList = memo(({ items, onItemClick }: ExpensiveListProps) => {
  console.log("ExpensiveList rendered"); // won't log if props are the same
  return (
    <ul>
      {items.map(item => (
        <li key={item} onClick={() => onItemClick(item)}>{item}</li>
      ))}
    </ul>
  );
});

export { ExpensiveList };

How It Works

Before re-rendering, React does a shallow comparison of all props (Object.is for each prop). If all props are the same → skip render.

When to Use React.memo

  • Component renders often but its props rarely change
  • Component is expensive to render (large list, complex calculations, heavy SVGs)
  • Component is deep in the tree and parent re-renders frequently

When NOT to Use React.memo

  • Component is cheap to render (simple div with text) — memo's comparison cost > render cost
  • Props change on almost every render anyway (memo compares but still re-renders)
  • Component receives new objects/arrays/functions as props every render (memo won't help without useMemo/useCallback)

The Trap: Unstable References

Memo only does shallow comparison. If parent creates a new object/function on every render, memo sees "new reference" and re-renders anyway:

// ❌ memo is useless here — onClick is a new function every render
const Parent = () => {
  return <MemoizedChild onClick={() => console.log("click")} />;
};

// ✅ Fix: stabilize the function with useCallback
const Parent = () => {
  const handleClick = useCallback(() => console.log("click"), []);
  return <MemoizedChild onClick={handleClick} />;
};

Note: you don't need a custom comparator in 99% of cases. The default shallow comparison is almost always what you want.
