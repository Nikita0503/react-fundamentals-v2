useMemo and useCallback

useMemo — caches the RESULT of a computation between renders.

useCallback — caches a FUNCTION reference between renders.

They solve the same problem: preventing unnecessary recalculations or unstable references.

useMemo

Syntax: const value = useMemo(() => computeExpensiveValue(a, b), [a, b])

Only recomputes when dependencies change.

Realistic example — filtering and sorting a large list:

type Product = { id: number; name: string; price: number; category: string };

const ProductList = ({ products, category, sortBy }: {
  products: Product[];
  category: string;
  sortBy: "price" | "name";
}) => {
  // Without useMemo: filters and sorts on EVERY render (even if unrelated state changes)
  // With useMemo: only recomputes when products, category, or sortBy change
  const filteredProducts = useMemo(() => {
    const filtered = products.filter(p => p.category === category);
    return filtered.sort((a, b) =>
      sortBy === "price" ? a.price - b.price : a.name.localeCompare(b.name)
    );
  }, [products, category, sortBy]);

  return (
    <ul>
      {filteredProducts.map(p => <li key={p.id}>{p.name} — ${p.price}</li>)}
    </ul>
  );
};

When to use useMemo:

  • Expensive computations (sorting/filtering large arrays, complex math)
  • Stabilizing object/array references passed to memoized children
  • Avoiding recalculation when unrelated state changes trigger re-render

useCallback

Syntax: const fn = useCallback(() => { ... }, [dependencies])

It caches a function reference between renders. Without it, a new function is created on every render — which breaks React.memo on child components.

Main use case: stabilizing function references passed to memoized children:

import { useState, useCallback, memo } from "react";

// Parent component
const App = () => {
  const [count, setCount] = useState(0);
  const [name, setName] = useState("");

  // Without useCallback: new function every render → Button re-renders when name changes
  // With useCallback: same function reference → Button skips re-render
  const handleIncrement = useCallback(() => {
    setCount(prev => prev + 1);
  }, []);

  return (
    <div>
      <input value={name} onChange={e => setName(e.target.value)} placeholder="Type here..." />
      <p>Count: {count}</p>
      <MemoizedButton onClick={handleIncrement} label="Increment" />
    </div>
  );
};
// Child component — wrapped in memo
type ButtonProps = {
  onClick: () => void;
  label: string;
};

const Button = ({ onClick, label }: ButtonProps) => {
  console.log("Button rendered"); // won't log when only name changes
  return <button onClick={onClick}>{label}</button>;
};

const MemoizedButton = memo(Button);

When you type in the input, name changes → App re-renders. But MemoizedButton skips re-render because its props (onClick and label) didn't change. Without useCallback, onClick would be a new function every render and memo would be useless.

The Combo: useCallback + React.memo

They work together as a pair:

  • React.memo on the child → skips render if props are same
  • useCallback on the parent's handler → keeps function reference stable
  • Without both together, neither is effective alone

When NOT to Use useMemo/useCallback

  • Simple calculations (a + b, string concatenation) — overhead of memoization > computation cost
  • Functions not passed to memoized children — if the child isn't wrapped in memo, stabilizing the reference does nothing
  • Values that change on every render anyway — memoization just adds overhead
