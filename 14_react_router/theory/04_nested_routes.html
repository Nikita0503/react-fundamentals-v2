Nested Routes

The problem: most apps have a shared layout (header, sidebar, footer) that stays the same across pages. Only the main content area changes.

Nested routes solve this: define a parent route with a layout, child routes render inside it.

Outlet

Outlet is a placeholder component that renders the matched child route:

// App.tsx
import { BrowserRouter, Routes, Route } from "react-router-dom";
import { RootLayout } from "./layouts/RootLayout";
import { HomePage } from "./pages/HomePage";
import { AboutPage } from "./pages/AboutPage";
import { ProductsPage } from "./pages/ProductsPage";
import { ProductPage } from "./pages/ProductPage";

const App = () => (
  <BrowserRouter>
    <Routes>
      <Route element={<RootLayout />}>
        <Route path="/" element={<HomePage />} />
        <Route path="/about" element={<AboutPage />} />
        <Route path="/products" element={<ProductsPage />} />
        <Route path="/products/:id" element={<ProductPage />} />
      </Route>
    </Routes>
  </BrowserRouter>
);
// layouts/RootLayout.tsx
import { Outlet, Link } from "react-router-dom";

const RootLayout = () => (
  <div>
    <header>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/about">About</Link>
        <Link to="/products">Products</Link>
      </nav>
    </header>

    <main>
      <Outlet /> {/* Child route renders here */}
    </main>

    <footer>© 2025 My App</footer>
  </div>
);

export { RootLayout };

The parent Route has no path — it's a layout route (always matches).

<Outlet /> is where the child route's element appears.

Header and footer stay on screen, only <Outlet /> content changes.

Multiple Levels of Nesting

<Routes>
  <Route element={<RootLayout />}>
    <Route path="/" element={<HomePage />} />
    <Route path="/dashboard" element={<DashboardLayout />}>
      <Route index element={<DashboardHome />} />
      <Route path="settings" element={<Settings />} />
      <Route path="profile" element={<Profile />} />
    </Route>
  </Route>
</Routes>

/dashboard → DashboardLayout with DashboardHome in its Outlet.

/dashboard/settings → DashboardLayout with Settings in its Outlet.

/dashboard/profile → Profile is wrapped in both layouts at once:

// What renders on screen for /dashboard/profile:
RootLayout (header, footer)
  └── Outlet renders → DashboardLayout (sidebar, dashboard nav)
       └── Outlet renders → Profile (page content)

Each <Outlet /> renders the next level of nesting. RootLayout's Outlet renders DashboardLayout, DashboardLayout's Outlet renders Profile. Both layouts stay on screen — only the innermost content changes.

index route — renders when parent path matches exactly (no sub-path).

Why Nested Routes Are Powerful

Layouts are defined once, not repeated in every page.

Each layout can have its own navigation, sidebar, loading states.

Routes are composable — add new pages without touching the layout.
