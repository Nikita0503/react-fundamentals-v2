Підсумки

В цьому модулі було розглянуто базові можливості React Router. Якщо розробляється додаток з простою навігацією, цих знань буде достатньо для реалізації проекту.

Можливі питання:

"Для чого використовувати React Router, якщо можна користуватися звичайним <a href="">?”

Відповідь - по-перше, можливості бібліотеки, котрі роблять додаток оптимізованішим.  Наприклад: Основна причина використання компонента <Link> з React Router замість звичайного тега прив'язки <a href=""> полягає в тому, що <Link> розроблений спеціально для навігації між маршрутами в односторінковому додатку (React – SPA, під капотом: весь додаток – одна сторінка).

Коли ви використовуєте тег прив'язки з атрибутом href, натискання посилання посилить перезавантаження сторінки, що може бути повільним і переривати роботу додатку. Навпаки, коли ви використовуєте компонент <Link>, він оновлює URL-адресу і відображає новий компонент, не викликаючи повного перезавантаження сторінки, що робить роботу додатка більш швидким і плавним.  По-друге - використання бібліотеки, робить код більш структурованим, читабельним та чистим. Дуже зручна структура навігації дає можливість розробляти гнучку архітектуру та розширення додатку не викличе проблем.

"Чи можливо поєднати React Router з Redux у одному проекті?”

Відповідь - так. Для цього треба внести невеличкі зміни у App.js:

/** App.js */

import React from 'react';
import { store } from './redux/store'; // імпортувати перед компонентами
import { BrowserRouter, Route, Routes } from 'react-router-dom';
import ProfilePage from './pages/ProfilePage';
import HomePage from './pages/HomePage';
import ProductPage from './pages/ProductPage';
import { Provider } from 'react-redux';
 
const App = () => {

  return (
    <Provider store={store}>
      <BrowserRouter> 
        <Routes> 
          <Route path='home' element={<HomePage/>}/>
          <Route path='profile' element={<ProfilePage/>}/> 
          <Route path='product/:id' element={<ProductPage/>}/>
        </Routes>
      </BrowserRouter>
    </Provider>
  )
}

export default App;

Коротше кажучи - просто огорнути навігацію у Provider. Але потрібно імпортувати store перед імпортуванням компонентів для запомігання помилок ініціалізації частин проекту.

"Компоненти були обгорнуті у пусті теги <></>. Що це таке?".

Відповідь - У React, коли компонент повертає більше одного елемента, вони повинні бути обгорнуті в один батьківський елемент (наприклад div).

Використання фрагментів дозволяє уникнути створення додаткового DOM-елемента (того ж div) в якості батьківського елемента.

import React from 'react';

const ComponentWithFragment = () => {
  return (
    <>
      <h1>Title</h1>
      <p>Text 1</p>
      <p>Text 2</p>
    </>
  );
};

export default ComponentWithFragment;

По суті, що при будуванні DOM-дерева цей фрагмент зникає. Він є просто частиною синтаксису, що дозволяє повертати декілька елементів без огортки.

Припустимо що ComponentWithFragment знаходиться у div, в кому в стилях вказано flex-direction: column. То усі елементи з цього компонента розташуються згідно с цим правилом. Так як в них немає елемента контейнера
