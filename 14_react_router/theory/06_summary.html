Summary

In this module, we covered the basic capabilities of React Router. If you are developing an application with simple navigation, this knowledge will be sufficient for project implementation.

Possible questions:

"Why use React Router if you can use a regular <a href="">?"

Answer - first, the library's capabilities make the application more optimized. For example: The main reason for using the <Link> component from React Router instead of a regular anchor tag <a href=""> is that <Link> is designed specifically for navigation between routes in a single-page application (React is an SPA, under the hood: the entire application is one page).

When you use an anchor tag with an href attribute, clicking the link will cause a full page reload, which can be slow and interrupt the application's work. On the contrary, when you use the <Link> component, it updates the URL and renders the new component without causing a full page reload, making the application faster and smoother. Second - using the library makes the code more structured, readable, and clean. A very convenient navigation structure allows developing flexible architecture and expanding the application won't cause problems.

"Is it possible to combine React Router with Redux in one project?"

Answer - yes. For this, you need to make small changes to App.js:

/** App.js */

import React from 'react';
import { store } from './redux/store'; // import before components
import { BrowserRouter, Route, Routes } from 'react-router-dom';
import ProfilePage from './pages/ProfilePage';
import HomePage from './pages/HomePage';
import ProductPage from './pages/ProductPage';
import { Provider } from 'react-redux';
 
const App = () => {

  return (
    <Provider store={store}>
      <BrowserRouter> 
        <Routes> 
          <Route path='home' element={<HomePage/>}/>
          <Route path='profile' element={<ProfilePage/>}/> 
          <Route path='product/:id' element={<ProductPage/>}/>
        </Routes>
      </BrowserRouter>
    </Provider>
  )
}

export default App;

In short - just wrap the navigation in Provider. But you need to import store before importing components to prevent initialization errors of project parts.

"Components were wrapped in empty tags <></>. What is that?"

Answer - In React, when a component returns more than one element, they must be wrapped in a single parent element (for example div).

Using fragments allows avoiding the creation of an additional DOM element (like div) as a parent element.

import React from 'react';

const ComponentWithFragment = () => {
  return (
    <>
      <h1>Title</h1>
      <p>Text 1</p>
      <p>Text 2</p>
    </>
  );
};

export default ComponentWithFragment;

Essentially, when building the DOM tree, this fragment disappears. It is simply part of the syntax that allows returning multiple elements without a wrapper.

Let's assume that ComponentWithFragment is inside a div that has flex-direction: column in its styles. Then all elements from this component will be arranged according to this rule, since they don't have a container element.
