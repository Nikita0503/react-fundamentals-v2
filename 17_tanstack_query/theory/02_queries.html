useQuery — The Main Hook for Fetching Data

import { useQuery } from "@tanstack/react-query";

type Post = { id: number; title: string; body: string };

const PostList = () => {
  const { data, isLoading, isError, error } = useQuery<Post[]>({
    queryKey: ["posts"],
    queryFn: () => fetch("/api/posts").then(res => res.json()),
  });

  if (isLoading) return <p>Loading...</p>;
  if (isError) return <p>Error: {error.message}</p>;

  return (
    <ul>
      {data?.map(post => <li key={post.id}>{post.title}</li>)}
    </ul>
  );
};

queryKey — Unique Identifier for Cached Data

  • It's an array: ["posts"], ["posts", postId], ["posts", { status: "published" }]
  • Same key = same cached data (deduplication)
  • When key changes, TQ fetches new data automatically
  • Think of it as the "address" in the cache
// Different keys = different cache entries
useQuery({ queryKey: ["posts"], ... })           // all posts
useQuery({ queryKey: ["posts", 42], ... })       // post with id 42
useQuery({ queryKey: ["posts", { page: 2 }], ... }) // posts page 2

When any part of the key changes, TanStack Query treats it as a new query and fetches fresh data automatically. So ["posts", { page: 2 }] and ["posts", { page: 3 }] are separate cache entries — switching from page 2 to page 3 triggers a new fetch without you writing any extra logic.

queryFn — The Function That Fetches Data

Can be any async function that returns data or throws:

// With fetch
queryFn: () => fetch("/api/posts").then(res => {
  if (!res.ok) throw new Error("Failed to fetch");
  return res.json();
})

// With axios
queryFn: () => axios.get<Post[]>("/api/posts").then(res => res.data)

Return Values

PropertyTypeDescription
dataT | undefinedThe fetched data (undefined while loading)
isLoadingbooleanTrue on first load (no cached data yet)
isFetchingbooleanTrue whenever a fetch is in progress (including background refetch)
isErrorbooleanTrue if the query failed
errorError | nullThe error object
isSuccessbooleanTrue if data is available
refetchfunctionManually trigger a refetch

Dependent Queries

A query that depends on another query's result:

const { data: user } = useQuery({
  queryKey: ["user", userId],
  queryFn: () => fetchUser(userId),
});

const { data: posts } = useQuery({
  queryKey: ["posts", user?.id],
  queryFn: () => fetchPostsByUser(user!.id),
  enabled: !!user, // only runs when user is available
});

enabled: false — query won't run until condition is true.

Stale Time and Cache Time

useQuery({
  queryKey: ["posts"],
  queryFn: fetchPosts,
  staleTime: 5 * 60 * 1000, // data is "fresh" for 5 minutes (no refetch)
  gcTime: 30 * 60 * 1000,   // cached data kept for 30 minutes after last use
});
  • staleTime — how long data is considered fresh (default: 0 = immediately stale)
  • gcTime (garbage collection time) — how long unused cache entries are kept (default: 5 min)
  • Fresh data → no background refetch. Stale data → refetch in background on mount/focus.
