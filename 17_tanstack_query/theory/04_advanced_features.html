Pagination

What is pagination? When you have a large list of items (e.g., 10,000 blog posts), you don't load them all at once — that would be slow and use too much memory. Instead, you load them in small chunks called "pages" (e.g., 20 items per page). The user clicks "Next" / "Previous" or page numbers to see more data.

Why? Faster initial load, less memory usage, better UX. The server only sends a small portion of data at a time.

const PostList = ({ page }: { page: number }) => {
  const { data, isLoading, isPlaceholderData } = useQuery({
    queryKey: ["posts", { page }],
    queryFn: () => fetch(`/api/posts?page=${page}`).then(r => r.json()),
    placeholderData: (previousData) => previousData, // keep showing old data while new page loads
  });

  return (
    <div>
      {isLoading ? <p>Loading...</p> : (
        <ul style={{ opacity: isPlaceholderData ? 0.5 : 1 }}>
          {data?.map((post: Post) => <li key={post.id}>{post.title}</li>)}
        </ul>
      )}
    </div>
  );
};
  • placeholderData: (prev) => prev — shows previous page data while new page loads (no loading flash)
  • isPlaceholderData — true when showing old data while new page loads (you can use it to show a subtle loading indicator, like reducing opacity)

Infinite Scroll with useInfiniteQuery

import { useInfiniteQuery } from "@tanstack/react-query";

type PostsResponse = { posts: Post[]; nextCursor: number | null };

const InfinitePostList = () => {
  const { data, fetchNextPage, hasNextPage, isFetchingNextPage, isLoading } = useInfiniteQuery<PostsResponse>({
    queryKey: ["posts", "infinite"],
    queryFn: ({ pageParam }) =>
      fetch(`/api/posts?cursor=${pageParam}`).then(r => r.json()),
    initialPageParam: 0,
    getNextPageParam: (lastPage) => lastPage.nextCursor,
  });

  if (isLoading) return <p>Loading...</p>;

  return (
    <div>
      {data?.pages.map((page, i) => (
        <div key={i}>
          {page.posts.map(post => <p key={post.id}>{post.title}</p>)}
        </div>
      ))}
      <button onClick={() => fetchNextPage()} disabled={!hasNextPage || isFetchingNextPage}>
        {isFetchingNextPage ? "Loading more..." : hasNextPage ? "Load More" : "No more posts"}
      </button>
    </div>
  );
};
  • getNextPageParam — tells TQ how to get the next page (cursor, offset, page number)
  • data.pages — array of all loaded pages
  • fetchNextPage() — loads the next page
  • hasNextPage — false when getNextPageParam returns null/undefined

Select — Transform Data Before Using It

Sometimes your API returns a full object, but your component only needs part of it. The select option lets you transform the cached data before it reaches your component:

// API returns full Post objects: [{ id, title, body, author }, ...]
// But this component only needs the titles

const { data: postTitles } = useQuery({
  queryKey: ["posts"],
  queryFn: fetchPosts,
  select: (posts) => posts.map(p => p.title),
  // select receives the full cached data (Post[])
  // and returns only what this component needs (string[])
});

Why use select?

  • The component only receives the transformed data — not the full response
  • The component only re-renders when the transformed result changes. If a post's body changes but titles stay the same — no re-render. (How? TanStack Query uses "structural sharing" — it compares the previous and new select result deeply, and if the data is identical, it keeps the old reference. So even though .map() creates a new array, TQ detects that the content didn't change and skips the re-render.)
  • The full data is still cached — other components can select different parts from the same cache
