Two Ways to Write Components

React has two ways to define components: functions and classes. Both produce the same result, but functional components are the modern standard.

Functional Components (What We Use)

A functional component is just a function that returns JSX. State and side effects are managed with hooks:

import { useState } from "react";

const Counter = () => {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
};

export default Counter;

Class Components (Legacy)

Class components were the only way to have state before React 16.8. You'll encounter them in older codebases:

import { Component } from "react";

type CounterState = { count: number };

class Counter extends Component<{}, CounterState> {
  state: CounterState = { count: 0 };

  handleClick = () => {
    this.setState((prev) => ({ count: prev.count + 1 }));
  };

  render() {
    return (
      <div>
        <p>Count: {this.state.count}</p>
        <button onClick={this.handleClick}>Increment</button>
      </div>
    );
  }
}

export default Counter;

Why Functional Components Win

Same result, but functional components are better in every way:

  • Less code — no constructor, no this, no render() method
  • Easier to read — just a function that returns JSX
  • Hooks — useState, useEffect, useContext, custom hooks (impossible in classes)
  • Better TypeScript — simpler type annotations, no generic class syntax
  • Better testing — plain functions are easier to test
  • Better performance — slightly less overhead (no class instance creation)

Why Class Components Still Exist

You won't write class components, but you should know why they're still around:

  • Legacy codebases — projects started before 2019 (pre-hooks era)
  • Error Boundaries — as of React 19, this is the only remaining use case that requires a class component
  • Older libraries — some libraries may use them internally

The Rule

Always write functional components. For this course and for modern React development, there is no reason to write class components. If you encounter them in existing code, you'll know what they are — but don't write new ones.
