Types of Components

Components can be conditionally divided into 2 categories: Dumb components and Smart components.

Dumb Components

Dumb components are also called "presentational" components because their only responsibility is to present something in the DOM. Once that is done, the component is finished. There is no need to monitor it, no need to check on it from time to time to see how things are going. Place the information on the page and move on:

// SimpleComponent.tsx
import React from 'react';

const SimpleComponent = () => {
  return <div>Hello, React!</div>;
};

export default SimpleComponent;

Smart Components

Smart components (or container components), on the other hand, carry a different responsibility. Since they bear the burden of being smart, they track state and care about how the application works.

With the React 16.8 update, the concept of hooks was introduced, which allows using state and functional capabilities in functional components, making them more powerful and convenient. Here is an example of using functional components with hooks in React:

// SmartComponent.tsx
import React, { useState } from 'react';

const SmartComponent = () => {
  const [count, setCount] = useState(0); // Using the useState hook for state

  const handleClick = () => {
    setCount(count + 1); // Updating state using setCount
  }

  return (
    <div>
      <div>Count: {count}</div>
      <button onClick={handleClick}>Increment</button>
    </div>
  );
};

export default SmartComponent;

In this example, we used the useState hook, which allows using state in a functional component. We use array destructuring to get the current state value count and the setCount function to update the state.

Also, we used a functional approach to defining the component, where we return JSX (HTML + CSS markup in which you can use JavaScript expressions in curly { } braces) directly from the function, making this component functional.

This approach using functional components and hooks allows creating simpler and more understandable components that can manage state and interact with other components, without using classes and lifecycle methods.
