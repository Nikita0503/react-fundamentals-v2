Two Common Roles for Components

Components in React tend to fall into two categories based on their responsibility. These aren't strict rules — they're patterns that help you think about component design.

UI Components (Presentational)

UI components focus on how things look. They:

  • Receive all data via props
  • Usually have no state (or only UI state like "is dropdown open")
  • Are highly reusable across the application
  • Examples: Button, Card, Avatar, Badge, Input
type ButtonProps = {
  label: string;
  onClick: () => void;
  variant?: "primary" | "secondary";
};

const Button = ({ label, onClick, variant = "primary" }: ButtonProps) => {
  return (
    <button className={`btn btn-${variant}`} onClick={onClick}>
      {label}
    </button>
  );
};

export { Button };

Components with Logic (Container/Feature)

These components manage state, fetch data, and handle business logic. They:

  • Manage state and side effects
  • Compose UI components together
  • Connect to external systems (APIs, stores, context)
  • Examples: UserProfile, ProductList, CheckoutForm
import { useState, useEffect } from "react";
import { Card } from "./Card";

type User = { id: number; name: string; email: string };

const UserProfile = () => {
  const [user, setUser] = useState<User | null>(null);

  useEffect(() => {
    fetch("/api/user/1")
      .then((res) => res.json())
      .then((data) => setUser(data));
  }, []);

  if (!user) return <p>Loading...</p>;

  return (
    <Card>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </Card>
  );
};

export { UserProfile };

Composition

Composition means building complex UI from simple pieces. React encourages composing small, focused components — each one does one thing well:

const DashboardPage = () => {
  return (
    <div className="layout">
      <Header />
      <Sidebar />
      <main>
        <UserProfile />
        <RecentActivity />
      </main>
      <Footer />
    </div>
  );
};

A page is just a component that composes other components. Header, Sidebar, Footer — each is independent and can be developed, tested, and reused separately.

Reusability

Reusability means the same component can be used in many places with different data:

  • A single Button component used everywhere with different labels and actions
  • A Card component that wraps any content
  • A UserAvatar component that shows different users' photos

This is the power of the component model — write once, use many times. Instead of duplicating markup, you create a component and pass different props each time you use it.

The Line is Not Strict

The distinction between UI and logic components isn't rigid. A component can start as pure UI and gain logic over time. A feature component might be simple enough to look presentational. The goal is clarity, not rigid categories — organize your code so it's easy to understand and maintain.
