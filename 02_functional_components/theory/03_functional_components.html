Чому функціональні компоненти?

У сучасній розробці майже усі проекти припинили застосування класових компонентів, тому в поточному курсі ми їх розглядати не будемо.

Функціональні компоненти стали дедалі популярнішими у React-спільноті з оновленнями в React 16.8, коли була введена можливість використання хуків (hooks) у функціональних компонентах.

Це дозволило розробникам використовувати функціональні компоненти замість класових компонентів, особливо в простих випадках, де класові компоненти були зайвими.

Реалізація того ж SmartComponent але у класовому компоненті:

import React, { Component } from 'react';

class SmartComponent extends Components {
  constructor(props) {
    super(props);
    this.state = {
      count: 0
    };
  }

  handleClick = () => {
    this.setState(prevState => ({
      count: prevState.count + 1
    }));
  }

  render(){
    const { count } = this.state;

    return(
      <div>
        <div>Count: {count}</div>
        <button onClick={this.handleClick}>Increment</button>
      </div>
    )
  }
}

export default SmartComponent;

Основні переваги використання функціональних компонентів у порівнянні з класовими компонентами:

  • Спрощений синтаксис: Функціональні компоненти мають простий синтаксис, що робить їх легшими для розуміння, тестування та розробки.
  • Немає внутрішнього стану: Функціональні компоненти не мають внутрішнього стану, що полегшує керування станом в додатках та сприяє принципам безпечного використання незмінних даних.
  • Використання хуків: Хуки (hooks) дозволяють використовувати функціональні можливості, такі як стан, контекст, побічні ефекти, без необхідності використовувати класові компоненти. Це робить код більш зрозумілим та компактним.
  • Покращена продуктивність: Функціональні компоненти мають нижчий вплив на продуктивність, оскільки вони мають менше додаткових операцій порівняно з класовими компонентами.
  • Легше тестування: Функціональні компоненти можуть бути протестовані легше, оскільки вони мають менше внутрішнього стану та мають простий вхідний API.
