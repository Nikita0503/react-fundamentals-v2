Why Functional Components?

In modern development, almost all projects have stopped using class components, so in this course we will not cover them.

Functional components became increasingly popular in the React community with updates in React 16.8, when the ability to use hooks in functional components was introduced.

This allowed developers to use functional components instead of class components, especially in simple cases where class components were unnecessary.

Implementation of the same SmartComponent but as a class component:

// SmartComponent.tsx (class component - legacy approach)
import React, { Component } from 'react';

interface SmartComponentState {
  count: number;
}

class SmartComponent extends Component<{}, SmartComponentState> {
  constructor(props: {}) {
    super(props);
    this.state = {
      count: 0
    };
  }

  handleClick = () => {
    this.setState(prevState => ({
      count: prevState.count + 1
    }));
  }

  render(){
    const { count } = this.state;

    return(
      <div>
        <div>Count: {count}</div>
        <button onClick={this.handleClick}>Increment</button>
      </div>
    )
  }
}

export default SmartComponent;

The main advantages of using functional components compared to class components:

  • Simplified syntax: Functional components have simple syntax, making them easier to understand, test, and develop.
  • No internal state: Functional components do not have internal state, which makes state management in applications easier and promotes the principles of safe use of immutable data.
  • Use of hooks: Hooks allow using functional capabilities such as state, context, and side effects without the need to use class components. This makes the code more understandable and compact.
  • Improved performance: Functional components have a lower impact on performance, as they have fewer additional operations compared to class components.
  • Easier testing: Functional components can be tested more easily, as they have less internal state and have a simple input API.
