What is a Component?

A component is a function that returns JSX. That's it. Every piece of UI in a React application is a component — a button, a form, a page, even the entire app itself.

Anatomy of a Component File

Every component file follows the same structure:

  1. Imports — React, other components, types, styles
  2. Type definition — for props (if any)
  3. The component function — receives props, contains logic
  4. Return statement — JSX that describes the UI
  5. Export — makes the component available to other files

Minimal Component

The simplest possible component — no props, no state, just JSX:

// Greeting.tsx
const Greeting = () => {
  return <h1>Hello, World!</h1>;
};

export default Greeting;

Component with Props

Props are covered in detail in Module 05, but here's a brief preview — a component that accepts data from the outside:

// Greeting.tsx
type GreetingProps = {
  name: string;
  age?: number; // optional prop
};

const Greeting = ({ name, age }: GreetingProps) => {
  return (
    <div>
      <h1>Hello, {name}!</h1>
      {age && <p>You are {age} years old.</p>}
    </div>
  );
};

export default Greeting;

Naming Conventions

  • Component names: always PascalCase — Button, UserCard, NavigationMenu
  • File names: match the component name — Button.tsx, UserCard.tsx
  • One component per file: each file exports one main component

File Structure in a Project

A typical React project organizes components like this:

src/
├── components/          // Shared/reusable components
│   ├── Button.tsx
│   ├── Card.tsx
│   └── Header.tsx
├── pages/               // Page-level components
│   ├── HomePage.tsx
│   └── ProfilePage.tsx
└── App.tsx              // Root component

Import and Use

Once a component is exported, you import it and use it like an HTML tag:

// App.tsx
import Greeting from "./components/Greeting";

const App = () => {
  return (
    <div>
      <Greeting name="Alice" />
      <Greeting name="Bob" age={30} />
    </div>
  );
};

export default App;

Named Exports vs Default Exports

Both are valid in React. You'll see both in real projects:

// Default export — one per file
const Button = () => { ... };
export default Button;

// Import:
import Button from "./Button";

// Named export — can have multiple per file
const Button = () => { ... };
export { Button };

// Import:
import { Button } from "./Button";

Named exports are preferred in larger projects — they're easier to refactor (rename detection works better), provide better autocomplete in editors, and prevent accidental name mismatches on import.
